# Arcanum — API Reference

This document is the source of truth for Arcanum's native HTTP API, OpenAI-compatible API, wire formats, authentication behavior, request and response contracts, status mapping, and public error codes. It covers both general `/api` calls and the OpenAI-compatible `/v1` surface.

Architecture and design decisions belong in [`Arcanum.DESIGN.md`](Arcanum.DESIGN.md). The readable architecture guide is [`Arcanum.Design.Human.md`](Arcanum.Design.Human.md). The complete public configuration model belongs in [`Compendium.README.md`](Compendium.README.md#complete-configuration-reference). Complete CLI syntax and option behavior belong in [`Arcanum.Command.Reference.md`](Arcanum.Command.Reference.md).

The established §8 contract numbers are retained in this extracted reference so existing issue, test, and documentation citations remain stable.

## 1. Complete API surface

**API surface (`MapArcanumEndpoints`):**

| Method | Path | Contract/purpose |
|--------|------|-----------------|
| GET | `/metrics` | Prometheus text-format metrics. |
| GET | `/api/presence` | Anonymous, bodyless local-server challenge accepted only when both the raw TCP peer and the post-forwarding effective peer are loopback. The client supplies one 32-byte random nonce in `X-Arcanum-Presence-Nonce`; a ready host returns **204** with protocol version, canonical loopback authority, a nonce/authority-bound HMAC proof, and an encrypted short-lived process capability. The authority is derived from the server-side listener's actual TLS state and local port with the client-facing host fixed to `localhost`; caller-controlled `Host`, request scheme, and forwarded metadata cannot select it. It exposes no health, configuration, reusable credential, or installation data, accepts no API key, and returns **400** for malformed challenges, **404** for a non-loopback peer, or **503** until both the process-held proof key and a trustworthy listener identity are available. |
| GET | `/api/health` | Authenticated `ApiResponse<HealthReportDto>` readiness snapshot. Healthy/Degraded reports return **200**; a valid Unhealthy report remains a success envelope with its component detail and returns **503**. Components include **`Conclave`**, whose detail leads with `state=disabled\|configured\|degraded\|healthy` (DESIGN §5.7.1); only `degraded` affects readiness. |
| GET | `/api/meta` | Instance metadata and feature flags for sidecar discovery (`ApiResponse<InstanceMetadataDto>`). Carries `conclaveEnabled`, `a2AServerEnabled`, `a2AClientEnabled`, `conclaveA2AState`, `a2AServerPath`, `a2AAgentCardPath`, and `a2AAllowedRemoteAgentCount`. Every flag is read from the resolved configuration: `archiveSearchEnabled` follows `Arcanum:Features:ArchiveSearch`, and `contextCompressionEnabled` / `tokenTrackingEnabled` report the runtime-resolved values (code-owned today, so they are `true`, but read rather than hard-coded). The old `loreSystemEnabled` flag, a constant `false` for a system that no longer exists, was removed from the wire. |
| POST | `/api/server/quit` | Accept an authenticated operator shutdown request (`202` + `ApiResponse<bool>`), then stop the host after the acknowledgement completes. |
| GET | `/api/budget` | Daily budget snapshot (`ApiResponse<BudgetSummaryDto>`: enabled, daily limit, today's spend, remaining, spent percent, alert threshold; DESIGN §22.2). Spend is split into `localSpendUsd` (this instance's own inference — committed billable operations for the UTC day plus outstanding reservations, the same authority the budget gate enforces on) and `externalSpendUsd` (delegated A2A work, as reported by peers), with `todaySpendUsd` their sum. `unpricedDelegatedSendings` counts Sendings that settled today whose peer reported **no** cost — counted, never costed, so a non-zero value means the spend figures are a floor rather than the whole bill. CLI `arcanum budget`. |
| GET | `/api/grimoire/stats` | Grimoire database statistics (`ApiResponse<GrimoireStatsDto>`; database + WAL byte sizes and per-table row counts via `GrimoireStatsService`). |
| GET | `/api/data/status` | Unified retained-data inventory (`ApiResponse<DataRetentionStatus>`): typed rows/files/estimated bytes, effective policy, physical store, safe provenance, aggregate totals, and categories preserved outside the selected root (§8.20). |
| GET | `/api/data/retention` | Read the effective `Arcanum:Retention` policy (`ApiResponse<RetentionSettings>`; §8.20). |
| PUT | `/api/data/retention` | Update one typed rule (`RetentionRuleUpdateRequest` → `ApiResponse<RetentionSettings>`); values are normalized and clamped by the server (§8.20). |
| POST | `/api/data/prune/plan` | Build the complete non-mutating selected plan (`DataRetentionRequest` → `ApiResponse<DataRetentionPlan>`), represented through internal checkpoint pages rather than a total candidate ceiling (§8.20). |
| POST | `/api/data/prune` | Re-plan and apply through a durable operation (`DataRetentionApplyRequest` → `ApiResponse<DataRetentionApplyResult>`; optional stale-plan guard; §8.20). A candidate that carries a live Covenant label is skipped at apply and left where it is, so a sweep still removes every other candidate; the plan is built before that check, so a dry run may name a candidate the apply then leaves. |
| DELETE | `/api/data/sessions/{id}` | Explicit dependency-aware session deletion (`ApiResponse<DataRetentionApplyResult>`; pins, holds, active work, and a Covenant-labelled assistant Entry all block; §8.20). A labelled Entry refuses the whole deletion with **403** `Covenant.ForbiddenAuthority`, because a Session delete is all or nothing and a Session removed around Entries that are still there is worse than one that stayed. A sensitivity label that cannot be read refuses it with **503** `Covenant.Unavailable` instead, since nothing was found to be protected and the protection could not be checked. The check is made inside the transaction that deletes, so a refusal leaves everything in place. |
| DELETE | `/api/data/attachments/{id}` | Explicit attachment-version deletion including owned bytes and derived indexes (`ApiResponse<DataRetentionApplyResult>`; §8.20). |
| POST | `/api/data/memory/reset/plan` | Build the non-mutating plan for exactly one `MemoryResetScope` from `MemoryResetRequest` (`ApiResponse<DataRetentionPlan>`). Optional `campaignId` previews only that Campaign's rows of a `Saga` or `Lexicon` reset. Covenant returns five content-free aggregates under a protected planning lease (§8.20). |
| POST | `/api/data/memory/reset` | Reset exactly one `MemoryResetScope` from `MemoryResetRequest` (`ApiResponse<DataRetentionApplyResult>`). Optional `campaignId` clears only that Campaign's `Saga` or `Lexicon` memories and leaves every other Campaign's and every installation-scoped one in place; naming it for any other scope is refused **400** `Data.InvalidRequest`. Covenant enters the durable protected-erasure coordinator directly under its V4 launch checkpoint and is never the nested arm of a broader workflow (§8.20). The untargeted `Saga` and `Lexicon` arms refuse with **403** `Covenant.ForbiddenAuthority` while the kind still holds any labelled member, because the statement behind them examines no identity and cannot leave one row out, and with **503** `Covenant.Unavailable` when the labels cannot be read. A Campaign-targeted `Saga` or `Lexicon` reset refuses the same way when any memory its Campaign predicate selects carries a live label: the question is asked inside the delete's transaction about exactly those memories, not about the label's recorded Campaign, and a refusal removes nothing. A reset of any scope but `Covenant` whose preview selected nothing applies as a successful, reconciled no-op with zero counts, and the bundled CLI exits `0`; rows that appear after that empty preview are refused as **409** `Data.PlanChanged`, and a fresh preview is needed. |
| POST | `/api/data/factory-reset` | Reset managed data beneath the selected root from `FactoryResetRequest`; requires exact `confirmation: "factory-reset"`, composes healthy-catalog Covenant erasure with ordinary factory cleanup under its V2 launch checkpoint, and preserves backups/configuration/security material/out-of-root data (`ApiResponse<DataRetentionApplyResult>`; §8.20). An offline installation reset launches this same erasure as its nested arm under a parent-receipt binding; a direct call to this route is standalone work and binds nothing. |
| POST | `/api/data/factory-reset/plan` | Loopback-only data-phase planning for an installation reset. Accepts `Global` with no workspace binding or `Workspace` with an exact registered Campaign binding (`ApiResponse<DataRetentionPlan>`; §8.20). |
| GET | `/api/config` | Read the latest successfully persisted `ArcanumSettings`; provider endpoints remain redacted, while secret environment-variable references are returned without resolving their values (`ApiResponse<ArcanumSettings>`; §8.12). |
| PUT | `/api/config` | Validate and write a full settings snapshot to `arcanum.json` (`ApiResponse<bool>`; §8.12). |
| POST | `/api/config/validate` | Validate settings without writing (`ApiResponse<bool>`; §8.12). |
| GET | `/api/models` | Flatten models from the latest successfully persisted provider snapshot (`ApiResponse<ModelInfoDto[]>`; endpoint redacted as `"***"`; effective `supportsTools` is false only for an explicit `providers.models.supportsTools: false`; models on a Familiar provider's `hiddenModels` list are omitted; read-only, no connectivity checks; §8.12). |
| GET | `/api/providers` | List the latest successfully persisted providers with `apiKey`/`endpoint` redacted (`ApiResponse<ProviderInfoDto[]>`; `models` excludes the hide list and `hiddenModels` reports it; a Familiar reports an empty `endpoint` and `credentialEnvironmentVariable`; read-only; §8.12). |
| GET | `/api/providers/{name}/familiar-probe` | Familiar readiness for one `ClaudeCodeCli`/`CodexCli` provider (`ApiResponse<FamiliarProbeResult>`; asks the CLI for its own status, never for a completion, so it is non-billable; never reads the CLI's credential store and carries no account material; **404** `Provider.NotFound`, **400** `Validation.InvalidProviderType` for an OpenAI-compatible row; §8.12.1). |
| GET | `/api/perception/look` | Eye of the World snapshot (optional `directory` query; requires `Arcanum:Security:PerceptionWorkspaceRoots`; **403** when unset). |
| POST | `/api/perception/chronosync` | Analyze a `PatternSnapshot` body and persist the workspace-context baseline it implies (`ApiResponse<ChronosyncReport>` through `IChronosyncEngine.AnalyzeAndSyncAsync`). The body is validated before any analysis and a refusal carries the mapper's status for its code. Honors `Idempotency-Key` through the bound-argument filter (§11.17), so a second post under the same key with a different snapshot is **409** `Security.IdempotencyConflict`. |
| POST | `/api/intelligence/ping` | Buffered inference. |
| POST | `/api/intelligence/ping-stream` | NDJSON streaming inference (same `PingRequest` extensions as buffered ping). |
| POST | `/api/intelligence/human-response` | Submit human-in-the-loop answer. |
| POST | `/api/intelligence/arsenal` | Spell names, metadata-only `SpellSummary[]`, native tools, and MCP server status. |
| POST | `/api/intelligence/mana` | Read-only diagnostic Mana (token) counter (`ApiResponse<ManaCountResult>`; body `ManaCountRequest` { `messages`, `prompt`, `model`, `tools` }). |
| POST | `/api/intelligence/context/inspect` | Read-only effective-turn preview (`ContextPreviewRequest` → `ApiResponse<ContextPreviewResult>`); accepts optional forced-Spell, preview-only text/image context, tool/system-prompt shaping, and inference-option fields while reusing production assembly components without main inference, tool invocation, attachment persistence, or assistant-entry persistence. |
| POST | `/api/web/search` | First-class bounded web search (`WebSearchWorkflowRequest` → `ApiResponse<WebSearchWorkflowResult>`; citations and provider usage; DESIGN §11.27). Optional `attachToSessionId` stores the result Markdown; the provider call is already billed by then, so a failed attachment answers **200** with `attachmentId: null` and a non-null `attachmentError` rather than discarding the answer. |
| POST | `/api/web/browse` | First-class bounded static page read (`WebBrowseWorkflowRequest` → `ApiResponse<WebBrowseWorkflowResult>`; JavaScript mode degrades explicitly when no renderer is configured; DESIGN §11.27). `attachToSessionId` behaves as on `/api/web/search`: a failed attachment reports `attachmentError` and still returns the page. |
| POST | `/api/web/research` | Server-owned progress-driven research as NDJSON `WebResearchStreamFrame` lines (policy/progress/terminal-reason/result/error); the request can carry effective Campaign/Workspace/Session/Model context, current-turn text/image context, and synthesis sampling controls (DESIGN §11.27). |
| GET | `/api/mcp` | List managed MCP servers (`ApiResponse<McpServerInfo[]>`; DESIGN §5.6). |
| GET | `/api/mcp/{name}` | One managed MCP server (`ApiResponse<McpServerInfo>`); optional `workingDirectory` query for disambiguation. |
| POST | `/api/mcp/{name}/start` | Start one MCP server (`ApiResponse<bool>`); optional `workingDirectory` query. |
| POST | `/api/mcp/{name}/stop` | Stop one MCP server (`ApiResponse<bool>`); optional `workingDirectory` query. |
| POST | `/api/mcp/{name}/restart` | Restart one MCP server (`ApiResponse<bool>`); optional `workingDirectory` query. |
| POST | `/api/mcp/trust-workspace` | Approve a workspace-local `mcp.json` for auto-start (`ApiResponse<bool>`; body `{ "workingDirectory": "..." }`; DESIGN §5.6). |
| POST | `/api/mcp/reload` | Reload MCP connections (global nuclear reload — DESIGN §5.6). |
| POST | `/api/mcp/tools/invoke` | **Diagnostic MCP Invocation** — policy-constrained direct invoke of an **external** MCP tool by an operator (`ApiResponse<McpToolInvokeResponse>`). Development edition only; otherwise **404** `Mcp.DiagnosticDisabled`. |
| GET | `/api/sessions` | Search/list Grimoire sessions (`ApiResponse<SessionQueryResult>`; DESIGN §11.16). |
| POST | `/api/sessions` | Create session (`ApiResponse<SessionDetailDto>`; **201**; a `campaignId` no Campaign has is **404** `Campaign.NotFound`, because the Session's Campaign binding is immutable and the table carries no foreign key). |
| GET | `/api/sessions/analytics` | Session analytics (`ApiResponse<SessionAnalytics>`; DESIGN §11.16). |
| GET | `/api/sessions/{id}` | Session metadata (`ApiResponse<SessionDetailDto>`; **404** when missing). |
| GET | `/api/sessions/{id}/entries` | Entry history (`ApiResponse<EntryDto[]>`; optional `offset`, `limit`, and keyset cursor parameters `beforeCreatedAt` / `beforeId`, which must be supplied together or not at all: either one alone is **400** `Validation.InvalidQuery` rather than being ignored). `?countOnly=true` returns `ApiResponse<SessionEntryCountDto>` instead of entry rows. |
| POST | `/api/sessions/{id}/entries` | Append entry manually (**404** / **400**; publishes live SSE). |
| PATCH | `/api/sessions/{id}` | Update title or status (**404** `Session.NotFound`; **400** `Session.InvalidStatus`). Only the fields the body supplies are written, in one statement: a title-only patch never rewrites the status, so it cannot overwrite a status another request changed after this one read the Session. A supplied blank title clears it. |
| DELETE | `/api/sessions/{id}` | Archive session (**204**; soft delete). |
| GET | `/api/sessions/{id}/export` | Export JSON or Markdown (`ApiResponse<SessionExportResult>`). Required `format` is `json` or `markdown`, matched without regard to case; anything else is **400** `Session.InvalidFormat`. A Session whose ledger tables cannot be read (one is missing) is **503** `Covenant.ManualRecoveryRequired` rather than exportable. A Session carrying any Covenant-derived artifact is refused with **403** `Covenant.PlaintextExportRefused` **before** the transcript is read, whether `Arcanum:Features:Covenant` is on or has since been turned off (with it off the same two content-free ledger reads run without a lease) ([DESIGN §10.19.11](Arcanum.DESIGN.md#101911-refusing-tainted-plaintext-export-and-reporting-what-a-campaign-export-left-behind)). |
| POST | `/api/sessions/{id}/rest` | Enqueue Campaign Log consolidation (**202** + `ApiResponse<bool>` when accepted; **503** + `Session.RestQueueFull` when the bounded queue rejects). |
| GET | `/api/sessions/{id}/stream` | SSE replay + live entry stream; optional `since=<entry-guid>` resumes after an Entry in that Session. A missing or foreign cursor returns **404** `Session.EntryNotFound` before SSE headers are written. |
| GET | `/api/sessions/{id}/attachments` | Revalidate tracked sources asynchronously, then list **bound** session attachments (`ApiResponse<SessionAttachmentDto[]>`; includes `indexingStatus`, the snapshot `RelativePath` for Reveal, and sanitized source provenance/refreshability; never an absolute source path; DESIGN §10.2.5). |
| POST | `/api/sessions/{id}/attachments` | Create a snapshot-only bound attachment from multipart field `file` (optional `logicalName` form field); returns `201` + `ApiResponse<SessionAttachmentDto>`. The filename and declared MIME are hints; the server validates name, detected content, kind-specific byte limit, MIME/Scrying policy, strict encoding for text, and Session byte/version budgets. Crossing a budget is **409** `Attachment.LimitExceeded`, reported only for the store's typed limit refusal; any other persistence failure is a server fault (**500**), never a limit. Unsupported binary/PDF/Office content remains a valid `Binary` attachment with `NotEligible` indexing status. |
| POST | `/api/sessions/{id}/attachments/reference` | Create a refreshable live reference from `CreateSessionAttachmentReferenceRequest` (`workspacePath`, optional `workspaceId`, optional `logicalName`); the server alone resolves/authorizes/reads the source and persists the already-verified bytes (a resolution whose bytes disagree with its own recorded hash or provenance is a server fault, **500**, not a limit); a Session byte/version budget is **409** `Attachment.LimitExceeded`; returns `201` + `ApiResponse<SessionAttachmentDto>`. |
| GET | `/api/sessions/{id}/attachments/{attachmentId}/content` | Stream the authenticated plaintext of that stored bound snapshot with `Content-Disposition: attachment`, `Cache-Control: no-store`, and `X-Content-Type-Options: nosniff`. Never returns or redirects to a live source path. |
| POST | `/api/sessions/{id}/attachments/{attachmentId}/refresh` | Operator-triggered secure refresh through the same source-validation/persistence core as `refresh_session_file`; returns `ApiResponse<AttachmentRefreshEvent>` only after the backend has reused or persisted the confirmed current version. |
| GET | `/api/sessions/{id}/context-pins` | List durable, structured session context pins. |
| POST | `/api/sessions/{id}/context-pins` | Create or update a context pin by `(session, kind, stable target)`; accepts file, directory snapshot, symbol/range, session entry, attachment, URL, and diagnostic kinds. |
| DELETE | `/api/sessions/{id}/context-pins/{pinId}` | Remove a durable context pin without changing `Entries.IsPinned` (**204**; **404** `Session.PinNotFound` in the standard envelope when the Session holds no such pin). |
| POST | `/api/sessions/{id}/fork` | Create an independent branch of a session, optionally truncated at `upToEntryId` (**201**; DESIGN §11.16.1). |
| POST | `/api/embeddings/reset` | Truncate embedding tables for RAG dimension-change recovery (requires `?confirm=true`; optional `?scope=all\|entry\|workspaceFile\|saga\|sessionAttachment\|tapestry`, default `all`; snake-case aliases accepted). `tapestry` drops exactly the three `tapestry_*` tables — the leaf corpora stay indexed and the background sweep rebuilds every tree (DESIGN §21.11). A protected artifact the reset could not erase stops it with **503** `Covenant.ManualArtifactErasureRequired` before any table is truncated. A refusal from the purge walk keeps its own code and the status the central mapper gives it (for example **409** `Covenant.StaleSnapshot` when a label or the operator authority changed while it was being purged), and a sensitivity label that cannot be read, or whose row cannot be parsed, stops it with **503** `Covenant.Unavailable`, which is the Grimoire's to repair and not an artifact to erase by hand. The truncation asks the label guard once more, for each labelled kind it clears (Entry embeddings and Saga memories), inside its own transaction and before any table is touched: a labelled member that appeared since the walk answers **403** `Covenant.ForbiddenAuthority`, and a label table that cannot be read there answers **503** `Covenant.Unavailable`, and either removes nothing. |
| DELETE | `/api/sessions/{id}/entries/{entryId}` | Delete a single entry and its `entry_embeddings` / optional vector row in the same transaction (**204**). A Covenant-labelled assistant Entry is removed through the sensitivity purge first (DESIGN §10.20.2): **409** `Covenant.StaleSnapshot` when its label or the operator authority changed while it was being purged, **503** `Covenant.Unavailable` when its sensitivity label cannot be read, **403** `Covenant.ForbiddenAuthority` when its label is found and the request holds no sensitivity-purge authority, and **503** `Covenant.ManualArtifactErasureRequired` when the kernel could not erase it and left it unchanged. The delete then asks the label guard again inside its own transaction: a label written since the purge answers **403** `Covenant.ForbiddenAuthority`, and a label table that cannot be read answers **503** `Covenant.Unavailable`; either leaves the Entry in place. |
| POST | `/api/sessions/{id}/entries/{entryId}/pin` | Pin an entry so it is always included in inference context, even when compression would otherwise drop it. |
| DELETE | `/api/sessions/{id}/entries/{entryId}/pin` | Unpin a previously pinned entry. |
| POST | `/api/sessions/{id}/compact` | Manually compress session context by deleting the oldest non-pinned entries until the token count is below the effective threshold (`ApiResponse<CompactResult>`: `tokensBefore`, `tokensAfter`, `entriesRemoved`, and `stoppedBy`). A refused erasure of a Covenant-labelled entry stops the compaction outright and removes none of the unlabelled remainder, and the answer is still **200**: `entriesRemoved` counts every entry already gone, including ones erased before the stop, each confirmed against the stored entry rather than the loaded window (a lower bound only when the session itself cannot be read again after the stop), `tokensAfter` is measured after them, and `stoppedBy` carries the typed code of the refusal — `Covenant.StaleSnapshot` when a label or the operator authority changed while it was being purged, `Covenant.ManualArtifactErasureRequired` when the kernel could not erase an entry and left it unchanged, or the purge's own refusal: `Covenant.ForbiddenAuthority` when a label is found and the request holds no sensitivity-purge authority, `Covenant.InvalidScope` when the labelled entries of one page belong to more than one owner scope, or `Covenant.Unavailable` when a sensitivity label cannot be read. `stoppedBy` is `null` when the compaction ran to completion. An ordinary entry delete inside the compaction asks the labelled-artifact guard again inside its own transaction, so a label written after the purge's dispatch refuses that delete outright instead of being counted as a stop: the route then answers the guard's own error with the status its code maps to — **403** `Covenant.ForbiddenAuthority` for a labelled entry, **503** `Covenant.Unavailable` when the label table cannot be read — in the `ApiResponse<string>` envelope, never a **500** `Hub.Unhandled`. Entries already deleted before the refusal stay deleted, and compacting again continues from there (DESIGN §10.20.2). |
| POST | `/api/sessions/divine` | Session Divination — semantic search over Grimoire entries embedded by `EntryWeavingService` (`ApiResponse<SemanticSearchResult>`; body `SemanticSearchRequest` with required `query` and optional `campaignId`, `status` (`active` or `archived`; default `active`), and `limit` (clamped 1–50)). The `campaignId` and `status` filters are applied to the Session each hit belongs to, and the search widens its candidate window (4× `limit`, doubling, at most 500 ranked entries) until `limit` hits survive them or the ranking is exhausted, so a Campaign whose closest matches rank below other Campaigns' entries is still answered; the installation's embeddings similarity threshold is applied to every candidate and is never relaxed by the widening. `hasMore` is true when more matching hits exist than `limit` returned, or when the 500-entry window filled before the search could rule that out; it is never false while another matching hit could exist. There is no cursor, so `nextCursor` is always null. |
| GET | `/api/lore` | List lore entries (`ApiResponse<ListPageResult<LoreDto>>`; paginated with optional `?limit=` and `?offset=`; the default page size is code-owned). |
| GET | `/api/lore/{key}` | Get lore by key. |
| POST | `/api/lore` | Upsert lore entry. |
| DELETE | `/api/lore/{key}` | Delete lore entry. |
| GET | `/api/saga` | Paginated listing of Saga memories (`ApiResponse<SagaMemoryDto[]>`; optional `?q=` substring, `?sessionId=`, `?limit=` clamped to 1–10,000, and non-negative `?offset=`). With `?sessionId=` the listing is narrowed by the same ownership a turn in that session's scope ranks by; without it an operator sees the whole store. Ownership is what the two surfaces share, not eligibility: this reads the memory rows themselves, so a retired memory is listed exactly as a live one is even though no turn can recall it. Every row reports its own `scopeKind` and `scopeCampaignId` either way, and its `retiredAtUtc` and `pinnedAtUtc` (DESIGN §21.9). Newest first, and memories that share an instant are ordered by identity, descending, so the order among them is the same on every request while the store is unchanged. |
| POST | `/api/saga/divine` | Semantic search over Saga memories (`ApiResponse<SagaSearchResult>`; body `SagaSearchRequest` with required `query`, optional `limit`, and optional `sessionId`; **503** when the embedding provider is unavailable). `sessionId` searches *as* that session: the scope comes from that session's immutable Campaign binding, never from anything else in the request. With Campaign scoping enabled and no `sessionId`, the search sees installation-scoped memories only (DESIGN §21.9). |
| DELETE | `/api/saga/{id}` | Delete a single Saga memory (**204**; **404** `Saga.NotFound`; DESIGN §21.9). A Covenant-labelled memory is removed through the sensitivity purge (DESIGN §10.20.2): **409** `Covenant.StaleSnapshot` when its label or the operator authority changed while it was being purged, **503** `Covenant.Unavailable` when its sensitivity label cannot be read, **403** `Covenant.ForbiddenAuthority` when its label is found and the request holds no sensitivity-purge authority, and **503** `Covenant.ManualArtifactErasureRequired` when the kernel could not erase it and left it unchanged. Every one of those refusals leaves the memory unchanged. The delete asks the label guard again inside its own transaction once the purge is done, so a label written in between answers **403** `Covenant.ForbiddenAuthority`, and a label table that cannot be read answers **503** `Covenant.Unavailable` there as well. An unsuppressed delete, not erasure: no fingerprint is recorded, so extraction or an agent can write the same content again; see `/api/memory/{store}/erase` (§8.35). |
| DELETE | `/api/saga` | Delete every Saga memory, embedding, and extraction watermark (**204**; requires `?confirm=true`, else **400** `Saga.NotEmpty`; DESIGN §21.9). Covenant-labelled memories are removed through the sensitivity purge first (DESIGN §10.20.2): **409** `Covenant.StaleSnapshot` when a labelled memory's label or the operator authority changed while it was being purged, **503** `Covenant.Unavailable` when a sensitivity label cannot be read, **403** `Covenant.ForbiddenAuthority` when a label is found and the request holds no sensitivity-purge authority, **400** `Covenant.InvalidScope` when the labelled memories of one page belong to more than one owner scope, and **503** `Covenant.ManualArtifactErasureRequired` when the kernel could not erase a memory and left it unchanged. Each of those refusals stops the deletion before the store is emptied; labelled memories already purged stay purged, and every other memory is left in place. The emptying statement asks the label guard once more inside its own transaction: a labelled member that appeared since the purge answers **403** `Covenant.ForbiddenAuthority`, and a label table that cannot be read answers **503** `Covenant.Unavailable`, and either removes nothing. The evidence retirement leaves behind survives this, deliberately: a suppression digest names no memory and outlives the one it describes, so emptying the store does not re-enable extraction the operator rejected. An unsuppressed delete, not erasure: no fingerprint is recorded, so extraction or an agent can write the same content again; see `/api/memory/{store}/erase` (§8.35). `POST /api/data/memory/reset` with the `saga` scope is what clears them: a whole-store reset takes the digests and the key together, and one naming a Campaign takes that Campaign's digests and leaves the key every other scope's digests are still bound by (§8.20, DESIGN §21.13). |
| GET | `/api/saga/stats` | Aggregate Saga memory summary (`ApiResponse<SagaStats>`: total count, session count, oldest/newest `CreatedAt`; DESIGN §21.9). |
| GET | `/api/memory/status` | Global gates and persisted counts for each distinct memory store (`ApiResponse<MemoryStatusDto>`), including the `Tapestry` row gated by `Arcanum:Features:Tapestry`. Reads are not blocked when a prompt-time feature is disabled. The Tapestry count includes only **published** generations — a staging generation is invisible here for the same reason it is invisible to retrieval. |

**Covenant status is measured, not estimated.** `MemoryStatusDto.covenant` carries `enabled`, `available`, `census`, `counts`, the three rendered byte totals, `renderedByteCeilingPerSection`, search health, retention, and an optional `degradationCode`. The counts come from one content-free census — scope, lane, lifecycle, count — taken under the one installation read capability, because a census that crosses every Campaign needs a capability that does too; a scoped lease is refused rather than answered for part of the installation. Retired heads are counted as retired and contribute no rendered bytes, which the storage guarantees rather than the reader: a tombstone version carries no compiled content by table constraint, versions are append-only, and a trigger pins every head's byte cost to its own version's. No census is attempted at all when `enabled` is false, because the scan opens a canonical connection and that permanently forbids this process the offline host-process-tools transition, which is a heavy price for a count nothing wrote. On an enabled installation it is attempted whatever health is reported, because the operation gate already refuses a capability over a tier it cannot serve and a second health check here would suppress the counts of a degraded-but-readable tier. When it cannot be taken the counts are empty and the whole status call still answers: an operator asking whether their memory works is entitled to that answer even when the number behind it is momentarily unavailable. `census` is what makes that zero readable — `Read`, `Refused`, or `Failed` — because health cannot carry the sentence on its own: the gate refuses the installation capability whenever an exclusive operation is closing the scope, and it does so with the canonical tier reporting itself `Healthy`, so `available: true, counts: []` would otherwise be indistinguishable from an installation that genuinely holds nothing. `globalConfirmedRenderedBytes` is that section's whole cost, while `maxCampaignConfirmedRenderedBytes` and `maxCampaignProposedRenderedBytes` are the largest single Campaign's rather than installation-wide sums, because `renderedByteCeilingPerSection` bounds one Campaign's rendered section on one turn and a sum would exceed it while every Campaign was well inside it. `renderedByteCeilingPerSection` is a single number for all three sections because the three placement ceilings hold the same value, and a domain-contract test pins them equal, so giving one section a ceiling of its own fails there rather than leaving an operator comparing a Campaign total against a Global bound. The object is omitted entirely when no Covenant arm is composed, since an empty count and an absent arm are different facts. `search` (`state`, `executionMode`, `guidance`) is read from the host's published Covenant availability. That is republished after every committed write that moves the search position — an operator set, retire or correct, a review apply, an agent proposal published at turn commit, and an entry erasure — and after every maintenance batch, whether it applied anything or not. The curation route (pin, unpin, mask) moves no part of that position, so it republishes nothing. A write whose search projection is still pending therefore reads `Synchronizing` with `CanonicalFallback` until the next maintenance pass applies it, and `Healthy` with `Fts` afterwards, in the same running host; a fresh installation and a Covenant reset reach `Healthy` the same way, without a restart. `guidance` is `None` whenever search is synchronized, even though a fresh installation and a Covenant reset record a full rebuild as owed: the accelerator is then answering every query, which is also what a search page's own guidance reports. The first maintenance pass is what makes that so: until it has adopted the empty projection, a fresh installation and a Covenant reset read `RebuildRequired` on this block and on a search page alike, and `None` afterwards. `RebuildRequired` appears only while search is not synchronized, either no applied tuple names the current dataset or the accelerator is not Healthy, and a recorded rebuild is what it is waiting for; a projection that is merely pending behind a published tuple reads `WaitForSynchronization`, whatever rebuild the installation still records. `POST /api/memory/covenant/query` carries the same `search` object and derives it by the same rule, so the two routes agree on a state. A restore that keeps Covenant entries is the ordinary case for `RebuildRequired`. Nothing in this release starts an index rebuild, and the route that would is among those §8.28 lists as unregistered, so those entries reach the index only once every one of them has been rewritten, which names each head in a pending delta and lets the next maintenance pass adopt the projection. Until then search answers them through the canonical fallback and `guidance` stays `RebuildRequired`. Search results never depend on this field: each query reads the persisted position itself and falls back to the canonical scan whenever the projection is behind.

The sole local-authentication exception is `GET /api/presence`: after requiring the actual TCP peer to be loopback, it receives a random nonce and returns a nonce/authority-bound proof plus an encrypted short-lived process capability; it never receives or returns the reusable key. The normal key check runs as **middleware, before parameter binding**, so an unauthenticated request is answered **401 `Auth.Unauthorized` regardless of its body**: the body is never read, buffered, or deserialized first, and a malformed body no longer yields a binding `400` ahead of the `401`. Endpoint **matching** still precedes the key check, so `404` (no route), `405` (wrong method), and `415` (`Content-Type` the route does not accept) remain reachable without a key — none of them touch the body. `ApiKeyEndpointFilter` remains attached to the same routes as defence in depth. Immediately after the authentication stage, and still before any later decision, every matched, non-exempt `/api` and `/v1` route passes **Grimoire request admission** (§8.31): while a database transformation owns connection admission the request is refused with **503** before its endpoint runs, and the three statuses above stay reachable because a request that matched no route this host mapped is left alone. Legacy `X-Arcanum-Key` remains accepted for external clients; Arcanum's own long-lived CLI clients bootstrap through `/api/presence`, retain only the capability plus a fixed-size digest, renew single-flight before expiry, and send only `X-Arcanum-Process-Capability`. Their centralized authenticated sender binds every request to the presence-proof authority, rejects pre-populated credential headers, refreshes after one `401`, and replays at most once only for a request explicitly marked replayable. Its named clients disable redirects and proxies. Sending both credential forms is rejected as ambiguous. Capability validation is constant-time and stateless; capabilities expire and every server restart invalidates the prior process's tokens.

## 8. HTTP JSON and Minimal API design (`Api` project)

### 8.1 Wire contract: the `ApiResponse<T>` envelope

```csharp
public sealed record ApiResponse<T>(T? Data, bool IsSuccess, Error? Error, string? TraceId = null);
```

- **`ApiResponse<T>`** is the default envelope for JSON under **`/api`**; streaming and OpenAI compatibility are exceptions (§1, §8.5). `sealed record` for value equality and immutability.
- `Error?` is literal `null` on success. `TraceId` from `Activity.Current?.Id ?? HttpContext.TraceIdentifier`.
- `ApiResponse<T>.FromResult` is the single mapping point from `Result<T>` to wire envelope.
- **404 bodies:** JSON routes under `/api` return an `ApiResponse<T>` envelope on **404** (for example `Campaign.NotFound`, `Session.NotFound`) — not an empty body. Use `Results.Json(..., ArcanumJsonContext.Default.ApiResponse…, statusCode: 404)` or `Results.NotFound(envelope)` so clients always receive `isSuccess`, `error`, and `traceId`.
- **Media type:** JSON routes that read the request body themselves go through `ApiRequestJson.ReadAsync`, which requires a JSON `Content-Type` before reading. A route that must inspect the raw `JsonDocument` tree instead (`PUT /api/config`, `POST /api/config/validate`, which run `ConfigurationValidator.RejectObsoleteJsonKeys` before deserializing) still gates on `HasJsonContentType()` and returns the same `ApiRequestJson.UnsupportedMediaTypeResult` envelope first. A missing or non-JSON media type, or a JSON one whose `charset` parameter names an encoding .NET cannot decode (`windows-1252`, `shift_jis` and `gbk` among them, a quoted value, or a made-up name; `utf-8` is always readable), is a **415** `ApiResponse<T>` failure envelope carrying `Validation.UnsupportedMediaType` and the message `Request body must be sent with 'Content-Type: application/json' and, if it names a charset, one this server can decode (UTF-8 always is).`, not an unhandled framework `InvalidOperationException` surfacing as **500** `Hub.Unhandled`. The check (`ApiRequestJson.HasReadableJsonContentType`) runs before the read and follows the framework's own charset resolution, so nothing after it catches `InvalidOperationException`: one that still escapes a read is a fault of the server's own and stays a logged **500**. A JSON-typed but unparsable body remains **400** `Validation.InvalidBody` (`Request body could not be parsed as valid JSON.`), and a well-formed body that deserializes to null remains **400** `Validation.InvalidBody`.
- **Bound-body routes:** most `/api` writes let minimal-API binding read the body instead (a record parameter). The framework's generated reader answers a failed read in one of two ways, and the host covers both so the response carries the same `ApiResponse<T>` envelope in every environment. A body that is not valid JSON for the parameter, and a query, route or header value the binder cannot convert, are *thrown*: the host pins `RouteHandlerOptions.ThrowOnBadRequest` on, so they reach `ArcanumExceptionHandler`'s `BadHttpRequestException` arm rather than the framework's empty status (outside Development) or a logged **500** `Hub.Unhandled` (inside it), and are answered **400** `Validation.InvalidBody` (`Request body could not be parsed as valid JSON.`, or `Request parameters could not be bound to this route.`). Everything Kestrel raises *while the generated reader pulls the body*, and a `Content-Type` the route does not accept, are instead recorded as a status on the response and returned without throwing, whatever `ThrowOnBadRequest` says, so they never reach the exception handler: `UseArcanumExceptionHandler` installs a status-code hook that puts the envelope on that otherwise empty response, for **408** `Validation.BodyReadTimeout` (a body under the minimum data rate), **413** `Validation.BodyTooLarge` (a body past the ceiling) and **431** `Validation.RequestHeadersTooLarge` (trailers over the header ceiling) on a matched endpoint, and for **415** `Validation.UnsupportedMediaType` with the message `The request's Content-Type is not accepted by this route.` (a multipart route reaches it too, so the wording does not say JSON). The hook touches no other status: a route can return a bodyless **400** on purpose (`GET /api/presence`), and a body that ends early on a bound route is also a bare **400**, because it cannot be told from that and the client that dropped the connection is no longer there to read it. A JSON `Content-Type` whose `charset` .NET cannot decode raises `InvalidOperationException` inside the generated reader, which has no pre-check of its own; the exception handler answers it **415** `Validation.UnsupportedMediaType` only when the request itself is JSON-typed with an unreadable charset and carries a body, and any other `InvalidOperationException` stays the logged **500**. The framework's own wording is never echoed, the answer is logged at Debug rather than Error, and a response that has already started is left alone. Under `/v1` the same paths write the OpenAI error shape (`invalid_request_error`, code `payload_too_large`, `unsupported_media_type` or `invalid_request`). A route that reads its body itself therefore differs from a bound one in the 415 wording and in answering a truncated body.
- **Host header:** A loopback-only host (`Arcanum:Host:ListenAny` and `ARCANUM_HOST_ANY` both off) refuses, before any other middleware or route, a request whose `Host` header names anything but `localhost`, `127.0.0.1`, `[::1]` or the host of `Arcanum:Integrations:A2A:PushCallbackBaseUrl` (a port is ignored; the callback name counts only while `Arcanum:Integrations:A2A:PushNotifications` is on, which is what maps the callback route): the framework's host-filtering middleware answers a bare **400**. The socket-peer gates cannot stop a page that has rebound its own DNS name to 127.0.0.1, because that browser really is on the same machine; only the name it sends gives it away. The callback name lets a same-host proxy or tunnel that relays the public name a peer was told to post to (`reverse_proxy`, cloudflared) reach `POST {ServerPath}/callbacks/{configId}`. An all-interfaces bind answers any name and applies no filter: a LAN client or a reverse proxy relaying `arcanum.example.com` is not refused. No other operator-supplied name is accepted on a loopback-only bind.

### 8.4 Returning the envelope from a Minimal API handler

Successful endpoints use `Results.Ok(ApiResponse<T>.FromResult(result, traceId))`. Failable endpoints use `Results.Json` with the source-generated `JsonTypeInfo` and an explicit HTTP status code. No anonymous DTOs; no reflection-based model binding.

**Selected status contracts:**

- **`POST /api/intelligence/ping`** — `ApiResponse<PromptResponseDto>` on every path: **400** for request/reasoning validation, **200** on success, and shared `ArcanumErrorMapper` status for inference failures (for example 404/403/400/503/500 by stable code). The payload contract is detailed in §8.10.

- **`POST /api/intelligence/human-response`** — **400** validation (including the code-owned answer UTF-8 byte limit); **404** + `ApiResponse<bool>` failure when no waiter exists for `promptId` (`Intelligence.HumanPromptNotFound`); **200** + `ApiResponse<bool>` with `Data: true` when the answer is accepted.

- **`POST /api/mcp/reload`** and **`POST /api/intelligence/arsenal`** — Optional JSON body **`OptionalWorkspaceRequest`** (`{ "workingDirectory": "..." }` only). Responses remain `ApiResponse<T>` as today. The arsenal passes the MCP manager only the *normalized* workspace root: a `workingDirectory` that does not normalize to a workspace is treated as no workspace, so its server statuses come from the global surface alone and no workspace-local MCP configuration is resolved from the raw request text.

### 8.5 NDJSON streaming pipeline

`/api/intelligence/ping-stream` uses NDJSON (`application/x-ndjson`) for real-time token streaming:

- **Server:** Events serialized via `Utf8JsonWriter` + `ArcanumJsonContext`, newline-terminated, flushed per event. Writer: **`InferenceExecuteWriter`** (also used by spell/prompt `execute-stream`).
- **Wire shape:** Each line is an `IntelligenceEvent` with **camelCase string** discriminator **`type`**: **`"status"`**, **`"sessionBound"`**, **`"conversationBound"`** (deprecated alias emitted alongside **`sessionBound`** for one release), **`"context"`**, **`"token"`**, **`"reasoning"`**, **`"result"`**, **`"error"`**, **`"toolCall"`**, **`"toolResult"`**, **`"warded"`**, **`"wardResolved"`**, **`"toolError"`** (tolerated tool exception, emitted immediately before its `toolResult`; DESIGN §10.2.1). `context` carries the latest pre-call `ContextTokenBreakdown`; a second frame for the same call may add provider-reported input and variance after usage arrives. The enum is annotated with `[JsonConverter(typeof(JsonStringEnumConverter<IntelligenceEventType>))]` and per-member `[JsonStringEnumMemberName]` so the AOT JSON source generator emits the canonical strings. **`PingRequest.SessionId`** continues a Grimoire thread; when omitted the hub creates a new session on first assistant turn.
- **Ward frames:** `type:"warded"` and `type:"wardResolved"` carry `wardId`, `toolName`, and (on resolve) `allowed` / `reason`. Both may carry an additive **`origin`** — `human`, `autoApproved`, `autoDenied`, `timedOut`, `cancelled`, `hostRestarted`, or **`ungated`** — omitted when unknown, so a client that ignores the field is unaffected. Every server-executed tool call, including `retire_covenant`, uses `ungated`: the host atomically records an allowed resolution without creating an active Ward, asking an operator, timing out, applying unattended auto-deny, or producing an approval prompt. All Ward frames are informational regardless of origin; Command Center writes an audit note and never opens a modal or posts a resolution. The non-`ungated` origins remain historical/compatibility vocabulary for the retained Ward engine, and a `POST` for an already-resolved record returns **409** `Ward.AlreadyResolved`. Sanctum and every other containment check still run (DESIGN §11.14).
- **Reasoning frame:** `type:"reasoning"` carries a typed, client-safe payload separate from answer `data`: `{"type":"reasoning","message":"client-safe summary","reasoning":{"text":"client-safe summary","output":"summary"}}` (the shared event envelope may also contain its normal null/default members). `reasoning.output` is exactly `none`, `summary`, or `full`; projected frames use `summary` or `full`. Provider `ProtectedData` is deliberately absent.
- **Error frame:** `type:"error"` carries the public message in `message` and the failure's typed `ErrorCodes` value in `data`, on every path: a budget refusal (`Budget.Exceeded`), a guardrail block (`Guardrails.*`), a Session held by another turn (`Hub.SessionTurnBusy`), an attachment rejection (`Validation.AttachedFiles`), a model that could not be resolved (`Hub.Model`), and the Spell-routing, accounting, Covenant, and structured-output failures each carry the same code the buffered route returns in its envelope. `Hub.Error` appears only for a genuinely untyped provider or transport failure, including the writer's own sanitized stream failure. The HTTP status is already 200 once the stream starts, so `data` is the machine-readable signal a streaming client backs off or retries on, and the `/v1` stream error `type` derives from the same code.
- **Disconnect / cancellation (`InferenceExecuteWriter`):** the code-owned policy is **`Auto`**. With an `Idempotency-Key`, continue-then-replay — do **not** link `RequestAborted` to the inference token; drain the hub enumerator and keep exact-byte capture so the claim may Complete. Without a key, caller cancellation abandons the claim. Arcanum adds no inference deadline; caller/host cancellation propagates, while unexpected provider/transport cancellation is sanitized as a generic inference failure. Either way, ledger provider-billed partial usage and reconcile/release the reservation.
- **Clients (`ArcanumApiClient` and The Forge):** `StreamReader` reassembles transport-fragmented UTF-8 into complete lines, including multibyte characters split across transport reads. Before strict source-generated deserialization, an AOT-safe `Utf8JsonReader` scan validates the root `type`. Canonical values are matched case-insensitively and normalized before `ArcanumJsonContext` / `TheForgeJsonContext` deserialization; a truly unknown, nonblank future string is silently skipped so later frames continue. Invalid JSON, a missing/non-string/blank discriminator, or any whitespace-padded discriminator is **malformed** and retains the surface's diagnostic behavior. This narrow pre-scan does not install a permissive enum converter or reflection serializer: direct source-generated deserialization remains strict. The terminal **`result`** event carries native **`usage`** (`prompt_tokens`, `completion_tokens`, `total_tokens`, optional `cached_tokens`, optional `reasoning_tokens`) on the `IntelligenceEvent` payload; **`data`** still duplicates **`total_tokens`** as a decimal string for backward compatibility, while the final answer remains in accumulated **`token`** frames and the result `message`. Assistant text is never reconstructed from legacy result `data`.

### 8.7 Session-Based Consolidation (Campaign Logger)

Three mechanisms trigger Campaign Log consolidation:

1. **Message-count threshold** (`CampaignLogThreshold`) — safety valve for unbounded growth.
2. **Idle timeout** (`CampaignLogIdleTimeoutMinutes`) — natural session boundary.
3. **Explicit rest** — `POST /api/sessions/{id}/rest`.

The queue consumer resolves **`IArcanumIntelligenceProvider`** in a per-item DI scope alongside **`IGrimoireRepository`**, loads the session header via **`GetSessionHeaderAsync`**, and batches rows with **`CreatedAt > (LastSummarizedMessageAt ?? DateTime.MinValue)`**. It builds a stateless **`PingRequest`**: empty `Prompt`, `StatelessMessages` (system persona + user payload with prior summary and batched turns), **`SkipSpellRouting: true`**, **`DisableMcpTools: true`**, **`UnattendedMode: true`**, **`Model`** from **`Arcanum:FastModel`** when set else **`Arcanum:DefaultModel`**, else omitted for first-provider fallback, and **no** `SessionId` so the hub does not append a new **`Entry`**. On **`ExecutePromptAsync`** success, **`UpdateSessionCampaignRollupAsync`** atomically persists the LLM text into **`Session.Summary`** and sets **`LastSummarizedMessageAt`** to the latest batched entry time. On **`Result.IsFailure`** or exception, **no** DB update — the session remains eligible on the next sweep. The intelligence hub **reads** `Summary` for optional read-time compression (DESIGN §10.2.3).

For attachment privacy, the successful source turn records only typed consultation metadata. The Campaign Logger adds logical key, version, opaque attachment id, and source type for consultations inside the summarized window; it never loads attachment bytes, automatically submits the session's attachment index, or copies hashes/host paths into the summarizer payload. The prompt asks for useful decisions and source references, not an attachment archive.

Under the same **Session-Based Consolidation model of AI memory**, **Chronosync reporting** (DESIGN §5.4.2) addresses **spatial** drift: thread lines and `DomainType` deltas vs the last persisted `PatternSnapshot`, not chat log length. Campaign Logger and Chronosync are separate triggers; the hub folds `ChronosyncReport` into the system prompt via `PingRequest.ChronosyncDelta`; MCP context remains separate.

### 8.8 OpenAI `/v1` Chat Completions compatibility subset

`OpenAiV1Endpoints` advertises a **Chat Completions compatibility subset**, not full OpenAI API parity. Moderations/images/audio remain **`501 not_supported`**. Polymorphic `content` (string | parts) is AOT-safe; unsupported part types / over `MaxContentPartsPerMessage` → **400** `invalid_value` before mapping. Vision parts map to MEAI `TextContent`/`UriContent`/`DataContent` (DESIGN §10.2.4).

**Request body framing** (`POST /v1/chat/completions` reads the body itself rather than model-binding it, so it applies the §8.1 media-type rule in the OpenAI envelope): a missing or non-JSON `Content-Type`, or a JSON one whose `charset` .NET cannot decode, is **415** `invalid_request_error` / `unsupported_media_type` with the message `Request body must be sent with 'Content-Type: application/json' and, if it names a charset, one this server can decode (UTF-8 always is).`, not an unhandled `InvalidOperationException` surfacing as **500** `api_error` / `inference_failed`. A body over the endpoint's 16 MiB `WithLargeRequestBody` ceiling keeps Kestrel's **413** as `invalid_request_error` / `payload_too_large`; any other Kestrel `BadHttpRequestException` keeps its own status code as `invalid_request_error` / `invalid_request`. A JSON-typed but unparsable body remains **400** `invalid_json`, and a body that deserializes to null remains **400** `missing_body`.

**Parameters applied** (`ApplyInferenceParameters`): temperature, top_p, max tokens, penalties, seed, stop, response_format. Reasoning controls are additive: `reasoning_effort` = `none|minimal|low|medium|high|xhigh`, `reasoning_budget` = positive integer, and `reasoning_output` = `none|summary|full`. `reasoning_effort` and `reasoning_budget` are mutually exclusive and map to native `PingRequest.reasoning`; capability validation runs before provider I/O for buffered and `stream:true` requests. `reasoning_output` is an Arcanum-local projection/exposure preference and is passed to Microsoft.Extensions.AI only as a best-effort hint. It is not a guaranteed provider wire control, and Arcanum does not patch an unsupported `reasoning_output` field into provider JSON. When omitted, the resolved capability chooses `full` when `SupportsFull`, otherwise `summary` when `SupportsSummary`; `AllowsClientOutput` is required, and streaming also requires `SupportsStreaming`. Native effort/output and configured control-support/wire-dialect enums are strict string-only AOT contracts. OpenAI `reasoning_effort` and `reasoning_output` are also string-only. A numeric enum (defined or undefined) or an unknown enum string fails JSON binding before semantic validation. `n` must be `1` when present. When `Arcanum:Features:ClientTools` is disabled, requests with no tool definitions may still use the no-forwarding choices `tool_choice: "auto"` or `"none"`. Any supplied `tools` are rejected **400** `unsupported_parameter`; `"required"` and named choices are also rejected, either as **400** `invalid_value` when no tool was supplied to satisfy them or by the preceding `tools` rejection. Enabling the feature permits client-tool forwarding with schema/count validation (§8.8.3). `"required"` and named choices require at least one supplied tool (**400** `invalid_value` otherwise). If the health-selected model explicitly declares `supportsTools: false`, optional `tool_choice: "auto"` safely runs without tools, while `"required"` or a named function is rejected **400** `unsupported_parameter` before provider I/O. A requirement removed by effective tool policy is rejected **400** `invalid_value`, and a pre-commit runtime no-tools rejection may restart without tools only for an optional choice.

**Responses:** buffered answers remain in `choices[].message.content`; additive reasoning is in `reasoning_summary` and/or `reasoning_content`. Streaming answers remain in `choices[].delta.content`; reasoning uses the same additive fields on the delta, in provider order. A client that ignores the fields still reads an unchanged answer. Usage keeps `completion_tokens` and `total_tokens` authoritative and projects the reasoning subset at `completion_tokens_details.reasoning_tokens`; cached prompt subsets use `prompt_tokens_details.cached_tokens`. Buffered `message.tool_calls` still reports server-executed calls (§8.8.1); streaming SSE includes keep-alives and usage only when requested by `stream_options`. Semantic reasoning failures are typed OpenAI error bodies/chunks, never `delta.content`: they use HTTP **400**, `type:"invalid_request_error"`, `param:"reasoning"`, and the reachable stable code `invalid_reasoning_options` (effort plus budget), `invalid_reasoning_budget` (budget outside 1–2,097,152), `unsupported_reasoning_control`, `reasoning_budget_exceeds_model_limit`, or `unsupported_reasoning_output`. Numeric/unknown reasoning enum JSON never reaches those semantic branches; strict binding returns HTTP **400** `invalid_request_error`, code `invalid_json`, and no parameter. Unknown model → **404** `model_not_found`; tool-loop/timeout → **503** `server_error`.

**Current streaming projection topology:** production `/v1/chat/completions` obtains native `IntelligenceEvent` frames from `WizardIntelligenceProvider` (`TurnExecutionCoordinator` → `IntelligenceEventProjection`) and maps them to SSE chunks in `OpenAiV1Endpoints`. That endpoint mapper is the only OpenAI compatibility implementation (there is no second OpenAI projection), and the typed-error rules it applies live in `OpenAiStreamErrorMapper`. Terminal usage chunks, `stream_options.include_usage`, and tool-argument fragmentation are covered directly by production endpoint tests.

#### 8.8.1 Server-executed tools on `/v1` (buffered + streaming tool_calls)

Arcanum executes MCP tools server-side; `/v1` surfaces calls for observability/replay. Buffered: `PromptTurnResult.ToolCalls` → `message.tool_calls`. Streaming: `ToolCall` events → `delta.tool_calls` (40-char argument fragments; monotonic per-response `index`; fresh `call_…` ids). **`toolResult` never surfaced** on `/v1`. Forwarding mode preserves provider-minted ids and returns `finish_reason: "tool_calls"` without executing client tools. Richer native surface: `/api/intelligence/ping(-stream)`.

#### 8.8.2 `GET /v1/models` capability enrichment

`ModelInfoBuilder` is shared with `GET /api/models`, and both routes read the same latest successfully persisted configuration snapshot. Additive OpenAI fields: `context_window`, `supports_vision`, `provider_name`/`provider_type`, effective `supports_tools` (false only for an explicit `providers.models.supportsTools: false`), `supports_streaming` (always true), plus the same optional typed `reasoning` capability object returned by the native endpoint.

#### 8.8.3 Client tool security (forwarding mode)

When `Arcanum:Features:ClientTools` is enabled, Sanctum, Ward recording, and server tool audit do **not** apply to client-supplied tools (provider executes). Default remains reject. The native `/api/intelligence/ping` and `/api/intelligence/ping-stream` routes enforce the same feature switch when `forwardClientTools` is requested; the public `PingRequest` flag is not a bypass. `tool_choice` is parsed once with kind-safe JSON checks and is validated again after every Arcanum policy filter: a required or named choice is never converted to optional/no-tools behavior. Buffered JSON and streaming SSE use the same sanitized `tool_choice` error mapping.

### 8.9 NDJSON anti-buffering headers (`/api/intelligence/ping-stream`)

The NDJSON streaming endpoint sets `Cache-Control: no-cache` and `X-Accel-Buffering: no` (parity with the SSE endpoint in §8.5/§8.8) so reverse proxies (nginx, Cloudflare, k8s ingress) do not coalesce incremental frames.

**Idle keep-alive.** While the provider has said nothing for a whole `Arcanum:EventBus:HeartbeatSeconds` interval (default 30; `0` disables it, the same setting the SSE routes use) the stream writes a **blank line** (`\n`), so an idle connection is not dropped by a proxy or client that treats silence as a dead peer. NDJSON is one JSON document per non-blank line, so every conforming reader skips it, as `arcanum` and The Forge do. It is written between frames only, never inside one, and it counts as a response byte, so a stream whose provider fails before its first event still answers `200` with the terminal error frame, exactly as before.

### 8.10 Buffered `/api/intelligence/ping` envelope

The buffered ping endpoint wraps a **`PromptResponseDto`** (Core) inside `ApiResponse<T>`: `text` (assistant answer only), `usage` (native token counts, including additive top-level `reasoning_tokens`), `toolCalls` (the assistant-issued calls executed server-side, when any), `finishReason`, and `reasoning` (an ordered array of `{ text, output }` client-safe segments; empty by default). Reasoning is never concatenated into `text`. Previously the envelope held only the assistant text as a bare `string`; clients now get the full turn context without falling back to NDJSON.

**Request-side `toolPolicy`** (on `PingRequest`, and likewise on `SpellExecuteRequest` and `PromptExecuteRequest`) narrows what a turn advertises: `allTools`, `noTools`, `readOnlyTools`, or `noForbiddenArts` (semantics in DESIGN §10.2.1). Omitted is equivalent to `allTools`. Like the reasoning and tokenization enums (§8.8), it is a **strict string-only** AOT contract: a numeric enum — defined or undefined — and an unknown enum string both fail JSON binding before any semantic validation, surfacing as **400** `Validation.InvalidBody` on the native routes (written by the host's body-fault envelope for the routes that bind the body, §8.1, and by `ApiRequestJson` for the routes that read it themselves) and **400** `invalid_json` on `/v1`. The strictness is load-bearing rather than stylistic: an integer that bound to an undefined member would carry a restriction nothing in the system recognizes. Every consumer now resolves an unrecognized policy to `noTools` — the advertisement path advertises nothing, and the invocation context reports `noTools`, so an unknown value can never be the arm that widens what a turn may do. `disableMcpTools` and `toolPolicy` are both narrowing instructions and compose as their intersection: `noTools` disables MCP tools outright, and `readOnlyTools`/`noForbiddenArts` apply their advertisement filter **and** still honour the flag rather than superseding it.

### 8.10.1 Mana counter (`POST /api/intelligence/mana`)

Read-only model-aware estimate (`ManaCountRequest` → `ManaCountResult`); no inference/Grimoire writes. `model` resolves the configured provider/canonical model profile, while an unconfigured model uses the conservative fallback. The result retains legacy `manaCount` / `encoding` / per-message fields and adds classification, profile id, safety margin, and the complete `ContextTokenBreakdown`. `tools:true` materializes the current native + MCP declarations and includes their names, descriptions, and full JSON schemas in both the total and source breakdown. **400** when neither `messages` nor `prompt` is supplied.

### 8.10.2 Effective context preview (`POST /api/intelligence/context/inspect`)

`ContextPreviewRequest` accepts optional `prompt`, `model`, `workingDirectory`, `sessionId`, and `campaignId`, plus `showContent` and `noRetrieval`. Unified-run previews can additionally supply `overrideSpellName`, preview-only `attachedFiles` (`AttachedFileDto[]`) and `scryingFoci` (`ScryingFocusDto[]`), `disableAllTools`, `unattendedMode`, `additionalSystemPrompt`, `maxOutputTokens`, and the production sampling fields `temperature`, `topP`, `stop`, `seed`, `responseFormat`, `presencePenalty`, and `frequencyPenalty`. The assembled request passes through the shared native preflight validation pipeline used by live inference, including attached-file, request-bound, and Scrying validation. An empty prompt is valid so an existing Session can be inspected as it stands. The response reports the effective provider/model and context window, selected Spell and routing mode, resonant dependencies, included and excluded tools with reasons, every `ContextTokenSource` row with estimate classification, reserved output, the production compression decision, and auxiliary routing/embedding work. With retrieval enabled those auxiliary calls are real provider calls: each embedding opens and settles its own `embedding` run and is ledgered as an `embedding` billable operation, while the model-backed routing and Lexicon extraction calls are reported here but not ledgered. `noRetrieval` makes the preview spend-free; the main response is never inferred.

Prompt input uses the production ping bound. When `campaignId` is supplied without `workingDirectory`, the endpoint resolves the Campaign's server-host path exactly as buffered and streaming inference do; an unknown Campaign returns **404**.

**Canonical Campaign resolution (§10.12).** Every inference and preview route now resolves Campaign authority through the one canonical resolver before doing any other work, and the sources must agree rather than the first populated one winning:

| Condition | Status | Code |
|---|---|---|
| `sessionId` names a Session that does not exist | **404** | `Session.NotFound` |
| `sessionId` names a Session that predates immutable Campaign binding | **409** | `Session.CampaignBindingRequired` |
| `campaignId`, the Session's binding, or the supplied `workingDirectory` name different Campaigns | **409** | `Covenant.CampaignBindingConflict` |
| `workingDirectory` is supplied but is not contained by the resolved Campaign's registered root | **409** | `Covenant.CampaignBindingConflict` |
| a Global-only Session is given any Campaign source | **409** | `Covenant.CampaignBindingConflict` |
| the resolved Campaign no longer exists | **404** | `Campaign.NotFound` |

A supplied Session ID is never silently replaced with a new Session, and an unregistered working directory contributes nothing only while no other source has established a Campaign. The Campaign a turn resolves to is server-owned: no request body, MCP schema, or tool argument can name it directly.

The endpoint uses `WizardIntelligenceProvider`'s production routing, RAG readers, tool builder and policy filters, `SystemPromptBuilder.BuildDocument`, `InferenceContextBuilder.TryApplyContextCompressionIfNeeded`, and `IModelTokenEstimator`. It never enters the turn coordinator, invokes a tool, reserves turn budget, creates an assistant Entry, persists preview files/images as attachments, or calls the main inference model. `overrideSpellName` uses the same forced-Spell load and dependency resolution as a live turn and continues to resolve when `noRetrieval:true`; only automatic semantic Spell routing is skipped. `disableAllTools` and `additionalSystemPrompt` let a research dry run reproduce synthesis policy without executing it. `noRetrieval:true` skips embedding/RAG and automatic semantic Spell routing, with explicit unavailable reasons. Model-visible content is omitted unless `showContent:true`; that opt-in returns the assembled system prompt and messages through the authenticated operator API. Pre-call token values are labeled `exact`, `estimated`, `unknown`, or `reserved`; provider-reported values are never fabricated.

`arcanum run --dry-run` always requests `noRetrieval:true`, making it a spend-free static, pre-inference plan rather than an exact copy of the eventual live `PingRequest`. It validates and shows the resolved user payload, forced Spell, server context, tool policy, output reserve, and sampling controls without search or provider inference. A later live Agent handoff may still add locally produced `PatternSnapshot` and `ChronosyncDelta` context before inference.

### 8.10.3 Web research workflow request (`POST /api/web/research`)

`WebResearchWorkflowRequest` carries bounded `question`, optional positive `sourceTarget`, `model`, `tokenBudget`, optional `costBudgetUsd`, `continueSessionId`, and `attachToSessionId` fields. It also accepts optional `workingDirectory`, `campaignId`, current-turn `attachedFiles`, current-turn `scryingFoci`, and synthesis controls `temperature`, `topP`, `stop`, `seed`, `responseFormat`, `presencePenalty`, `frequencyPenalty`, and `unattendedMode`. These additions let `arcanum run --research` carry the same effective Campaign, Workspace, Session, Model, and explicit turn context as the ordinary Agent route. `tokenBudget` remains the synthesis output-token authority.

Before any search-provider work, the server validates the request and prospective synthesis request, resolves a Campaign-only request to its server-host working directory, and validates the continuing and attachment target Sessions. It then performs progress-driven search/read passes and uses the preflighted `PingRequest` for final synthesis. The research-only untrusted-source system instruction and `DisableAllTools` remain server-owned. Client filesystem paths are never dereferenced by this endpoint: callers send typed content, and the host validates and materializes it through the normal inference path.

There is no hop counter. Passes continue while they discover new unique URLs and stop at an optional `sourceTarget`, deterministic source exhaustion/no-progress, caller cancellation, explicit token/cost policy, provider/context failure, or a safety denial. The fetch phase that follows is bounded even when the request names no `sourceTarget`: a code-owned ceiling of 50 citations applies, and fetching stops once the retained page text already covers the synthesis prompt's character budget, since everything past it would be held in memory and then dropped unread. An explicit `sourceTarget` is the operator's own authority and is honoured as written.

On live synthesis, supplied `attachedFiles` and `scryingFoci` enter the normal attachment pipeline: when Attachments are enabled they are persisted and bound to the synthesis Session before model inference; when Attachments are disabled they remain in-memory current-turn content. A context preview never persists them. `attachToSessionId` is separate: it stores the final research Markdown, not the supplied synthesis context. Attachment is an optional side effect on an answer that is already billed by the time it runs, so a failure there is never terminal: the stream emits an `attachment_failed` progress frame carrying the attachment error and still emits the `result` frame, with `attachmentId` null. `/api/web/search` and `/api/web/browse` have no progress channel, so they carry the same fact as an `attachmentError` field on the result itself.

### 8.11 Daemon event SSE bus (`GET /api/events/daemon`)

In-process `IEventBus` uses code-owned bounded per-subscriber channels with `DropOldest`. Wire: `text/event-stream` `DaemonEvent` frames + best-effort `[DONE]`. A maintenance window ends the stream at a complete frame boundary with that same `[DONE]` (§8.32). `Arcanum:Execution:MaxSseConnections` and `MaxSseConnectionsPerType` feed `SseConnectionGate` → **503** `Api.TooManyConnections`. Anti-buffering headers; API key on the `/api` group. Rate limiting admits the HTTP request only, not open-stream duration.

`arcanum watch daemons` is the terminal consumer. It keeps heartbeats and `[DONE]` out of data output, supports free-form event/tool filtering, and offers opt-in reconnect. Reconnect cannot recover process-local daemon frames and therefore always warns that a gap may exist.

### 8.12 Configuration API (`GET` / `PUT` / `POST /api/config`)

Read: redacted secret-bearing URLs/endpoints (`***`) plus non-secret credential references; environment values are never read into the response. `GET /api/config`, `GET /api/models`, `GET /api/providers`, and `GET /v1/models` resolve one latest-successfully-persisted snapshot, so their configuration and discovery projections agree immediately after a successful write. Write: under the configuration-writer lock, re-read the current file, merge recognized redacted URL placeholders, run outbound and semantic validation, and atomically replace `arcanum.json`. Holding that lock across the entire read-validate-write transaction prevents a concurrent retention-rule update from committing between the full PUT's snapshot and replacement. Validate-only also merges recognized endpoint masks against the current snapshot before outbound and semantic validation, so an unchanged redacted `GET` document remains a valid update candidate; it never writes. Residual masks for new/unmatched providers fail closed. Provider API keys and PFX passwords are not accepted fields. Other non-retention runtime consumers remain bound to the process-start snapshot and require a host restart to adopt configuration changes; referenced secret environment values are resolved only at provider/certificate use. Status: **400** `Configuration.ValidationFailed`, `Config.UnresolvedMask`, or `Security.BlockedOutboundUrl`; **500** `Configuration.WriteFailed` or `Configuration.LockUnavailable` (another process held the configuration transaction past the bounded acquisition window). `POST /api/config/validate` answers **200** with `isSuccess: true` and `data: true` only when the merged document clears residual-mask, outbound, and semantic validation; every failure — semantic included — is a **400** failure envelope, so a status-code-driven probe cannot read an invalid configuration as validated.

#### 8.12.1 Familiar readiness (`GET /api/providers/{name}/familiar-probe`)

Answers whether a subscription-backed CLI provider is ready, without asking it for a completion. Runs host-side next to the process runner so Compendium — an editor that does not spawn processes — can ask over HTTP instead of growing a second implementation. Non-billable (ADR 0002 / `NonBillableSurfaces.FamiliarProbe`), alongside `GET /v1/models`.

`FamiliarProbeResult` carries `providerName`, `providerType`, `status` (`NotInstalled` | `NotConfigured` | `Configured`), `version` when the CLI reports one, a one-line `summary`, `remediation` text, a copyable `remediationCommand` the **operator** runs, `enumeration` (`Discovered` | `OperatorDeclared` | `Unknown`), `models`, and `hiddenModels`.

Redaction is structural rather than a filtering pass: the bound DTOs have no field for the account e-mail, organisation identifiers, or local paths that `claude auth status --json` and `codex doctor --json` print, so that material cannot reach this payload or a log. Arcanum never authenticates — `remediationCommand` is text the operator runs themselves. `enumeration: "Unknown"` is the ordinary outcome, because neither CLI publishes a machine-readable model list; clients fall back to free-text model entry and everything still works.

### 8.14 Spell Management API (`/api/spells`)

Workspace resolution: `?workspace=` → `Arcanum:Workspaces:DefaultRoot` → CWD. CRUD needs a resolvable workspace; empty `Arcanum:Security:SpellWorkspaceRoots` denies all (**403** `Spell.PathNotAllowed`). Built-ins under `~/.config/arcanum/spells/` are read-only (`Spell.BuiltinReadOnly`). Format: `SPELL.md` frontmatter + body; optional `SPELL.json` (legacy `SKILL.json` read fallback; writes always `SPELL.json`). Search shadow order is campaign > workspace > builtin and returns the complete deterministic match set rather than silently dropping results after 1,000. Declared dependency lists and cycle-safe graph traversal have no count/depth ceiling; single-file allocation, cancellation, visited identity, `MaxDeclaredTools`, and provider-facing `MaxResonantBytes` remain. Versions: string labels `SPELL.v{label}.md` (`^[A-Za-z0-9.]+$`); activate swaps into `SPELL.md` and records `activeVersion`, and skips the prior-content backup when the requested label is already the active one, because the two resolve to the same file. Import writes through the same frontmatter and `SPELL.json` bounds gate as create, so an imported bundle's `description`/`tags`/`model`/`provider` cannot smuggle a newline and forge an extra frontmatter key. `payload`, and its `fullContent` and `scripts`, are `[JsonRequired]`: a body omitting any of them is refused at the binding layer rather than binding null and importing a spell with no content. Every write failure answers **500** `Spell.WriteFailed` with a fixed sanitized sentence (§8.23, alongside `Workspace.WriteFailed`); the exception detail stays in the server log rather than returning an absolute server path to the caller. Export (`POST /api/spells/{name}/export`) reads `SPELL.md`, the sidecar, and every `scripts/*` file through the same fail-closed handle-identity read the scanner uses (DESIGN §11.6): a script or sidecar that is a symlink, a hard-linked file, a FIFO or device, or that resolves outside the workspace is skipped and logged rather than exported, and a `SPELL.md` that is not a readable regular file inside its root answers **404** `Spell.NotFound`. Script bytes are returned base64-encoded exactly as read, never decoded and re-encoded as text. Version activation reads the requested version file the same way and refuses one that is not a readable regular file with **404** `Spell.NotFound` before it writes the backup. Clone/cast/import quirks and status codes: §1. Import accepts no more than export emits, and refuses anything larger as **400** `Validation.InvalidBody` before it writes: a spell file or script over the per-file limit (the code-owned spell file limit, 256 KiB by default and never above the workspace read size), scripts that together pass the aggregate read-size envelope, more than 64 scripts (export stops at the same 64), or a script whose content is not base64. A bundle whose name matches a built-in spell is refused with **400** `Spell.NameCollision` exactly as a workspace duplicate is, because a workspace spell shadows a built-in one of the same name; create refuses the same name. A caller that cancels after the spell directory has been moved into place (clone or import) is not told the write failed: the spell exists, the summary is read back on a token of its own, and an error is logged only for a real failure. Per-workspace locks are taken before the spell snapshot is read, so concurrent updates, version writes, clones and imports each build on the previous result rather than rewriting one stale copy; once `SPELL.md` has been replaced by an update or a version activation, the `SPELL.json` write that completes it is not cancelled by the caller. Delete only under `{workspace}/spells/{name}`. Updating or deleting a spell that does not exist in the resolved workspace returns **404** `Spell.NotFound` through `ArcanumErrorMapper` (§8.23), matching `GET /api/spells/{name}`; built-in and validation refusals stay **400**.

`GET /api/spells` preserves the legacy `ApiResponse<SpellSummary[]>` response unless the nullable query flag is explicitly `paged=true`. Paged mode returns `ApiResponse<SpellCatalogPage>` with 50 metadata items, `hasMore`, opaque `nextCursor`, and `continuationAction`; it accepts `workspace`, `q`, `tag`, `tool`, `source`, and `cursor`. The cursor binds all filters/workspace plus the exact source/name/path identity of the prior anchor. A mismatched query, malformed cursor, or missing or changed anchor returns a structured **400** that instructs the client to restart with `cursor` omitted. Replaying the same input cursor is deterministic; the returned cursor advances. One cursor-name frame retains a 65,536-byte strict-UTF-8 boundary; **400** `Spell.ContinuationFrameTooLarge` reports the measurement and asks the operator to rename the spell or narrow the filters, then restart. The resource selector follows every advancing page, while Command Center `/spell list [opaque-cursor]` fetches one page and prints the exact next command. Legacy array consumers remain unchanged.

### 8.16 Log ring buffer (`GET /api/logs`, `GET /api/events/logs`)

Serilog → `SerilogLogRingBufferSink` → a code-owned bounded in-memory ring that overwrites the oldest entry. Query filters + `beforeSequence` cursor. Live SSE accepts nullable `LogLevel` `level` (`trace`, `debug`, `information`, `warning`, `error`, or `critical`) plus free-form `category` and `search`. The CLI forwards the level token without adding another client-side allowlist; API enum binding remains authoritative, and an unknown nonblank value returns **400** `Validation.InvalidQuery` before the response becomes SSE. ### 8.16.1 Unified CLI watch projection

The six CLI sources map one-to-one to existing server contracts:

| CLI source | Server contract |
|---|---|
| `watch session [session]` | `GET /api/sessions/{id}/stream`; optional `since=<entry-guid>` |
| `watch apprentice [apprentice]` | `GET /api/apprentices/{id}/chronicle` |
| `watch logs` | `GET /api/events/logs`; optional `level`, `category`, `search` |
| `watch mcp` | `GET /api/events/mcp` |
| `watch daemons` | `GET /api/events/daemon` |
| `watch health` | Repeated `GET /api/health`; `--interval` defaults to five seconds |

`watch <source>` is the only live-stream entry; the CLI ships no alias spellings for these. Every request uses the normal `/api` credential; the CLI neither widens authorization nor bypasses SSE connection caps. The shared SSE consumer joins multi-line `data:` fields without a client-only payload cap that the server could reach (a single line, or one event's joined data, is held to 64 Mi characters, above the server's 64 MiB tool-output ceiling; anything larger is discarded as a recoverable `Api.InvalidResponse` diagnostic instead of being buffered without bound), accepts LF, CR and CRLF line endings however the bytes are fragmented in transit, surfaces heartbeat comments as stderr liveness diagnostics while excluding them from data, reports the no-activity diagnostic after one to two idle intervals (the idle timer is armed once per window, not once per line), stops cleanly on `[DONE]`, uses UTC timestamps and event-type coloring in terminal mode, and returns **130** on Ctrl+C. `--json` reserves stdout for compact newline-delimited source objects and routes all diagnostics, including reconnect/gap messages, to stderr.

Repeatable `--event-type` and repeatable `--tool` (alias `--tool-name`) accept arbitrary case-insensitive values; blank values are ignored, and log tool matching recognizes structured `properties.ToolName` metadata. Reconnect is opt-in, retries unexpected disconnects and transient HTTP 408/425/429/5xx failures until cancellation with a code-owned capped exponential delay, and always reports a possible gap. Permanent validation/authentication/not-found/cap errors exit. A Session cursor may reduce the gap by continuing after the last received valid Entry id, but the bounded Session window is not a replay guarantee; Chronicle, log, MCP, and daemon streams have no replay cursor. Health polling accepts any positive whole-second interval and renders a valid Unhealthy 503 envelope as an observation. These are per-process CLI options and add no configuration surface.

### 8.17 Workspace registry and file browser/writer (`/api/workspaces`)

Campaign-backed when Grimoire ready (`persisted: true`); else in-memory. Writes gated by `Arcanum:Workspaces:EnableFileWrite` (default off) → **403** `Workspace.FileWriteDisabled`. Path policy: reject `..`/absolute; symlink escape → `Workspace.SymbolicLinkEscape`; revalidate before I/O. Atomic temp+rename for PUT/PATCH. Size clamps: DESIGN §3.4. PATCH ordinal replace with ambiguous/not-found codes; its read of the existing target is bounded by the same maximum file read size as GET contents, so an oversized target returns `Workspace.FileTooLarge` rather than buffering the whole file. HEAD contents returns size/`Last-Modified` only. The read routes (`GET .../files`, `.../files/info`, `.../files/contents`) map failures through the §8.23 authority exactly as HEAD and the write routes do — `Workspace.FileNotFound` → **404**, `Workspace.AccessDenied` → **403**, `Workspace.FileTooLarge` → **413** — while the list route's paging/search codes (`Workspace.ContinuationInvalid`, `Workspace.ContinuationCheckpointMissing`, `Workspace.InvalidSearchPattern`) stay **400**.

Link handling on the write routes is explicit rather than a generic I/O failure: a recursive DELETE first walks the tree (never following links) and, if any entry resolves outside the workspace, returns `Workspace.SymbolicLinkEscape` naming that link and deletes nothing; PUT or PATCH to a destination that is a symbolic link or has more than one hard link returns `Workspace.SymbolicLinkEscape` and leaves it untouched. Every write route (PUT, PATCH, DELETE and directory create) refuses protected workspace metadata: a path with a `.git` segment at any depth (including the `GIT~1` short name on Windows) or whose first segment is `.arcanum` returns **403** `Workspace.PathNotAllowed` before anything is created, changed or removed (DESIGN §11.6); the same refusal applies when an in-workspace symbolic link resolves into `.git` or `.arcanum`, and reads are unaffected. An operator can lift the refusal for every write route (and for the in-process `write_file`, `replace_text_block` and `apply_patch` tools) by setting `Arcanum:Workspaces:AllowProtectedPathWrites` to `true`; it does not replace the `Arcanum:Workspaces:EnableFileWrite` gate, so with that gate off every write route still returns **403** `Workspace.FileWriteDisabled`. PATCH is a read-modify-write: it replaces the target only if the file is still byte-for-byte what it read (length and SHA-256, including any BOM), so an edit by someone else that lands between the read and the replace, including an in-place edit that keeps the inode and length, or a target deleted in that window, returns `Workspace.WriteFailed` with the other edit left intact and nothing written; re-read and retry. The in-process `replace_text_block` tool applies the same rule. Both write routes are UTF-8 text routes, and neither rewrites bytes it cannot represent. PATCH decodes the target strictly: a target that is not valid UTF-8, or that contains a NUL byte and is therefore binary, returns **403** `Workspace.PathNotAllowed` and the file is left byte-for-byte untouched. PUT carries an existing destination's UTF-8 BOM across the overwrite, matching PATCH, so a read-modify-write loop through `GET .../files/contents` does not strip the preamble; a `content` value that already begins with U+FEFF supplies its own BOM and is never doubled.

Registration creates the workspace `.arcanum` directory **before** the Campaign row is persisted, mirroring `POST /api/campaigns`. A directory that cannot be created returns `Workspace.AccessDenied` / `Workspace.WriteFailed` and leaves nothing registered, so a retry is never blocked by a half-completed first attempt. Recursive file listing skips a subdirectory that vanished or cannot be read and returns the rest of the tree instead of failing the whole page. The listing walk runs off the request thread and proves containment once per directory chain rather than re-walking every ancestor component for each child; a symbolic link is still validated individually, since it is the one entry that can break a chain its parent already proved.

The CLI exposes this boundary directly as `arcanum workspace list|current|register|show|tree|info|read|search|index|index-status|chunks|unregister`. `tree`, `info`, and `read` call the authenticated file-browser routes and never read the client filesystem directly. File writes remain absent from this command family, so `Arcanum:Workspaces:EnableFileWrite` is neither bypassed nor implicitly enabled. `register [path]` sends the path to the server registry; omission uses the client current directory only because the shipping CLI targets the bundled loopback host. Help and output call every such value a server-host path so this convenience cannot silently become a remote path assumption.

### 8.18 Session API

Search, export, analytics, CRUD, manual entry append, SSE live stream, and Campaign Log **`/rest`** use the Grimoire-backed **`/api/sessions`** surface. See **DESIGN §11.16 Session lifecycle** for persistence and lifecycle architecture.

#### 8.18.1 Standalone session attachments

All routes are API-key protected and operate only on a bound attachment belonging to the route Session. Successes use the native `ApiResponse<T>` envelope except the content stream.

- **Snapshot:** `POST /api/sessions/{id}/attachments` requires multipart form field `file`; an optional `logicalName` chooses the version family. It persists the supplied bytes as an immutable encrypted snapshot with `SourceKind=SnapshotOnly` / `SourceStatus=NotApplicable`. The request may originate from any client-readable path or stdin because no client path is sent or retained. Unsupported binary/PDF/Office content is stored as `Binary` and remains `NotEligible` for text extraction; it is not rejected merely because Arcanum cannot materialize it into model context. The parser admits a maximum-size file plus 64 KiB of multipart envelope, but rejects aggregate overflow with `Attachment.TooLarge` for both declared-length and chunked requests.
- **Live reference:** `POST /api/sessions/{id}/attachments/reference` accepts `{ "workspacePath": "docs/notes.md", "workspaceId": "optional-id", "logicalName": "optional-key" }`. `workspacePath` is interpreted only on the server, relative to the selected registered workspace or the configured active/default workspace. Absolute values do not widen authority: canonical containment, link/file identity, stable bounded reads, and Campaign Sanctum must all pass. The response exposes only opaque/sanitized provenance; canonical paths and file identities stay encrypted server metadata.
- **List/versions:** `GET /api/sessions/{id}/attachments` returns all bound versions. Clients derive a latest-per-logical-key list or a version history without a second persistence authority. The server fulfills that all-version array contract by exhausting bounded SQL keyset pages; turn indexes and logical-name tool selectors use SQL-selected latest projections and retrieve version ordinals only for the requested index keys, rather than loading every full historical row first. `SessionAttachmentDto.SessionId` enables direct CLI output; `RelativePath` names the encrypted stored snapshot, never the live source. CLI Reveal uses it only when the corresponding local file is present and has an `ARCABLOB` envelope; otherwise the user is directed to authenticated export.
- **Refresh:** `POST /api/sessions/{id}/attachments/{attachmentId}/refresh` accepts no body or path. It calls the same `ToolExecutionPipeline.RefreshSessionAttachmentAsync` core used by `refresh_session_file`. An unchanged hash reuses the row; changed verified bytes create the next version under the measured per-Session byte protection without an incidental per-key version-count cap. Detected MIME determines the refreshed version's current Text/Image/Binary kind. Kind-specific policy is reapplied, but this operator endpoint does not require model vision capability because it injects no content.
- **Content:** `GET /api/sessions/{id}/attachments/{attachmentId}/content` opens only the authenticated stored snapshot through `ISessionAttachmentStore.OpenReadAsync`. It returns a download, never inline content, with `Cache-Control: no-store`, `X-Content-Type-Options: nosniff`, and no source path in headers. Attachment bytes are therefore available for atomic client export without ever being printed by metadata commands.
- **Pins:** the existing context-pin routes create/delete `kind=attachment` pins whose target is an attachment id and whose content version is its snapshot hash. Text pins may materialize implicitly within the shared pin/turn budgets. Image pins remain stored but materialize with `Unsupported`; a vision-capable turn must explicitly pass that bound attachment id.
- **Inference references:** native `attachmentReferences` remain ordered opaque IDs for Bound snapshots in the effective Session. Preparation validates metadata without loading every file. After provider/model resolution, the turn opens and admits each reference independently against the actual context window; overflow stops before opening later references or calling the provider. Successful content retains request order and typed attachment provenance. Caller cancellation propagates immediately and does not materialize later references.

`Attachment.Disabled` → **403**; `Attachment.InvalidRequest`, `InvalidContent`, `InvalidReference`, and `SourceUnavailable` → **400**; `Attachment.NotFound` and `SourceNotFound` → **404**; `Attachment.LimitExceeded` → **409**; `Attachment.TooLarge` → **413**. Error messages are bounded and never echo a source path. Refresh failures use this same mapping instead of collapsing every outcome to a conflict.

### 8.19 Server lifecycle (PID file)

The code-owned path is `~/.config/arcanum/arcanum.pid`. Startup claims the file with an atomic exclusive create and fails if it names a live Arcanum owner, with a message that names the file and says to remove it when no Arcanum process owns that PID; a stale file (malformed, a dead process, or a recycled id held by a process that started after the file was last written) is replaced, and two starters can never both claim it. Shutdown deletes the file only if it still names this process. DevHost and `serve` share the same path and therefore cannot run concurrently.

Every route in this family is protected by the normal `/api` key filter. Status and planning are read-only. Mutations are operation-specific; there is no generic memory-delete route and the CLI never mutates the Grimoire directly. CLI confirmation is an additional operator gate, not a substitute for HTTP authentication. Factory reset also requires the exact body token shown below.

Every handoff property is required once the object is present. `requestedOperationId` must be nonempty and identical in both locations. `installationPlanId` is the installation-reset plan identity and is distinct in meaning from the singleton `acceptedBinding.dataPlanIds[0]`, which must equal the request's `expectedPlanId`; their text is not required to differ. `Global` forbids `workspace`; `All` requires the exact valid workspace binding. Arrays and strings retain the current installation-plan bounds, and the complete candidate is preflighted against the 64 KiB authenticated-envelope boundary before any key, external identity, anchor, or file write.

`POST /api/data/factory-reset/plan` is a loopback-only planning seam used by the installation-reset coordinator. "Loopback" is judged as every other loopback-only gate judges it (`ArcanumTransportPeer`): the socket the request arrived on **and** the effective peer after forwarded-headers rewriting must both be loopback, so a same-host proxy relaying a remote client, or a forged `X-Forwarded-For`, is **403** `Data.Blocked`. `Global` forbids a workspace binding. `Workspace` requires the exact registered Campaign id and canonical root. The existing `POST /api/data/factory-reset` confirmation contract remains available for compatibility and retains its data-only boundary. A global/all installation reset obtains this authenticated online plan and rebinds its exact `planId` into the local installation plan before any dry-run output, disclosure, or confirmation; an unreachable host, missing API key, absent current Covenant inventory, or local/online candidate mismatch fails before active state or shutdown. Workspace installation reset remains offline. The reset-plan route, reset apply, factory-plan route, and factory apply all require `CovenantAuthorityRequirement.LifecycleManage` through the pre-binding authority boundary.

The typed handoff arm is host-owned. After API-key authentication and recovery-route admission, the endpoint validates the complete request and active recovery identity before it borrows the singleton installation maintenance lock. It reads the exact database installation UUID, begins or recovers the authenticated V2 publication, and only then starts/replays the data operation. Handoff-free requests do not resolve the coordinator or lock accessor. A pre-effect `Data.PlanChanged` retires the prepared publication under that same lock before the error response; cancellation, an uncertain response, any post-effect failure, or mismatched replay evidence leaves it active. On success the host advances the publication with the exact requested/server operation identities, data-plan identity, reconciliation, and observed counts before serializing the result. An existing exact proof is idempotent; a completed LRO replay that reports zero counts cannot erase a prior nonzero proof.

The V2 active envelope is internal persistence, not a second public payload. Its outer profile, installation, operation, revision, previous digest, location, scope, and plan fields are authenticated data and remain display-only until AES-GCM authentication succeeds and the decrypted payload repeats the exact operation/scope/plan. The envelope format version stays 2 while the record's payload version is 3, because what moved is the plaintext inside the envelope rather than the envelope itself: a record now carries the nested-transition receipt described below. Payload version 2 is read as a strict legacy value, may carry no receipt, and is migrated forward by the record's next publication; only version 3 is sealed. Partial, unknown, rolled-back, cross-profile, cross-installation, wrong-location, missing-key, missing-anchor, and noncanonical evidence all produce one content-free recovery refusal, and so does every parent-binding disagreement: a claimed receipt whose transition journal is absent, a journal carrying a parent binding with no reset record to be the nested arm of, a binding neither record can reproduce, a receipt naming a different nested operation, a nested transition of any kind other than a healthy-catalog factory erasure, a completion receipt whose effect digest is not the journal's, a stored completion beside a journal outside the retirement suffix that receipt implies, and two present terminal winner digests that differ. Which arm refused is deliberately absent from the message, because every one of them has the same remedy and the difference between them is not operator-visible detail.

`DataRetentionOperation` is emitted as `Prune`, `DeleteSession`, `DeleteAttachment`, `ResetMemory`, `FactoryReset`, or `ResetWorkspace`. The two DELETE routes construct the corresponding target operation from `{id}`; callers do not send a body. `MemoryResetScope` is emitted as `Entry`, `Attachments`, `Workspace`, `Saga`, `Lexicon`, or `Covenant`. `Covenant` uses the same plan/apply vocabulary but never the ordinary reset executor: preview returns its content-free inventory, and apply commits the V4 `InventoryPrepared` launch checkpoint before acquiring exclusive admission and then awaits the ten-phase coordinator (DESIGN §10.20.1–§10.20.4). A Covenant reset is always standalone work: only a healthy-catalog factory erasure may run as the nested arm of a broader workflow, and a Covenant reset that arrives carrying a parent binding is refused rather than adopted. Enum input matching is case-insensitive; responses use the canonical casing shown here. `RetentionDataClass` response values likewise retain their CLR casing, such as `ActiveSessions`. `Covenant` is inventoried and has no configurable rule at all: `PUT /api/data/retention` with that class is refused **400** `Data.InvalidRequest` with a message saying so, deliberately distinct from the "not recognized" refusal an unknown class receives. `RetentionRuleUpdateRequest.dataClass` names one configured rule. Matching is case-insensitive after hyphens, underscores, and spaces are removed; grouped aliases include `attachments`, `workspace-indexes`, `accounting`, and `daemon-history`, while typed attachment, batch-file, workspace, and accounting subclasses resolve to their governing rule. `days` is clamped to 1–3,650 and is required when `enabled` is `true`. It is optional when `enabled` is `false`; disabling a rule preserves its prior day value and does not add a capability restriction to explicit deletion. `GET /api/data/retention` returns the complete effective policy, including sweep bounds, accounting floor, and protected session ids. A successful PUT persists the normalized rule and makes it immediately authoritative for subsequent GET, status, and planning calls. The same process-authoritative snapshot controls subsequent inference- and guardrail-log planning and apply calls. Log writers only create, secure, and append dated files; they never enumerate or delete historical files. The former host/security day fields are removed. A query without `from` searches all dated files, and only the canonical `AuditLogs` / `GuardrailLogs` retention rules can trigger age-based mutation. Mutation selectors and `enabled` are required: omission never selects a default destructive scope or silently substitutes `false`. The sole presence-aware field is retention `days`, under the rule above. Data-class and memory-scope choices accept documented names and aliases only; JSON/CLI numeric enum spellings are rejected before mutation.

**Status.** `DataRetentionStatus` contains `generatedAt`, `items`, aggregate `rows`, `files`, and `estimatedBytes`, plus `preservedOutsideSelectedRoot`. Each `DataRetentionStatusItem` has `dataClass`, `rows`, `files`, `estimatedBytes`, `policyEnabled`, nullable `retentionDays`, `store`, and safe `provenance`. The typed class list and physical ownership are defined in DESIGN §5.4.7. For a composite physical owner, `rows` includes its canonical row plus owned companion, index, and provenance rows. File counts and `estimatedBytes` describe managed files that actually exist at inspection time; they do not estimate missing metadata targets or SQLite page allocation. Batch input/output/error items count role references, so one uploaded file may appear in more than one of those items; the response-level aggregate totals exclude those reference-only roles and sum physical owners. The response contains no plaintext content, secret, or host source path. Optional `memoryErasure` carries `fingerprints`, `receipts`, and `receiptSubjects`: content-free counts of the selective-erasure evidence (§8.35), with no fingerprint, key id, digest, store, or scope. It sits beside a `MemoryErasureEvidence` item whose `rows` is the sum of the three counts, always with `policyEnabled: false` and a null `retentionDays`; a catalog below Core 13 reports zeros. Erasure evidence is never aged out and no prune or reset selects it: `PUT /api/data/retention` with `memory-erasure-evidence` is refused **400** `Data.InvalidRequest` with its own message, and the rows go only through a release, operator re-creation, `memory erasure reset-key`, restore's destination-authoritative join, or a full installation reset.

**Covenant inventory.** `DataRetentionStatus` and `DataRetentionPlan` each carry an optional `covenant` object with `rows`, `managedFiles`, `localArtifacts`, `affectedSessions`, `possibleDisclosures`, and `disclosureCountKind` (`Exact` or `LowerBound`). It is counts only — no subject text, key, digest preimage, path, or Campaign identity. `possibleDisclosures` folds only **nonrevocable** buckets, because it sits beside a statement about what local removal cannot revoke, and one lower-bound bucket carries the whole total to `LowerBound`. The buckets are the effective disclosure state: each acknowledged receipt counts as soon as it commits, and receipts recorded before the live disclosure fold existed are counted too, which makes `disclosureCountKind` `LowerBound` rather than reporting no disclosure. Status and non-erasure plans omit the field when no Covenant read capability could be taken: a zero would read as a measurement where the honest answer is that nothing was measured. A `Covenant` status item appears in `items` only when measured, always with `policyEnabled: false` and a null `retentionDays`. Explicit Covenant reset and factory plans instead require a current installation inventory and fail closed rather than returning an unmeasured destructive plan. The `covenant` object remains outside `planId` for prune and workspace planning, so unrelated family writes do not expire operations that do not select it. Covenant reset and factory reset do select the family, so their plan identities bind all five counts and `disclosureCountKind` (DESIGN §10.20.1).

When a reset or factory preview carries Covenant inventory, its endpoint acquires exactly one installation read lease with that inventory and transfers both to `CovenantProtectedJsonResult<DataRetentionPlan>`. The lease is revalidated immediately before the first byte and released only after serialization or typed refusal. Success and failure on all four lifecycle-authorized routes carry `Cache-Control: no-store, private`, `Pragma: no-cache`, and `Expires: 0`; `ETag` and `Last-Modified` are removed. The lease itself never crosses the wire or survives into CLI confirmation. A protected `Request` or `Installation` plan admission that does not return its required live lease is refused; this does not change the ordinary lease-consuming `PlanAsync` wrapper used by prune/workspace callers or feature-off status projection. Within a healthy-catalog factory apply, the current plan and catalog are established from one installation snapshot and any mismatch before effects fails closed. Reset apply re-plans under installation authority and binds the optional `MemoryResetRequest.expectedPlanId`; the bundled CLI always sends the preview id after confirmation. Omitting it preserves backward-compatible direct API behavior. Factory installation validation binds its matching online plan.

**Dry-run plan.** `DataRetentionPlan` contains `planId`, the normalized `request`, `generatedAt`, per-class `items`, `blockers`, `conflicts`, aggregate `rows`/`files`/`estimatedBytes`/ `derivedRecords`, deterministic `candidateIds`, and `requiresConfirmation`. Every item reports `dataClass`, `rows`, `files`, `estimatedBytes`, and `derivedRecords`. Blockers report `dataClass`, `resourceId`, `reasonCode`, and a sanitized `message`; conflicts report `code`, `resourceId`, and `message`. Optional `sagaCuration` contains `pinnedRows` and `pinnedRowsExemptFromPlan` (§8.30): every pinned Saga memory, and the pinned memories this plan's own cutoff would otherwise have selected. Optional `lexiconCuration` contains `pinnedRows` and `pinnedRowsExemptFromPlan` (§8.33). Both are plan-only inventory. Optional `memoryErasure` (`fingerprints`, `receipts`, `receiptSubjects`) appears on factory-reset plans only and counts the erasure evidence a standalone factory reset keeps: a `--global` or `--all` installation reset removes that evidence with the Grimoire and the erasure key, so after one nothing remains in force. It is never a plan item, it is absent from every other plan, and it is outside `planId`, so a release between two previews does not change the plan identity. Planning reads the same dependency graph used by apply and does not write rows, files, operation history, or checkpoints.

**Apply.** Apply recomputes the current plan. If `expectedPlanId` is present and differs, the server returns `Data.PlanChanged`; clients must preview again. The bundled CLI always fetches the exact plan immediately before `--apply`, shows it in human mode, confirms its id and totals, and sends that id as `expectedPlanId`; `--json --yes` performs the same binding but emits only the final apply result as one machine-readable JSON value. Policy prune leaves blocked/conflicting candidates untouched while applying unrelated eligible candidates. Explicit session/attachment deletion and scoped/global reset fail when their selected target has a blocker or conflict. A prune candidate that becomes protected after planning is preserved and reported through a `Data.PlanChanged` conflict while later independent candidates may still run. Its checkpoint stays before the earliest preserved candidate so recovery re-evaluates that boundary instead of silently skipping it. A successful `DataRetentionApplyResult` reports `operationId`, the applied `planId`, deleted row/file/estimated-byte/derived-record totals, `reconciled`, and the plan diagnostics. A memory reset of any scope but `Covenant` whose preview selected nothing applies as a successful, reconciled no-op with zero counts, and the bundled CLI exits `0`; rows that appear after that empty preview are refused as **409** `Data.PlanChanged` (or, when they arrive inside the apply's own transaction window, **409** `Data.Conflict`), and a fresh preview is needed. A Lexicon candidate pinned after planning is preserved with the distinct `Data.PinnedAfterPlanning` conflict; the plan inventory is not repeated in the apply result. Execution is bounded, durable-operation-backed, checkpointed, and restart-idempotent. Each planned candidate receives a bounded post-delete ownership check for its selected rows, derived records, and owned files; `reconciled` is true only after every applicable candidate check succeeds. This is not a global orphan-vacuum operation.

`MemoryResetScope.Covenant` is the protected exception to ordinary result accounting. Apply takes a fresh installation planning lease, rebuilds the current plan and five-count inventory, validates a nonempty current dataset, and compares the supplied preview plan id before it starts a durable mutation. For this explicit erasure, the identity includes the inventory; neither ordinary-plan drift nor changed counts can silently cross confirmation. It then commits the `InventoryPrepared` launch, releases the planning lease, and enters `CovenantErasureCoordinator` under the launch-derived owner. It returns only after `CommitAndReopen`, fresh disclosure-writer reopen, general-admission reopen, exclusive release, and durable terminalization. Its success keeps the originally confirmed plan id and reports zero deletion counters: retained disclosure evidence is part of the preview, so those aggregates are not an exact deleted-row/file/byte ledger. A client cancellation before immutable proof may park the operation for exact-owner recovery. After proof it cannot interrupt publication, writer reopen, disposition, or failure recording.

For every file-bearing prune candidate and explicit deletion, the durable checkpoint carries an exact `ARCAMUT2` manifest with the mutation subtype/target, managed-root role, normalized relative path, captured no-follow identity metadata, and operation-scoped same-parent quarantine prefix. Recovery examines only that manifest-declared namespace; unrelated or malformed quarantine is rejected fail-closed. Factory reset uses a separate whole-root recovery contract and re-inventories the complete managed roots when it resumes.

The dependency contract removes owned derived rows and bytes—attachment chunks/embeddings/index state with the attachment, Entry embeddings with Entries, and workspace embeddings with chunks. Managed-file deletion uses no-follow identity capture and apply-boundary revalidation; an object that changes identity is preserved with its metadata and the operation fails closed. Batch references protect uploaded files. Pinned Entries/context/attachments, protected sessions, active operations/inference/idempotency leases, outstanding budget reservations, and in-progress batches remain visible as blockers/conflicts. The effective accounting age is never shorter than `accountingMinimumDays`, and `Sessions.TotalCostUsd` is not accounting authority.

Deleting an attachment does not silently delete independently retained Saga or Lexicon facts. Their typed provenance remains and resolves the missing source as unavailable. Factory reset clears only managed data beneath the configured root and never silently deletes external backups, registered out-of-root workspace content, configuration, or security/credential/key material. The Forge-owned local histories are outside this API's implementation boundary and remain untouched; no coordinated cleanup integration is added by this feature. Prior terminal operation history is cleared in dependency order, while the successful factory reset necessarily leaves its own completed durable-operation marker as the audit/recovery record for that mutation. The `DaemonExecutions` status/plan item includes both process-local execution summaries and persisted Unseen Servant schedule watermarks, so factory-reset previews account for both before clearing them. Factory previews exclude reference-only batch roles and count dependency/index/provenance rows as derived records.

With a healthy Covenant catalog, one `DataRetentionFactoryReset` operation owns both protected and ordinary deletion. V2 `InventoryPrepared` is committed from the confirmed installation snapshot; protected database and managed-file kernels run first; then a required restart-idempotent ordinary continuation rebuilds and applies the ordinary plan after `ManagedArtifactsProcessed` and before `HandlesClosed`. The same exclusive lifecycle therefore covers ordinary cleanup, handle closure, WAL truncation, compaction, sidecar proof, runtime publication, writer reopen, general-admission reopen, and exclusive release. Recovery adopts the exact checkpoint owner before readiness, reruns the continuation at `ManagedArtifactsProcessed`, and skips it at `HandlesClosed` or later; V0 remains unchanged. The response preserves the original plan id and reports the continuation's executor-observed ordinary totals. A same-snapshot catalog or plan mismatch is fail-closed with zero effects.

Factory plans retain `Data.InferenceRunActive` and its exact resource identity in the confirmed `planId`. Only this diagnostic is drainable at the two pre-launch eligibility checks: already-admitted inference must finish during stage one. The factory-only closed-catalog preflight then refuses any still-`Running` inference row with `Data.Conflict` (**409**) before canonical, managed-file, ordinary, or credential effects, and performs a proven pre-effect rollback and reopen. All other conflicts and stale `Data.PlanChanged` checks remain strict; ordinary continuation and its transactional conflict check remain strict too. Completed accounting, audit, and indexing work from the drain is included in the continuation's re-inventoried ordinary totals without changing the protected launch binding or the response's confirmed plan id.

A global or all-scope installation reset that runs its data phase offline is the one workflow that launches this erasure as a nested arm. It claims the nested operation identity in the same publication as its point of no return, because that is the same fact from the other side: from there a nested database transition is about to exist, and a crash before the launch has to read as "one was started" rather than as "none ever was". The erasure's transition journal commits a parent-receipt binding before any effect — SHA-256 under a dedicated domain over the outer operation identity, the nested operation identity, the nested canonical effect digest, and the completion phase. The terminal winner digest is deliberately outside that preimage: it cannot be known before the effect, and a binding computable only afterwards could not be committed beforehand. After the exact terminal compare-exchange and before the journal may retire, the erasure publishes its completion receipt into the outer authenticated record, rereads that record, and recomputes the binding from what came back; equality is the proof that the two records describe one piece of work. An already-exact receipt is reread and never republished, so a replay does not advance the outer envelope revision a second time. A receipt that cannot be published, or that reads back as something else, keeps the transition closed and repeats no effect. A workspace-scope reset, an online handoff completion, and a direct factory reset claim nothing and publish nothing.

`requestedOperationId` is the optional installation-handoff replay key and is valid only with `expectedPlanId`. The server atomically starts or replays one factory LRO for that identity and returns the caller identity separately in `DataRetentionApplyResult.requestedOperationId`; `operationId` is always the distinct server-created durable operation identity. The replay key is never a root operation, server operation, Covenant gate owner, or lease owner. A replay with the same fixed apply/effect digests returns the same operation outcome; an identity/digest conflict is refused without creating a second erasure. The installation reset accepts completion only when the response proves the confirmed plan, matching requested identity, distinct server identity, reconciliation, and terminal success, then stores that content-free proof monotonically before shutdown.

The factory LRO enters one lease maintainer immediately after named or unnamed durable start. Maintenance spans re-plan/catalog proof, V2 checkpoint publication, coordinator execution, the ordinary continuation, and terminalization, closing the former pre-checkpoint adoption window. Ordinary continuation renewal/deletion is a compare-and-set over operation ID, `Running`, exact owner, and live expiry. Factory V0/V2 and reset V4 recovery use the same maintainer with the reconciler-adopted owner; loss of ownership stops further work and returns content-free requires-attention recovery. The launch checkpoints are `DataRetentionFactoryTransitionLaunchV2` for a healthy-catalog factory erasure and `CovenantOfflineTransitionLaunchV4` for a Covenant reset, filed under different durable kinds because one shape spanning both would be a payload whose meaning depended on the row it happened to be read from. Nesting adds no `CovenantResetPhase` member, no reconciliation step, and no further checkpoint version.

Global factory apply never treats a missing Covenant lease or inventory as permission to delete only ordinary data. Production composition supplies the gate and catalog independently of the inference feature policy and may prove an empty family; an unmeasurable inventory, unhealthy catalog, or missing exclusive lifecycle fails closed before ordinary effects. The ordinary cleanup kernel still uses its restart-idempotent immediate database transaction plus daemon-start gate, but only as the protected coordinator's continuation or the unchanged legacy V0 recovery arm. Prune and explicit data mutations also share an atomic cross-kind single-flight start, while elapsed-time heartbeats keep ownership during a slow candidate. Inference and guardrail audit writers share a singleton managed-log publication gate with factory reset. The reset takes that gate before its database writer transaction and holds it through log inventory, quarantine, commit, cleanup, and reconciliation: an append that wins is counted and cleared, while an append waiting behind the reset is published afterward and is not reported as a deleted file. Each logger retains its private append serialization and best-effort failure behavior. Managed factory-reset files move into identity-verified, owner-only same-parent quarantine before the database commit. Rollback restores them; after commit cleanup removes them, and restart recovery re-inventories the managed roots, discovers any quarantine left by a crash, and resumes the idempotent whole-root cleanup. Logical row deletion and file unlinking do not promise physical secure erasure on SSD, copy-on-write, snapshot, WAL/free-page, cache, encrypted-replica, or backup media.

This route family maps `Data.InvalidRequest` and `Data.ConfirmationRequired` to **400**, `Data.NotFound` to **404**, `Data.PlanChanged`, `Data.Blocked`, `Data.Conflict`, and `Data.OperationNotFinalized` to **409**, and `Data.ReconciliationFailed` and `Data.QuarantineRecoveryRequired` to **500**. Other failures delegate to the central `ArcanumErrorMapper`; protected erasure failures therefore keep their frozen statuses, including **503** for `Covenant.ErasureIncomplete`, `Covenant.MaintenanceFailed`, `Covenant.ManualArtifactErasureRequired`, and `Covenant.ManualRecoveryRequired`. An unexpected unclassified apply failure is **500**. The retention rule PUT route returns **400** for `Data.InvalidRequest`; an unexpected policy-store failure is **500**.

### 8.21 The Proving Grounds (`POST /api/proving-grounds/trials/run`)

Ephemeral Trial + Inquisitors (`regex` / `jsonSchema` / `semantic` FastModel judge). `jsonSchema` delegates to the shared `JsonSchemaHelper` and enforces exactly these keywords: `type` (a string, or an array of types of which any one satisfies the schema, `null` included; an unrecognized type anywhere in it fails the verdict), `properties`, `required`, `items`, `enum`, and `additionalProperties` (boolean). Every other keyword (for example `minimum`, `pattern`, `oneOf`, `$ref`) is ignored, and an unreadable schema is a failed verdict. Targets: spell / prompt / apprenticeGoal. Terminology strict — industry LLM-test jargon prohibited. Errors §8.23.

### 8.22 Metrics endpoint (`GET /metrics`)

Prometheus text `0.0.4` via `System.Diagnostics.Metrics` + hand-rolled exporter (no OTel/prometheus-net — AOT). Catalog: HTTP requests, inference duration/tokens, tool outcomes, SSE gauge, active sessions (scrape-time query), Sanctum breaches, plus `arcanum_estimated_input_tokens`, `arcanum_provider_reported_input_tokens`, absolute `arcanum_input_token_estimation_variance` (low-cardinality `direction=underestimated|overestimated|exact|inconsistent`), and `arcanum_context_budget_rejections_total`. `arcanum_tool_invocations_total` has the closed `outcome=success|denied|error` domain (Sanctum and other live-policy refusals are `denied`) and uses the invocation's canonical `tool_name`; a model-supplied name that was never registered collapses to `unregistered`, so arbitrary model text cannot create a metric label. `arcanum_ward_decisions_total` applies the same `tool_name` rule and counts Ward outcomes with the closed `origin=human|auto_approved|auto_denied|timed_out|cancelled|host_restarted|ungated` domain; current server tool calls use `ungated`, while the other values remain compatibility vocabulary. Resolution reason text, tool arguments, and paths are never labels. `arcanum_apply_patch_artifact_cleanup_total` is count-only with closed `outcome=complete|retained`; it never labels paths, sessions, or receipt IDs. Token histograms use token-scale buckets rather than duration buckets; provider/model labels remain low-cardinality (+ runtime meters via `MeterListener`). Path outside `/api`/`/v1`, which is also what keeps it outside Grimoire request admission (§8.31): admission is selected by whole-path-segment prefix, never by whether a route carries API-key metadata, so an authenticated `/metrics` bypasses it while `/apiary` and `/v10` are never swept into it. A scrape during a maintenance window still queries active sessions and is refused by the database itself, which reaches the caller as the same sanitized **503**. `Arcanum:Features:Metrics=false` → **404**. `Arcanum:Security:MetricsRequireApiKey` defaults true and is forced true on ListenAny. Auth: `X-Arcanum-Key` or Bearer.

### 8.24 OpenAI embeddings (`POST /v1/embeddings`)

Composes `IWeaveService` + tokenizer. `model` must match `Arcanum:Integrations:Embeddings:Model` or be omitted → else **404** `model_not_found`. Long inputs use code-owned chunking + mean-pool/L2. `encoding_format` is `float|base64` (`EmbeddingBlobCodec`). Idempotency-Key is supported, and (like `/v1/chat/completions`) its fingerprint is the raw request bytes. Embedding provider calls have no Arcanum whole-operation deadline; request-abort/caller cancellation propagates directly, while provider failures are sanitized as **503** — including a provider answer whose vectors are not all the same width, which is refused rather than mean-pooled into a silently truncated embedding. That width check is a property of the whole response rather than of one round trip: a request issues one provider call for its short inputs and one per long input, so the assembled `data[]` is checked for a single common width before it is written, and a pool that answers each call consistently but the request at two model widths is refused the same way. Errors use the OpenAI envelope (**400** invalid input/chars, **400** `invalid_json` for a body that does not parse, **415** `unsupported_media_type` for a non-JSON `Content-Type`; **503** when The Weave is unavailable). The body is read by the handler rather than bound as a route parameter, so a malformed body never produces a body-less framework 400/415.

### 8.25 HTTP response compression

Brotli+Gzip via ASP.NET ResponseCompression; early pipeline. Excludes `text/event-stream` and `application/x-ndjson`. `EnableForHttps` left false (framework default).

### 8.26 Persisted inference audit log

Opt-in JSONL (`Arcanum:Host:AuditLog:*`); dated files, owner-only, with a soft daily size cap. A row is written only after a turn completes successfully (ping / ping-stream / v1-completion today); errors, cancellations, and interrupted streams are not audit rows. The writer never deletes historical files: age-based removal runs only through the bounded, durable unified data-retention planner/service under `Arcanum:Retention:AuditLogs`. When an audit query omits `from`, it searches every dated file instead of applying a hidden lookback. `GET /api/audit` keeps the existing `ApiResponse<InferenceAuditRecord[]>` body and supports `from`, `to`, `model`, `sessionId`, and `limit` (default 100, maximum 1,000). Records are newest-first. When more retained matches may remain, the response includes `X-Arcanum-Next-Cursor`; repeat the unchanged query with that opaque value as `cursor`. The cursor binds the audit family, configured file family, all filters, the first-page snapshot time, dated-file prefix identity, and reverse byte boundary, so active appends cannot shift the traversal. A malformed, filter-mismatched, replaced, or retained-away cursor returns **400** `Validation.InvalidQuery` with an exact restart-without-cursor action; so does a `from` or `to` that is not a date/time, or a `from` after `to` (the same code `GET /api/guardrails/audit` returns, so the two routes' query contracts match). Readers reverse-scan fixed 64 KiB blocks and stream one JSON record segment at a time; neither the complete file nor skipped records are materialized as a string array. Tool names and counts are metadata; `Arcanum:Host:AuditLog:RedactToolArguments=true` (default) makes `toolArgumentsJson` null, while opting out records the exact raw argument snapshots at operator risk. Tool results, prompt/answer bodies, and reasoning bodies are never fields in this log. Audit failure is warning-only and never changes the already-successful turn. A dated file the reader discovers but cannot open or read — a mode/ACL change, a disk error, a lock held elsewhere — is skipped and the page still returns **200**, so the omission is reported as a **Warning** naming the audit family and the file path; a file that simply vanished between enumeration and open is the retention sweep doing its job and stays at Debug. The same handling applies to `GET /api/guardrails/audit` (§8.27), because both routes share `AuditLogPageReader`.

### 8.27 Content guardrails (PII / toxicity / topics)

Opt-in via `Arcanum:Features:Guardrails` (default false), with policy under `Arcanum:Security:Guardrails`. Input PII (GeneratedRegex, each pattern with the same 500 ms match budget as the operator topic patterns) → `Guardrails.PiiDetected`; toxicity/topics → `Guardrails.Blocked`. A PII or blocked-topic pattern that exhausts its match budget is undetermined and fails closed with `Guardrails.Blocked` (audited as `pii-undetermined` / `topic-blocked`). The violation audit record is written to completion even when the request token is already cancelled, because the rejection is decided before the write. Streaming output filtering is code-owned **buffered** mode. Audit JSONL + `GET /api/guardrails/audit` keeps the existing `ApiResponse<GuardrailAuditRecord[]>` body and accepts `from`, `to`, `stage`, `violationType`, `sessionId`, `limit`, and optional `cursor`. Its default/max page, newest-first snapshot semantics, `X-Arcanum-Next-Cursor` continuation, bounded reverse scan, query binding, and **400** `Validation.InvalidQuery` restart contract match `/api/audit`. Only redacted matched spans appear in logs/errors.

### 8.28 Covenant public contract (mutation and inspection routed)

The request and response shapes the dedicated Covenant management surfaces use are frozen, and the table below is the whole of them; which of those shapes has a route behind it is what this paragraph names, and no count of them is kept here. **Registered, mutation:** `POST /api/memory/covenant/set/prepare`, `POST /api/memory/covenant/retire/prepare`, `POST /api/memory/covenant/correct/prepare`, `POST /api/memory/covenant/curate/prepare`, `PUT /api/memory/covenant`, `POST /api/memory/covenant/retire`, `POST /api/memory/covenant/correct`, `POST /api/memory/covenant/curate`, the entry erase pair of §8.35, `POST /api/memory/covenant/erase/prepare` and `POST /api/memory/covenant/erase`, and the §8.35 release, `POST /api/memory/covenant/release`. **Registered, inspection:** `POST /api/memory/covenant/list`, `/query`, `/detail`, `/versions`, `/sources`, `/explain` — every one a `POST` with a typed body, so no scope selection, Campaign identity, key, query text, or cursor ever enters a URL. `/query` compiles operator text through the Covenant query compiler, uses the accelerator or its bounded canonical fallback, and returns the same content-free `CovenantPageDto` heads and authenticated continuation model as the other catalogs. Repair, rebuild, Campaign path, and Session binding remain unregistered. The activated `/api/data` Covenant reset/factory-erasure lifecycle in §8.20 registers none of them. This section remains documented because four surfaces build against these shapes, and a contract that four of them each invent separately is four contracts.

> **Boundary status.** The authenticated boundary these routes sit behind is in place — see [§8.29](#829-x-arcanum-context-policy-and-the-covenant-pre-binding-boundary) — and `MemoryStatusDto` has its content-free `covenant` block. The eight set, retire, correct and curate routes declare `CovenantManage` operator authority, and the two erase routes `LifecycleManage`, so the pre-binding middleware refuses an unauthorized request before a single body byte is bound; each of the eight hands its lease to `CovenantProtectedJsonResult<T>`, which revalidates before the first byte and emits the protected header tuple, and the erase pair follows §8.35. Every prepare route takes the **installation** read capability rather than a scoped lease: a Global mutation's effect reaches every Campaign, and making the capability depend on a field in the body would be conditional authority that ends up wrong in one branch. The six mapped inspection routes each sit behind Covenant read authority and hand their lease to the same protected result; the four §8.20 lifecycle routes already require `LifecycleManage`. The maintenance surface is the one that is still absent: `ICovenantMaintenanceService` is registered in no container and reached by no route or command, and its two family-reinitialize methods refuse with `Covenant.ManualRecoveryRequired` pending the authenticated all-installation preflight and the token issuer a signed plan needs. A `search.guidance` of `RebuildRequired` therefore names a state, not a verb any caller can invoke. All six mapped inspection routes declare `ProtectedRead` authority, so the same middleware refuses an unauthorized read before its body is bound; each takes the lease its own body implies — a scoped read lease when the request names one Campaign, the installation read capability for an all-scopes request, because an all-scopes read crosses every Campaign and a scoped lease does not cover that — and hands it to `CovenantProtectedJsonResult<T>` on the same terms the mutation routes do. `/explain` is the exception: the service detaches its own lease, so the handler transfers what it is handed rather than acquiring anything. The four §8.20 lifecycle routes already require `LifecycleManage`.
>
> **Backup and restore status.** Backup, restore, and selective Session transfer are local operations and add no route here. The import side is covered by `IProtectedArtifactTransferStore`, which refuses any Covenant-derived source outright ([DESIGN §10.19.5](Arcanum.DESIGN.md#10195-selective-transfer-and-the-two-ports-it-had-to-build-first)).
>
> **Export status.** The export side is covered too. `GET /api/sessions/{id}/export` returns **403** `Covenant.PlaintextExportRefused` before a single content byte when the Session carries any Covenant-derived artifact, and `POST /api/campaigns/{id}/export` reports typed `exclusions` counts for the Covenant memory and tainted artifacts it did not carry. Both hold one conditional Covenant read lease from before the export graph through the last response byte, and both emit the protected header tuple of [§8.29](#829-x-arcanum-context-policy-and-the-covenant-pre-binding-boundary) while that arm is active. With the feature off neither takes a lease and the Campaign `exclusions` field is absent; the Session route still runs its two content-free ledger reads, so a Session that carries labels or taint written while the feature was on stays refused, and a Session with no ledger rows exports exactly as it did ([DESIGN §10.19.11](Arcanum.DESIGN.md#101911-refusing-tainted-plaintext-export-and-reporting-what-a-campaign-export-left-behind)).

**Bodies, never query strings.** Campaign identities, Covenant keys, filters, search text, and cursors are body fields on every route above, including the read-only ones. A URL is the one part of a request that nothing redacts, and an access log keeps it forever.

**Search matching.** Search text is split into terms on whitespace, and every term must match: each is a **token prefix**, so `spor` finds an entry whose key or text holds the word `sport` and `ort` does not, because a term matches only where a word begins. Case does not matter, and the characters `.`, `_` and `-` belong to a word (`global.sport` is one word, which `global` and `global.sp` find and `sport` does not). A word is made of letters, digits and those three characters; every other character separates words, including the vowel signs and other combining marks of scripts such as Devanagari, so `ताब` finds `किताब` just as `ort` finds nothing in `sport`. The one exception is the Latin combining accents (U+0300 to U+0331), which stay inside the word they follow. Both execution modes the page's `executionMode` reports answer by this rule, the full-text index and the bounded canonical fallback, so a hit does not appear while the accelerator is behind and vanish once it catches up. Four differences remain: the full-text index removes diacritics and folds case by Unicode rules where the fallback compares ordinally and case-insensitively; the full-text index reads a term that contains a separator (`a,b`, or a word with a vowel sign inside it such as `किताब`) as the phrase `a b` where the fallback matches the term as written; the fallback classifies characters with the Unicode tables of the .NET runtime where the full-text index uses SQLite's, so a character that Unicode added or reclassified after SQLite's tables were built (a rare script or a recent symbol) can be a word character in one mode and a separator in the other; and the fallback examines at most 2,048 heads and reports `truncated` when it could not examine them all.

**Frozen request bounds.** Search text ≤ 512 UTF-8 bytes and ≤ 32 terms (`Validation.InvalidQuery`); authored content 1–2,048 UTF-8 bytes (`Covenant.InvalidContent`); keys match `[a-z0-9][a-z0-9._-]{0,127}` (`Covenant.InvalidKey`); cursors and tokens ≤ 4,096 encoded characters, checked before decoding (`Covenant.InvalidCursor`); apply-request digests are exactly 64 hexadecimal characters (`Validation.InvalidBody`). `limit` is **clamped** to 1–200 with a default of 50 rather than refused, and the clamped value is exposed as `EffectiveLimit`. Byte bounds are UTF-8 bytes, not characters.

**Erasure fingerprints on a set.** A write of a key's Confirmed content (`set`, and `correct`, which commits as one) re-creates that exact scoped key, so it releases any erasure fingerprint recorded for it (§8.35). The preflight's `effect.releasesErasureFingerprint` discloses it before the operator confirms, and the result's `releasedErasureFingerprint` reports what the commit did, in the mutation's own transaction. Both are trailing, optional and tri-state: `true` when a fingerprint is (or would be) deleted, which lets agents author the key in that scope again; `false` when there is nothing to release, which is also what a retirement and every replay report; and `null` when the installation holds Covenant fingerprints this host cannot check, because no erasure key is latched or the rows were recorded under another key, so nothing is released and the operator runs `memory erasure status`. The flag is not bound into the token, and an operator write is never refused over a fingerprint: a commit the kernel refuses rolls the release back with it.

**A malformed target hash is a malformed body.** A `correct` or `correct/prepare` whose `targetRenderedHash` is not a 64-character hexadecimal digest is **400** `Validation.InvalidBody`, not `Covenant.InvalidScope`: the hash is a body field and the request named no scope wrongly. A well-formed hash that is not the live head's is **409** `Covenant.StaleSnapshot`.

**Both revisions on the preflight.** `CovenantMutationPreflightDto` reports `currentLaneRevision` — read from the head, never echoed — beside `expectedLaneRevision`, which is the number the request carried. The commit compares exactly those two and refuses a mismatch with `Covenant.RevisionConflict`, so a preview that reported only the head described a write no caller could tell would fail: every line of it true, and the refusal arriving after the operator had approved it. A client shows the disagreement instead of the confirmation.

**Explicit scope, always.** `CovenantCursorScopeSelection` (`Global`, `Campaign`, `AllScopes`) has no default; an omitted value is `Covenant.InvalidScope`, so an installation-wide read is never the result of a missing field. `Global`/`AllScopes` must not carry `campaignId`; `Campaign` must. Detail carries `CovenantScope`, which has no all-scopes member at all, because the same key can exist in Global and in every Campaign. A `Set` carries no lane — Confirmed is the only lane an operator authors — and a Global Proposed retirement is `Covenant.InvalidScope`.

**Effective versus local state.** `CovenantHeadDto` reports `lifecycle` (local) and `shadow`/`materialization` (effective for the evaluated Campaign) separately. Both effective fields are `NotEvaluated` when the request supplied no `effectiveForCampaignId`, because the honest answer differs per Campaign; the evaluation Campaign is part of the filter digest a cursor binds.

**Detail is content-free by rule.** `CovenantDetailDto` carries `scope`, `campaignId`, `key`, `entryId`, the `confirmed` and `proposed` heads (`CovenantHeadDto`: version identity, lane revision, lifecycle, origin, authored and rendered hashes, byte cost, provenance count and digest, and timestamps, never the authored text), the key's dependency `keyEpoch`, `confirmedSources` and `proposedSources` (always `null`: provenance leaves are the `/sources` route's bounded read), and, as trailing members, `confirmedCuration` and `proposedCuration`. Each is a `CovenantCurationStateDto` (`isPinned`, `isMasked`, `revision`) for that lane in the requested scope, read at the key's binding epoch inside the same read transaction as the heads, so the heads and the curation describe one snapshot. A lane nobody curated reads `false`, `false`, `0`, the same state and revision a curation preflight reports, and a lane can be curated with no head: a Campaign mask over a Global key is curation in a Campaign that holds no entry for that key. A key with no entry in the scope answers **200** with a null `entryId` and null heads, and the curation members carry nothing an erasure could be read from: an erase removes the erased subject's curation, except a retained Campaign mask, which reads exactly as a mask recorded where no entry ever existed.

**Protected responses.** Every content-bearing Covenant read is written through `CovenantProtectedJsonResult<T>` or `CovenantProtectedStreamResult`: the operation lease is revalidated immediately before the first byte, the response carries the exact tuple in [§8.29](#829-x-arcanum-context-policy-and-the-covenant-pre-binding-boundary) with any `ETag` and `Last-Modified` removed, and the lease is released after serialization completes. A conditional revalidation of protected content is a 304 on data the installation may since have erased.

**Idempotency.** Covenant set and retirement use their canonical `mutationId` and the durable receipt ledger as the sole replay mechanism; a supplied HTTP `Idempotency-Key` has no semantic effect on these routes. Long-running Covenant operations bind a caller-generated `operationId` plus a stable `applyRequestDigest`: the same pair replays the durable operation, a different digest under the same id is `Security.IdempotencyConflict`, and neither depends on the process that issued the original **202** still being alive.

`MemorySearchScope.All` continues to exclude Covenant. Covenant content search, sources, and explain use the typed routes above and always require Covenant read authority, so no existing default `All` request silently gains privilege.

### 8.29 `X-Arcanum-Context-Policy` and the Covenant pre-binding boundary

The authenticated boundary every dedicated Covenant management route sits behind applies today to every `/api` and `/v1` route, including the existing `/api/data` Covenant reset and factory lifecycle. The mutation and inspection routes of §8.28 are registered behind it, including protected free-text query; repair, rebuild, Campaign path, and Session binding are not registered at all.

**Decision order.** API-key authentication → Grimoire request admission (§8.31) → installation-reset recovery admission → `X-Arcanum-Context-Policy` validation → Covenant authority issuance → body-size enforcement → source-generated binding. Everything before "body-size enforcement" happens with **zero bytes of the request body read**. Authentication is strictly first: a wrong key presented with a malformed policy header returns **401**, never 400, because a 400 would tell an unauthenticated caller that they reached a real route and that only their header spelling was wrong.

**The header.**

| Sent | Result |
|---|---|
| absent | `Default` — durable context may be injected |
| exactly `none` (one header, lowercase ASCII) | `None` — durable context is suppressed for this request; the server echoes `X-Arcanum-Context-Policy: none` |
| `NONE`, `None`, ` none`, `none `, `""`, `none,none`, any other value | **400** `Covenant.InvalidScope`, before binding |
| the header repeated | **400** `Covenant.InvalidScope` — refused, never merged |
| any value on a route that cannot inject Covenant content | **400** `Covenant.InvalidScope` |

Repetition is refused rather than merged because every merge rule — first wins, last wins, comma-join — is a guess about which of two disagreeing senders meant it. A route that cannot inject context refuses the header rather than ignoring it, because a caller that sent `none` to a route that silently discarded it believes it suppressed content it in fact sent. `X-Arcanum-Context-Policy` is in the CORS exposed-header set so a browser client can read back the decision instead of assuming it.

**Idempotency.** The parsed policy is part of an `Idempotency-Key` request's fingerprint (DESIGN §11.17): the same key and body sent once without the header and once with `none` is **409** `Security.IdempotencyConflict`, never a replay of the first answer, because the first answer may carry durable memory the retry asked to exclude (or lack memory the retry asked for). The fingerprint carries the policy for every request, the default included, so a claim recorded before this was folded in reads as a conflict across an upgrade rather than as a replay.

Routes that accept the header today: `PostIntelligencePing`, `PostIntelligencePingStream`, `PostIntelligenceContextInspect`, `TestPrompt`, `Prompt_Execute`, `Prompt_ExecuteStream`, `Spell_Execute`, `Spell_ExecuteStream`, `Spell_Cast`. Every one of those nine builds its invocation context from a resolved Campaign, which is what makes the header mean something on it, and `CovenantContextRouteInventoryTests` fails in both directions when the set changes. `PostOpenAiChatCompletions` accepted the header until it was withdrawn: both of its handlers build a stateless context with no Campaign, so the context provider answers `Absent(NoCampaign)` before reading any Covenant state and nothing was ever going to be injected there. It now refuses the header under the row above, which is the honest answer — a caller that sent `none` to it was being told it had suppressed something.

**The protected response tuple.** Every protected success *and* failure emits exactly:

```text
Cache-Control: no-store, private
Pragma: no-cache
Expires: 0
```

with `ETag` and `Last-Modified` removed. `private` survives intermediaries that treat an unqualified `no-store` as advisory; `Pragma` and `Expires` cover HTTP/1.0-era caches that ignore `Cache-Control`. It is applied on response start, so it also covers framework-generated refusals no handler wrote. Streaming responses keep their `Cache-Control: no-cache` default when they are *not* protected and are never downgraded when they are — headers cannot be corrected after the first byte.

**Authority.** A route declares exactly one `CovenantAuthorityRequirement`; the boundary issues a context bound to it and to the current clean authority epoch, and an endpoint filter rechecks — never reissues — that epoch after binding. A missing context is **403** `Covenant.ForbiddenAuthority`; an epoch that moved (host-tools taint, key rotation) is **503** `Covenant.OperatorAuthorityUnavailable`. `ProtectedRead` cannot be declared as an operator requirement, so a context minted for an inspection page can never authorize a mutation.

### 8.30 Saga curation (`/api/memory/saga/`)

Six routes over one Saga memory at a time, mapped onto the same authenticated `/api` group as everything else in this chapter and deliberately not onto `/v1`, which maps its own routes and knows nothing about Saga curation. They sit beside the Covenant's curation surface (§8.28) and the Lexicon's delete rather than under `/api/saga`: `/api/saga` is the store's own read-and-delete surface and answers what is in there, while these answer what one memory is and what the operator has decided about it (DESIGN §21.13).

The detail route answers `ApiResponse<SagaMemoryDetail>`; the five write routes answer `ApiResponse<SagaCurationResult>`, which carries the outcome beside the memory the call left behind. That extra field is load-bearing, because three outcomes write nothing and are still successes.

**`eligibility` is written as its name.** `SagaRetrievalEligibility` is `Eligible`, `Retired`, `OwnershipUnresolved`, or `EmbeddingMissing`. It was previously written as its number (`1` to `4`, in that order); it is now written as its name (`"eligibility":"Retired"`) on `GET /api/memory/saga/{id}`, inside every write route's `detail`, and on the Saga review items' current snapshot (§8.34). That changes the shape of `arcanum memory saga show --json`, of the Saga curation verbs' `--json`, and of `arcanum memory saga review list --json` the same way: a client that matched the number matches the name instead. No request body carries this value.

**One classifier, under the policy retrieval runs.** Eligibility is decided in one place for the detail route, the review queue, and `POST /api/memory/search` (§1): retired first, then unresolved ownership, then a missing embedding. Unresolved ownership is a rung only while Campaign scoping is on (`Arcanum:Features:CampaignScopedMemory`). With it off, a turn ranks every embedded memory whoever owns it, so a memory whose owning Session's binding never resolved reads `Eligible` (or `EmbeddingMissing`), and `GET /api/memory/explain` counts it the same way. With it on, that memory reads `OwnershipUnresolved` on the detail route and in the review queue; search and explain, which narrow by the ownership a turn ranks by, neither return it nor count it.

**`Saga.EmbeddingUnavailable` also covers a wrong-width vector.** `correct` and `reinstate` embed before the store is called, and a provider that answers a vector whose length is not the clamped `Arcanum:Integrations:Embeddings:Dimensions` (a model swapped without `embeddings reset`, or a provider that ignores the requested width) is refused with **503** `Saga.EmbeddingUnavailable`, whose message names the two widths, rather than reaching the store's dimension guard and surfacing as an unhandled **500**. **A cancelled request does not undo the verb.** The projection the response carries is composed after the store has committed, on `CancellationToken.None`, so a caller that disconnects between the commit and the read still gets (or, once gone, would have got) the outcome the store reported, never a cancellation that says a durable change did not happen.

**Three successes write nothing, and each says which it was.** Retiring a memory that is already retired, reinstating one that is not retired, and correcting one to the text it already holds all answer **200** with the outcome kind that names what happened — the operator asked for a state and the memory is in it. Only correction meets `Saga.AlreadyRetired`, and only because a retired memory is reinstated before it is corrected rather than corrected in place; that check runs before any content comparison, so it is the answer whatever text the correction carried. `ArcanumErrorMapper` owns the status codes and `ISagaCurationService` owns which outcomes are errors, per verb; neither decision is restated at the route.

**A correction can release an erasure fingerprint.** `SagaCurationResult` carries a trailing optional `releasedErasureFingerprint`. A correction whose new content is content the operator erased in the memory's own scope makes that identity live again and deletes its fingerprint in the same transaction, so extraction may write that content there again: `true`. On a host-tools-tainted installation, which issues no release authority, the correction still lands but releases nothing and reports `false` (§8.34). `false` means there was nothing to release, and every other verb and outcome reports it. `null` means the store holds Saga fingerprints this host could not check, because no erasure key is latched, the rows were recorded under another key, or the memory's stored scope names no identity a fingerprint can describe; the correction still succeeds and the operator runs `memory erasure status`. A correction is never refused over a fingerprint (§8.35).

**`expectedContentHash` is proof, not a courtesy.** It is compared inside the write transaction, against the same digest function `SagaMemoryDetail.ContentHash` publishes, so a caller quotes a value the host computed rather than reproducing the function. Pin and unpin take no hash and no body at all: a pin is not a statement about what a memory says, and requiring proof of the text would make pinning fail after an unrelated correction.

Bodies are read through `ApiRequestJson` rather than as bound parameters, so the route itself answers malformed JSON and a wrong media type with the envelope and a code (§8.1). A bound-body route is answered the same way by the host's exception handler (§8.1), so the empty **400** and **415** minimal-API binding writes no longer reach a client on either read path. A body that never reached the curation service is refused as `Validation.InvalidBody`, which names the envelope rather than the verb: none of these routes can report a memory, an outcome, or a store from a body it could not read.

### 8.31 Grimoire request admission and the maintenance `503`

An installation can take its own database offline — a Covenant erasure, a factory reset — and for the length of that transformation nothing ordinary may hold the Grimoire open. This section is what a caller sees while that is true.

**Where it decides.** Immediately after the authentication stage and before installation-reset admission, Covenant pre-binding, body-size enforcement, binding, and the endpoint. It runs in both branches of the pre-binding gate, so an anonymous or peer-authenticated route under `/api` is decided by path authority exactly like an authenticated one. In the anonymous branch the recovery-mode 404-hide still decides first: a route that must stay indistinguishably unavailable while a factory reset is recovering cannot begin announcing that this host exists and its database is busy. "After authentication" means after the authentication *stage*, not after a successful key check: a wrong key is still **401**, never **503**, because a **503** would confirm to an unauthenticated caller that they reached a real route.

**What it selects.** Whole path segments, case-insensitively, under `/api` and `/v1` — never API-key metadata. That is the entire exclusion rule and it has no list to drift: `/metrics` is outside both prefixes, `/apiary` is not inside `/api`, and `/v10` is not inside `/v1`. A request that matched no route this host mapped is left alone, so `404`, `405`, and `415` stay reachable without a key.

**What it exempts.** Exactly `GET /api/presence`, `GET /api/health`, and `POST /api/server/quit`. Presence is the bodyless local proof used before a client reads or sends a credential; closing it would force the launcher to choose between disclosing the key to an unverified listener and spawning a second host onto an occupied port. Health already answers a closed gate better than a refusal could — its probe reports an Unhealthy component naming only an exception type, inside the **503**-with-`IsSuccess: true` envelope §1 documents. Quit is the shutdown step of the factory-reset sequence and opens nothing. None is a way past the gate: health and quit are refused by the database itself if they touch it, while presence contains no database operation or state. The factory-reset route is deliberately **not** exempt — it is the request maintenance runs for, and it holds an admission lease so the transformation can release it from its own drain.

**What it answers.**

| Surface | Status | Body |
|---|---|---|
| `/api/**` | **503** | source-generated `ApiResponse<string>` with `IsSuccess: false` and code `Grimoire.MaintenanceUnavailable` |
| `/v1/**` | **503** | source-generated OpenAI error envelope with type `service_unavailable` and code `grimoire_maintenance` |

Both carry the same fixed sentence — "The Grimoire is temporarily unavailable while maintenance owns connection admission." — and nothing else. No path, owner, operation id, phase, generation, or native detail appears in the body or in any log line, and the refusal is never logged at `Error`: it is expected control flow, not a fault. Both refusals carry the `no-store, private` / `Pragma: no-cache` / `Expires: 0` tuple with `ETag` and `Last-Modified` removed, because a cached maintenance answer outlives the window that produced it. No `Retry-After` accompanies either: a transformation may compact a large catalog or park for manual recovery, and a delay a client treats as a promise and the host cannot keep is worse than none.

The same pair is written for a request that was already running when admission closed under it, so an operator sees one answer for one condition rather than two. That second answer is produced by the admission stage itself, wrapping the rest of the pipeline, rather than left to the framework's exception handling: that middleware clears cache headers through a response-start callback registered before any handler runs, and those callbacks run last-registered-first, so nothing downstream can put back the exact tuple above. Wrapping there also covers the surfaces admission deliberately does not gate — `/metrics` queries the database on every scrape, and would otherwise answer **500** and be logged at Error for the length of the window. A response whose first byte has already left is never rewritten, and the refusal is not reported as a fault when it cannot be written.

**What it guarantees.** Every matched, non-exempt `/api` or `/v1` request either owns an admission lease for the whole of its request scope — held past the pooled database context and past every response-completion writer — or receives the refusal above before any endpoint work happens, with **zero bytes of the request body read**. Both bodies serialize through explicit source-generated `JsonTypeInfo`, so neither adds a reflection path.

No route, wire DTO, CLI verb or option, configuration key, schema/DDL, or migration changed to deliver this.

### 8.32 Streaming routes in a maintenance window

§8.31 is what a request that has not started receives. This section is what a response that has
already started does, because a stream whose first byte has left cannot be given a `503`: its status
and headers are settled, and a half-written body cannot become an envelope. Every streaming route is
therefore classified, and the class decides what a maintenance window does to it.

| Route | Class | Grimoire authority | Framing |
|---|---|---|---|
| `GET /api/events/daemon` | quiesceable | none | SSE |
| `GET /api/events/mcp` | quiesceable | none | SSE |
| `GET /api/events/logs` | quiesceable | none | SSE |
| `GET /api/sessions/{id}/stream` | quiesceable | live | SSE |
| `GET /api/apprentices/{id}/chronicle` | quiesceable | live | SSE |
| `POST /api/intelligence/ping-stream` | billable drain | live | NDJSON |
| `POST /api/prompts/{id}/execute-stream` | billable drain | live | NDJSON |
| `POST /api/spells/{name}/execute-stream` | billable drain | live | NDJSON |
| `POST /api/web/research` | billable drain | live | NDJSON |
| `POST /v1/chat/completions` (`stream: true`) | billable drain | live | SSE |
| `GET /api/sessions/{id}/attachments/{attachmentId}/content` | finite drain | live | bytes |
| `GET /v1/files/{id}/content` | finite drain | live | bytes |
| The A2A JSON-RPC server surface | billable drain | live | package-owned SSE |

**The five quiesceable routes stop at a complete frame boundary.** The frame already being written is
finished, no further data frame or `: keep-alive` comment is written, the producer is cancelled and
observed, enumerators and scopes are disposed, and the body ends with the terminal `data: [DONE]`
frame. HTTP status stays **200**, because it left with the first byte. The two routes that replay
before going live stop between replayed frames as well: the session stream stops between Entries and
skips its `data: {"type":"live"}` sentinel, and the Chronicle stops between its plan, escalation, and
step-start frames. Both then skip their buffered drain. `/api/events/logs` writes no `: connected`
comment if the window began before it got there. Those per-route guards fall through to the shared
writer, so a stream that stopped early still ends on the one terminal frame the writer owns; the
frame-boundary behaviour itself is pinned at that writer, and driving each route's replay phase
against a live transition belongs to the full-host race coverage that closes the epic.

A client cannot distinguish this ending from any other deliberate one, and that is intentional:
`[DONE]` already means "the server ended this stream" on all five, so `arcanum watch` exits cleanly
instead of reporting a disconnect that did not happen. A reconnect attempt made while the window is
still open receives the §8.31 **503**.

**Every other stream is drained, never cut.** A billable stream has already spent money on the
caller's behalf by the time a transition begins, so cutting it would charge for an answer nobody
receives; a finite one ends on its own in bounded time and holds no producer to stop. Both hold an
ordinary request lease, which the transition waits out — so a transition begun while one is open can
still reach its work-drain timeout and refuse. That refusal is the intended answer rather than a
regression: nothing is erased, ordinary admission stays open, and the operator retries once the
stream has finished.

No route, request or response shape, media type, frame vocabulary, sentinel, CLI verb, configuration
key, or database schema changed to deliver this.

### 8.33 Lexicon curation (`/api/memory/lexicon/`)

The six curation POSTs require the normal API authentication and JSON request media type. They remain mapped with prompt-time Lexicon or ordinary Annals capture disabled. Responses use `ApiResponse<T>` with source-generated camelCase fields. The three Lexicon enums — `LexiconScopeKind`, `LexiconRetrievalEligibility`, and `LexiconCurationOutcomeKind` — accept recognized string names, never numeric spellings. Inherited Annals enums retain numeric JSON values: a format-2 assertion head contains `"operation":1` and `"contentHashFormat":2`, not symbolic strings such as `"Assert"` or `"LexiconStructuredSnapshot"`; those strings fail deserialization. Existing `GET /api/memory/lexicon/{name}` remains effective active lookup. `DELETE` remains an exact-scope delete, including retired rows. It records no erasure fingerprint, so extraction or an agent may write the name again; only `erase` (§8.35) suppresses and verifies. POST `show` is exact inspection: absence in a Campaign is 404 even when Global has the same name.

| `/api/memory/lexicon/show` | `LexiconShowRequest`: `name`, `scope` | `LexiconEntryDetail` |

```json

```

For Campaign scope use `{"kind":"Campaign","campaignId":"a nonempty Campaign GUID"}`. Global forbids a Campaign id; Campaign requires one. Names are trimmed and case-normalized by the server. Correction preserves the entry's id, name, normalized name, and scope. `LexiconEntryDetail` contains `entry`, `scope`, nullable `currentOrigin`, `lifecycle`, `eligibility` (`Eligible` or `Retired`), `curationGeneration`, `snapshotDigest`, `target`, `annalHistory`, and `historicalFactProvenance`. `entry` contains id/name/type/facts/updatedAt, current fact provenance and scope, and lifecycle/generation/eligibility fields. `lifecycle` contains nullable `retiredAtUtc` and `pinnedAtUtc`. Historical source records contain `annalVersionId`, `factOrdinal`, source Session/attachment identity, logical key, attachment version/content hash, materialization time, and source type; no superseded fact or per-fact hash is retained.

It binds `scope`, `normalizedName`, `entryId`, `curationGeneration`, `snapshotDigest`, `lifecycle`, `annalHead`, and `sensitivityLabel`. The server compares every field against one live write snapshot and independently verifies row/head/label consistency. Clients must not recompute or omit evidence. A successful mutation returns `{"outcome":"Applied","entry":{...}}` where `entry` is the resulting full `LexiconEntryDetail`. Outcomes are `Applied`, `Unchanged`, `AlreadyRetired`, `NotRetired`, `AlreadyPinned`, and `NotPinned`, all HTTP 200. The latter five write nothing. They still require a current exact target: retrying an already applied request with its predecessor target returns 409, not a successful replay.

The two evidence arms are explicit and presence-sensitive:

| Target arm | `isPresent: false` | `isPresent: true` |
|---|---|---|
| `annalHead` | All other fields null or omitted. | Requires `claimId`, `versionId`, positive `revision`, numeric `operation` (1 = Assert, 2 = Correct, 3 = Retire), numeric `contentHashFormat` (1 = LegacyStoreDigest, 2 = LexiconStructuredSnapshot), and a SHA-256 hex `contentHash` for Assert/Correct. ### 8.34 Exact-version memory review (`/api/memory/{store}/review/`)

Each durable memory store exposes exactly three authenticated static POSTs: `list`, `prepare`, and `apply`. Scope selectors, Campaign ids, Covenant lanes, observations, and cursors are typed body fields and never URL segments. Saga uses `SagaMemoryScopeKind` plus nullable `campaignId`; Lexicon uses `LexiconCurationScope`; Covenant uses `CovenantScope`, nullable `campaignId`, and one required `CovenantLane`. Global forbids a Campaign id, Campaign requires one, and Saga alone admits the exact `LegacyUnresolved` scope. Page and bulk lengths are refused outside 1–50 rather than clamped.

| Suffix | Store-specific request | Successful data |
|---|---|---|
| `list` | `*ReviewListRequest` with exact scope, `limit`, and optional authenticated `cursor` | `*ReviewPageDto` with current-head unreviewed items, durable marker, frozen upper frontier, and optional continuation |
| `prepare` | `*ReviewBulkPrepareRequest` with nonempty `requestId`, one `action`, and 1–50 store-specific decisions | `MemoryReviewBulkPlanDto` with the exact ordered targets and five-minute `preparedPlanToken` |
| `apply` | `*ReviewBulkApplyRequest` repeating the complete prepare request plus its `preparedPlanToken` | `MemoryReviewBulkResultDto`, including per-item outcomes, reviewed-through marker, and `replayed` |

The first list page freezes the exact queue frontier; its continuation and every observation token authenticate the store, canonical scope, marker generation/revision, lower and upper event frontiers, and exact event/version identity. Pages are newest first. A continuation from another store, scope, lane, marker generation, or request is invalid. Queue items report assertion origin, source, scope, and immutable version, plus a bounded current snapshot with the content and lifecycle needed to review it. Saga claim history and Lexicon Annals/fact-provenance histories stay on their exact `show` surfaces rather than multiplying a 50-item queue page by an unbounded nested history. A version superseded after observation is stale: every action, including `Confirm`, refuses it, and a refreshed queue presents the actionable current head instead.

Actions are `Confirm`, `Correct`, `Retire`, `Pin`, and `Unpin`. All decisions in a request share that one action and exact store/scope/lane. `Correct` requires replacement content for every item; all other actions forbid it. Preparation rejects duplicate, tampered, expired, unseen, wrong-scope, mixed-frontier, or non-current observations before issuing a plan. Apply revalidates the ordered request digest, marker state, exact versions, and authority inside the owning store's transaction. The complete batch commits or none does. A committed exact replay returns the durable result even after the process plan token expired; reuse of the request identity for a different decision set is **409**.

**Per-item outcomes are one closed set.** `MemoryReviewBulkItemResultDto.outcome` is, for every store, exactly one of `Confirmed`, `Corrected`, `Retired`, `Pinned` or `Unpinned` (the action did what it was asked), `Unchanged` (Saga and Lexicon: a correction carried the content already held), `NoChange` (Covenant: the write would change nothing), or `AlreadyRetired`, `AlreadyPinned` or `NotPinned` (the state was already as asked), always in this PascalCase spelling. `AutoAcknowledged` is the outcome a Lexicon receipt records for the replacement version a correction acknowledges in the same transaction; it never appears in a response. Earlier builds reported the Lexicon's applied outcomes in lowercase (`acknowledged`, `corrected`, `retired`, `pinned`, `unpinned`); a receipt persisted that way still replays and reports the closed spelling.

Each `MemoryReviewBulkItemResultDto` also carries a trailing optional `releasedErasureFingerprint`. A Saga or Covenant `Correct` writes its replacement as the operator, so when an erasure fingerprint is recorded for the replacement's content (Saga) or the item's key (Covenant) in the item's own scope it is deleted in the review's transaction and the item reports `true`; `null` means the store holds fingerprints this host could not check, so nothing was released and the operator runs `memory erasure status`. Every other action, every Lexicon item, and every item of a replay report `false`; the flag is not part of the durable decision receipt. Each `MemoryReviewBulkPlanItemDto` carries the matching trailing optional `releasesErasureFingerprint`, measured by `prepare` under the rule apply uses — the same identity, the key copied from the host's latch before the read, and for Saga the same release authority and the same no-change test — so the operator sees which items will release before approving: `true`, `false`, or `null` when the store holds fingerprints this host could not check. Every other action and every Lexicon item report `false`. It is a disclosure, not a promise bound into the plan token: an erase or release between prepare and apply changes what apply finds, and the result reports what apply did. Each item is measured on its own, so when two items of one Saga batch correct to the same erased content, both read `true` in the plan, but only the first releases; the second finds nothing left and reports `false`. The plan over-discloses there, never under.

**No release on a host-tools-tainted installation.** Lifting a fingerprint needs the `LifecycleManage` authority the §8.35 release routes require, and a host-tools-tainted installation issues no operator authority. So no path lifts a fingerprint there. A Covenant review `apply`, and a Covenant `set` or `correct`, already require Covenant management authority and are refused before their body is read (**503** `Covenant.OperatorAuthorityUnavailable`). A Saga review `Correct`, and a Saga correction (§8.30), run under ordinary API authority and still commit on a tainted installation, but they release nothing and report `releasedErasureFingerprint: false` (a Saga review plan reports `releasesErasureFingerprint: false` there too), so the erased content stays refused to extraction in its scope. Lexicon has no operator write that re-creates an erased entry.

`Confirm` is acknowledgment only: it records that the exact versions were reviewed and changes no content, lifecycle, scope, pin state, or Covenant lane. Mutation actions preserve the owning store's individual exact-version semantics, including successful already-satisfied/no-change outcomes. A correction that produces a replacement acknowledges both the observed predecessor and the replacement event from that same transaction; a no-change correction acknowledges only the observed version because no replacement exists. Durable markers advance only across a gap-free exact queue frontier; a newer decision cannot skip an older live event, while an event proven superseded can be crossed without falsely recording a confirmation.

Saga review uses ordinary API authority. Lexicon `list` and `prepare` take conditional protected-read authority and `apply` takes the exact conditional write authority when any selected entry is protected. Covenant `list` requires `ProtectedRead`; both bulk phases require `CovenantManage`, with prepare holding the matching read lease and apply the matching write lease. Protected results retain the no-store headers and pre-first-byte lease revalidation in §8.29.

Review token faults are **400** `MemoryReview.InvalidToken`; stale, unseen, or request-reuse conflicts are **409** (`MemoryReview.StaleObservation`, `MemoryReview.UnseenObservation`, `MemoryReview.RequestReuse`, or `Security.IdempotencyConflict`); durable review-integrity failures are **500** `MemoryReview.IntegrityFailure`. A Saga or Covenant `apply` whose transaction could not commit (a storage fault, or for Covenant a database still busy after the bounded retry) answers **500** `Saga.WriteFailed` or `Covenant.WriteFailed` with nothing written, the way Lexicon answers `Lexicon.WriteFailed`; a Covenant `apply` retries `SQLITE_BUSY` itself rather than surfacing the first one. Other store-specific mutation, authority, availability, and infrastructure failures retain their existing codes and statuses.

### 8.35 Selective erasure

Selective erasure removes one memory item for good and records a keyed erasure fingerprint, so the same content, name, or key is refused when extraction or an agent tries to write it again in that exact scope. Every store's erase is two authenticated static POSTs, `prepare` and apply, with typed bodies; nothing about the target enters a URL. Each route declares exactly one operator authority, is refused on a host-tools-tainted installation (**503** `Covenant.OperatorAuthorityUnavailable`), and answers every status with the protected tuple of §8.29: `Cache-Control: no-store, private`, `Pragma: no-cache`, `Expires: 0`, and no `ETag` or `Last-Modified`.

**Prepare.** The body names the exact target the store's `show` reported, plus a client-generated `mutationId`. Before any lease or snapshot the erasure key is obtained, and it is created only when no fingerprint exists yet. One read snapshot then measures the plan with the predicates apply deletes by, the external exposure, and the retained local copies. The response is `MemoryErasurePreflightDto`: the store, `mutationId`, the keyed `requestDigest` and `effectDigest` (lower-case hex; they bind identifiers, counts and flags, never content), the content-free `plan`, `external`, `retainedLocalCopies`, scope-boundary `notes`, `issuedAtUtc`, `expiresAtUtc`, and the `preflightToken`. The token lives five minutes and binds the request digest, the effect digest and, when a sensitivity label was measured, the dataset generation. Prepare writes nothing but, on a fresh installation, the key.

**Apply.** The body repeats the prepare body and adds `preflightToken`. Apply first looks the `mutationId` up among the erasure receipts. A receipt for the same request is a **replay**: the stored result comes back with `replayed: true` and the token is not verified against the plan, so a committed erase answers after its token expired or the host restarted. The body must still carry a non-empty `preflightToken` (any non-empty value replays): an absent or blank token is refused as an invalid body (**400** `Validation.InvalidBody`) before the receipt is consulted. A receipt for a different request is **409** `Security.IdempotencyConflict`. Otherwise the token must be valid and bind this request, or the answer is **400** `MemoryErasure.InvalidPreflight`. The erase then runs in one `BEGIN IMMEDIATE` transaction: it probes the receipt again, refuses a subject another mutation already erased, re-reads and compares the target, re-measures the plan and recomputes the effect digest (**409** `MemoryErasure.StalePlan` on any difference), deletes, records the fingerprint and the receipt with one subject per erased row, proves every planned row absent, and commits. After the commit it attempts a write-ahead-log `TRUNCATE` checkpoint and reports the result from the receipt alone. An erase that rolls back reports its error and no result. A labelled item takes its owner's write lease before the transaction; when the item is already gone, it takes none and the transaction answers as above, replaying a receipt or refusing with **410** or the store's not-found code.

**Result.** `MemoryErasureResultDto` carries `store`, `mutationId`, `replayed`, `effectDigest`, and `local`: `outcome` (`Verified`, or `RowsRemovedScrubPending` while any reason remains), `pendingReasons` (`WalCheckpointPending`, which a later checkpoint clears; `FullTextSecureDeleteUnverified` and `VectorIndexScrubUnverified`, which never clear), `walCheckpointAttempt` (`Truncated`, `Busy`, `Unavailable`, or `NotAttempted`), `erasedItemCount`, `removedRowCount` (the planned rows the transaction measured and then proved absent, rows removed by a cascade included, so it equals `plan.rowsToRemove` for the same erase), `removedLabelCount`, `removedRetirementSuppressionCount`, and `suppressionFingerprintRecorded`. It also carries `external` (`revocation: NotPerformed` and one evidence value per channel: `Known`, `ReceiptWindow`, `NotRecorded`, or `NotApplicable`), `retainedLocalCopies`, which are reported and never purged, and `notes`. No field carries content, a content hash, a provider name, or a disclosure count. `NotRecorded` means that no record exists, not that nothing was exposed: the Lexicon `InferenceProviderAuthorship` channel reads `NotRecorded` for a legacy entry and for an entry scribed with the Annals off, even when an agent wrote it, because no claim version records an agent origin. `ReceiptWindow` says only that a backup or provider-dispatch receipt falls at or after the item's earliest creation, compared at millisecond precision, and the Lexicon `EncryptedBackup` channel is unbounded: it is `ReceiptWindow` whenever any backup has completed, because an entry records no creation time. A replay of a receipt still pending only on the log retries the checkpoint, and the result reports `Verified` once it truncates.

| Status | Codes |
|---|---|
| **400** | `Validation.InvalidBody` for a malformed or incomplete body; `MemoryErasure.InvalidPreflight` for a missing, expired, tampered, or borrowed token |
| **403** | `Covenant.ForbiddenAuthority`, from a labelled item's lease and authority: its labels name more than one owner scope, a label lies outside the scope the held write lease covers, or the operator context was not issued for the route's requirement |

| **503** | `MemoryErasure.Unavailable` until the schema that records erasures is reached; `MemoryErasure.KeyUnavailable` when secure storage cannot supply the key; `Covenant.OperatorAuthorityUnavailable`; the Covenant gate's own refusal when a labelled item's lease cannot be taken |

#### Saga

| Route | Body | Refusals beyond the shared table |
|---|---|---|
| `POST /api/memory/saga/erase/prepare` | `SagaErasePrepareRequest`: `memoryId` (a GUID), `expectedContentHash` (the `contentHash` of `GET /api/memory/saga/{id}`), `expectedClaimVersionId` (the claim's `currentVersionId`, or null for a claimless memory), `mutationId` | **404** `Saga.NotFound`; **409** `Saga.StaleContent` when the content or the claim head differs |
| `POST /api/memory/saga/erase` | `SagaEraseRequest`: the same fields plus `preflightToken` | as prepare; **409** `MemoryErasure.StalePlan` when a claimless memory was corrected after prepare, even if the new hash is supplied |

Both routes require `SensitivityRetentionPurge`, the authority a labelled memory's purge needs. The erase removes the target and every **twin**: each memory whose content is byte-identical and whose scope and Campaign are the same. Content that differs in whitespace, line endings, or Unicode normalization form is a different memory. Twins are found by the Campaign in every spelling a writer has produced and checked against a count that compares the Campaign normalised; a twin stored in any other spelling, or a member whose id another row shares, refuses the erase with **500** `MemoryErasure.ErasureIncomplete` and removes nothing. For every erased memory the plan covers its row, its embedding, a plain vector mirror, its attachment provenance, and its Annals claim with every version, head, dependency, review event and review decision receipt. It also covers any sensitivity label, deleted under a write lease over the label's one owner scope, and the retirement-suppression pair for the content in that scope; the retirement key itself is kept. A legacy virtual vector mirror cannot be opened, so it is skipped and the receipt records `VectorIndexScrubUnverified`. Pinned and retired memories can be erased, and the plan reports `pinned`. `plan.rowsToRemove` counts every planned row once, `plan.labelsToRemove` and `plan.retirementSuppressionsToRemove` are counted apart, and `plan.lexicon` and `plan.covenant` are null. Exposure reports authorship and embedding `Known`, provider context `NotRecorded`, and encrypted backup as a receipt window from the earliest creation in the class. The preflight notes include `OtherScopesUnaffected`, plus `UnresolvedScopeStopsMatchingOnResolution` for a memory whose Session binding is unresolved; an apply reports `OtherScopesUnaffected`.

#### Lexicon

| Route | Body | Refusals beyond the shared table |
|---|---|---|
| `POST /api/memory/lexicon/erase/prepare` | `LexiconErasePrepareRequest`: `target` (the complete `target` of `POST /api/memory/lexicon/show`, exactly as returned), `mutationId` | **400** `Lexicon.InvalidCurationTarget` for an incomplete or malformed target; **400** `Lexicon.InvalidName` for a `daemon_state:` entry; **404** `Lexicon.NotFound`; **409** `Lexicon.StaleCurationTarget` when any field of the target differs from the live entry; **500** `Lexicon.CurationIntegrityFailed` when the entry's stored evidence is inconsistent; **503** `Covenant.Unavailable` when a labelled entry's dataset generation cannot be read |
| `POST /api/memory/lexicon/erase` | `LexiconEraseRequest`: the same fields plus `preflightToken` | as prepare; **409** `MemoryErasure.StalePlan` when what the erase would remove changed after prepare, including a Global entry of the same name appearing or going for a Campaign entry |

Both routes require `SensitivityRetentionPurge`, the authority a labelled entry's purge needs. A `daemon_state:` entry belongs to the Unseen Servant job that writes it and is refused with the message `Unseen Servant daemon_state entries are managed by their daemon job and cannot be erased.` Such an entry is never fingerprinted, so the erasure key's state never gates a write to one, and an operator who needs one gone uses `DELETE /api/memory/lexicon/{name}`, a plain delete with no receipt. The erase removes exactly one entry in exactly its scope: a Global entry and a Campaign entry of the same name are different subjects, and erasing one leaves the other. The plan covers the entry row, its current fact provenance, and its Annals claim with every version, head, dependency, review event, review decision receipt, and historical fact provenance; the entry's full-text rows go with the row. A sensitivity label is deleted under the write lease over the entry's own scope, taken before the transaction. The fingerprint names the entry's name, trimmed and case-normalized, in that exact scope, so a later scribe of that name in that scope by extraction or an agent is refused with `Lexicon.SuppressedNameRefused`, whatever spacing or case it uses; the same name in another scope is still recorded. Pinned and retired entries can be erased, and the plan reports `pinned`. `plan.erasedItemCount` is 1, `plan.retirementSuppressionsToRemove` is 0, `plan.covenant` is null, and `plan.lexicon.globalEntryResurfaces` is true when a Campaign entry is erased while a Global entry of the same name exists, which a Campaign turn will then see instead. The full-text index must read `secure-delete = 1` at the start of the transaction; an index found with it off is switched back on and merged with `optimize` before anything is deleted, and a setting that still does not read back as on is recorded as `FullTextSecureDeleteUnverified`. The absence proof covers the entry's full-text row as well as its table rows: an index that still holds the entry after its row is deleted refuses the erase with **500** `MemoryErasure.ErasureIncomplete`, and nothing is removed. Exposure reports authorship `Known` when any version of the entry's claim was asserted by an agent and `NotRecorded` otherwise, provider context `NotRecorded`, embedding `NotApplicable`, and encrypted backup as `ReceiptWindow` whenever any backup has completed, because an entry records no creation time. Prepare and apply both note `OtherScopesUnaffected`. `DELETE /api/memory/lexicon/{name}` is not an erase: it records no fingerprint (§8.33).

#### Covenant

| Route | Body | Refusals beyond the shared table |
|---|---|---|
| `POST /api/memory/covenant/erase/prepare` | `CovenantErasePrepareRequest`: `scope` (`Global` or `Campaign`), `campaignId` (exactly when the scope is `Campaign`), `key`, `entryId`, `confirmed` and `proposed` (each the lane head `POST /api/memory/covenant/detail` reported, as `versionId` and `laneRevision`, or null when the lane has no head), `mutationId` | **400** `Covenant.InvalidScope` for a Global body carrying `proposed` or a Campaign identity that does not match the scope; **400** `Covenant.InvalidKey`; **404** `Covenant.NotFound`; **409** `Covenant.RevisionConflict` when the entry's scope, Campaign or key, or either lane head, differs from the body; **409** `Covenant.StaleSnapshot` when a Campaign entry's Campaign is no longer registered; **503** `Covenant.Unavailable` when the installation read capability is refused, as it is while any closure is held |
| `POST /api/memory/covenant/erase` | `CovenantEraseRequest`: the same fields plus `preflightToken` | as prepare; **409** `Covenant.StaleSnapshot` when operator authority changed after prepare or while the scope drained; **409** `MemoryErasure.StalePlan` when the dataset generation, the key's epoch, the key-reclamation epoch, whether the key is reclaimed, or anything the effect digest binds changed after prepare, a pin or mask recorded since included; **403** `Covenant.ForbiddenAuthority` when operator authority changed between the start of the erase's transaction and its `COMMIT`, or when the erase would reclaim the key or erases a Global entry but the held closure does not cover the installation; **409** `Covenant.LifecycleConflict` when a Campaign entry's Campaign was deleted before apply asked for its closure, and **404** `Covenant.NotFound` when that Campaign was never registered; **503** `Covenant.Unavailable` when another operation already holds the scope, or the receipt probe's read lease is refused while a closure is held, which includes a concurrent apply of the same request: retried, it replays; **503** `Covenant.MaintenanceFailed` when the scope did not drain within its bound, or when a `COMMIT` failed and recorded nothing; **503** `Covenant.ManualRecoveryRequired` when a `COMMIT` failed and its outcome was not proved |

Both routes require `LifecycleManage`. The erase removes one whole entry: both lanes, every version with its review events and review decision receipts, its attachment provenance, its heads, its mutation receipts, its pending search-outbox deltas, its search documents, and the curation recorded for its scope and key, in every lane and key epoch. A Global entry and a Campaign entry of the same key are different entries, and erasing one leaves the other. The fingerprint names the key in exactly the erased scope, so a later agent proposal of that key in that scope is refused at staging with **403** `Covenant.ForbiddenAuthority` and the message `This Covenant key is managed by the operator in this scope.`, the text a pin also answers with, while the turn that tried it still saves its answer; operator sets are never refused. Erasing a Global entry leaves the key proposable inside Campaigns, and the notes say so. `plan.erasedItemCount` is 1, `plan.labelsToRemove` and `plan.retirementSuppressionsToRemove` are 0, `plan.lexicon` is null, and `plan.covenant` reports `confirmedVersions`, `proposedVersions`, `provenanceLeaves`, `mutationReceipts`, `curationRows`, `outboxRows`, `searchDocuments`, and the flags `reclaimsKey`, `retainsCampaignMask`, `globalConfirmedResurfaces` and `isPinned`, with `affectedCampaigns`: 1 for a Campaign entry and every registered Campaign for a Global one. `plan.pinned` and `isPinned` say whether either lane of the entry's scope and key is pinned at the key's current binding; pinned entries can be erased. `globalConfirmedResurfaces` is true when a live Campaign Confirmed entry is erased while a live Global Confirmed entry for the key exists and no Campaign mask is kept, so Campaign turns see the Global entry instead.

**Masks and reclamation.** A Campaign's mask of the key's Confirmed lane is the operator's policy about the Global key, not content of the erased entry, so while the key stays it is kept with its curation chain, and `retainsCampaignMask` reports it. When no other entry or head in any scope names the key, the erase **reclaims** it: every curation row for the key in every scope goes with the key's epoch row, and the installation's key-reclamation epoch advances by one. A later set of the same key starts a new incarnation that no earlier pin or mask binds. Because the key-reclamation epoch is installation-wide, a reclaiming erase makes every outstanding Covenant preflight stale, on every key: a set, retire, correct or curate commit answers **409** `Covenant.StaleSnapshot`, an erase apply answers **409** `MemoryErasure.StalePlan`, and each is prepared again.

**The drain and the closure.** Prepare holds the installation read capability through its protected response. Apply answers a committed `mutationId` from its receipt before any token is read, under a short read lease released before any closure is asked for, so a replay never closes a scope. An entry already gone takes no closure: one transaction answers it as a replay, **410**, or **404**. Otherwise apply takes the entry-erasure closure over the entry's Campaign, or over the whole installation for a Global entry or a reclaiming erase, and drains it: new work in that scope is refused while in-flight Covenant turns and leases finish, for at most 30 seconds, and an undrained scope fails the erase with **503** `Covenant.MaintenanceFailed` having changed nothing. That is not the whole time the closure is held: after the drain the erase still takes the SQLite write lock for its `BEGIN IMMEDIATE`, retrying on busy under a separate two-minute deadline that is checked between attempts, so under sustained write contention the scope can stay closed for up to about two minutes beyond the drain. An erase that cannot take the lock within that deadline fails, changes nothing, and reopens the scope as rolled back. A turn that starts while the closure is held runs without Covenant content rather than waiting, and any lease that needs installation coverage, an installation-wide read or another prepare included, fails fast during any closure rather than queuing behind it. The erase itself is one `BEGIN IMMEDIATE` transaction under entry-erasure authority, which re-proves the receipt, the subject, the dataset generation and both key epochs, both heads and the Campaign, recomputes the effect, deletes, appends one content-free absent delta per erased head so the search projection drops it, records the fingerprint and receipt, proves every planned row absent, and commits. The closure then completes with exactly one disposition: a commit reopens the scope as committed, a proven refusal reopens it as rolled back, and a `COMMIT` whose failure leaves its outcome unknown is settled by reading the receipt on a connection of its own: a receipt there reopens as committed and reports the erase; none reopens as rolled back and reports **503** `Covenant.MaintenanceFailed`, which a retry can clear. The read is made even when the rollback of the failed transaction itself fails, the likeliest shape of a commit that persisted, and a receipt there still reports the erase and reopens the scope as committed. Anything short of a proof keeps the scope closed until the host restarts and reports **503** `Covenant.ManualRecoveryRequired`: a read that cannot be made or fails in any way, or a failed rollback whose read finds no receipt of this request. A later retry answers from the receipt if the erase did commit. A cancelled request still completes its disposition. The write-ahead-log checkpoint runs only after the scope has reopened.

**Search, receipts and exposure.** The entry's search documents are deleted whenever the search accelerator exists, whatever `covenant_fts` reports; a full-text index that does not read `secure-delete = 1` is recorded as `FullTextSecureDeleteUnverified`. Mutation receipts written before the canonical schema named an entry on a `NoChange` outcome carry no key, so the erase also deletes every such receipt in the entry's scope, Campaign and lanes since the entry was created; a very late replay of another key's no-change mutation from that window then answers as stale rather than replaying. The absence proof covers the full-text index as well as the tables: an index that still holds a row for one of the entry's heads once its search documents are deleted refuses the erase with **500** `MemoryErasure.ErasureIncomplete`, and nothing is removed. `removedRowCount` is the measured plan, rows the versions' delete cascades included, and equals `plan.rowsToRemove`. Exposure reports authorship `Known` when any version of the entry was proposed by an agent and `NotRecorded` otherwise, provider context as a receipt window when a nonrevocable Covenant-derived provider dispatch is recorded since the entry was created and `NotRecorded` otherwise, embedding `NotApplicable`, and encrypted backup as a receipt window when any backup has completed since the entry was created. The notes are `OtherScopesUnaffected` and `CovenantDrainsInFlightTurns`, with `GlobalKeyStillProposableInCampaigns` first for a Global entry. A reclaiming erase omits `OtherScopesUnaffected`, because it removes the key's curation in every scope, and so does every replay, because a receipt does not record whether the key was reclaimed. The erase requires the canonical Covenant schema version that records erasures, and answers **503** `MemoryErasure.Unavailable` before any key is created until it is reached.

#### Release

| Route | Body | Refusals beyond the shared statuses below |
|---|---|---|
| `POST /api/memory/saga/release` | `SagaErasureReleaseRequest`: `scopeKind` (the numeric `SagaMemoryScopeKind` the memory's detail reports: 0 `Unclassified`, 1 `Global`, 2 `Campaign`, 3 `LegacyUnresolved`), `campaignId` (exactly when the scope is `Campaign`), `content` | **400** `Validation.InvalidBody` for an unrecognized scope, a Campaign pairing that does not match it, or empty content |
| `POST /api/memory/lexicon/release` | `LexiconErasureReleaseRequest`: `scope` (as `show` takes it), `name` | **400** `Lexicon.InvalidScope`; **400** `Lexicon.InvalidName` for a blank name |
| `POST /api/memory/covenant/release` | `CovenantErasureReleaseRequest`: `scope` (`Global` or `Campaign`), `campaignId` (exactly when the scope is `Campaign`), `key` | **400** `Covenant.InvalidScope`; **400** `Covenant.InvalidKey` for a key outside the lower-case grammar, which is refused rather than folded |

Release lifts an erasure fingerprint, so the content, name or key may be written again in that exact scope by extraction or an agent. It is the unsafe direction, so every release route requires `LifecycleManage`, whatever its store, answers with the protected tuple, and a missing body or member is **400** `Validation.InvalidBody`. Release takes no `mutationId` and is naturally idempotent: a second release of the same identity answers `NotFingerprinted`. It recomputes the fingerprint from the supplied scope and identity and deletes that row and nothing else. Saga content is tried exactly and with `Trim()` applied, and whichever were erased are deleted, so content read from a file with a trailing newline still releases; any other difference, a Unicode normalization form included, is a different identity and releases nothing. A Lexicon name is trimmed and case-folded the way the scribe chokepoint reads it. A Covenant key must already be well formed.

The result is `MemoryErasureReleaseResultDto`: `store`, `outcome` (`Released` or `NotFingerprinted`) and `releasedCount`, the fingerprints deleted (2 when both the exact and the trimmed Saga form had been erased). A store with no fingerprints answers `NotFingerprinted` without reading the credential store, so a release never creates the erasure key. Otherwise the key is read again, as every operator call reads it, before the transaction opens, and the deletes run under `BEGIN IMMEDIATE`.

| Status | Codes |
|---|---|
| **409** | `MemoryErasure.KeyLost`: the store holds fingerprints and the erasure key is gone, or nothing matched while the store holds fingerprints another key recorded. Nothing is released, and the operator runs `memory erasure status` |
| **503** | `MemoryErasure.KeyUnavailable` when the key could not be read; `MemoryErasure.Unavailable` until the schema that records erasures is reached; `Covenant.OperatorAuthorityUnavailable` |

Release keeps every receipt, so a later erase of the same identity is a new erasure with a receipt of its own. An operator write that re-creates an erased identity in its own scope, a Covenant `set` or `correct` and a Saga correction, single or by review, releases its fingerprint too, in its own transaction, and reports it (§8.28, §8.30, §8.34); Lexicon has no operator write that can re-create an erased entry.

#### Status, scrub and key reset

| Route | Body | Response |
|---|---|---|
| `GET /api/memory/erasure` | none | `MemoryErasureStatusDto` |
| `POST /api/memory/erasure/scrub` | none | `MemoryErasureScrubResultDto` |
| `POST /api/memory/erasure/reset-key/prepare` | none | `MemoryErasureKeyResetPreflightDto` |
| `POST /api/memory/erasure/reset-key` | `MemoryErasureKeyResetRequest`: `preflightToken` | `MemoryErasureKeyResetResultDto` |

These four belong to no one store. The status read declares no operator authority, because it returns only a key state and counts: authentication is enough, and it answers on a host-tools-tainted installation too. The scrub and both halves of the key reset require `LifecycleManage` and are refused on a host-tools-tainted installation with **503** `Covenant.OperatorAuthorityUnavailable`. All four answer with the protected tuple. Below the schema that records erasures there is no evidence: status reports zero counts, and the other three answer **503** `MemoryErasure.Unavailable`.

**Key states.** `keyStatus` is one of four values:
- `Absent`: no key item exists, and no fingerprint needs one. The first erase creates it.
- `Present`: the key is readable.
- `Lost`: fingerprints exist and the key item is gone, so nothing can verify them. Every automatic writer fails closed: Saga extraction defers its page before the model call, and the Lexicon scribe and agent Covenant proposals are refused with `MemoryErasure.KeyLost`. Operator writes still succeed but release nothing.
- `Unavailable`: the credential store could not answer, or the stored item is not a valid key.

**Counts.** `stores` always lists `Covenant`, `Saga` and `Lexicon`, in that order. Each entry carries `fingerprints`, `receipts`, and `unverifiable`: the fingerprints the current key did not record, which is every fingerprint when the key is lost. A row is unverifiable when a different key recorded it, as happens when a second test home overwrites the shared account. While the key is `Unavailable` nothing can be said about which rows it would verify, so `unverifiable` reads 0, meaning unknown. `pendingScrubReceipts` counts receipts still pending for any reason, whatever key wrote them. An erase is one fingerprint and one receipt, however many Saga twins it removed.

**The presence probe.** With no evidence rows, status only asks the credential store whether the key's item exists. It reads no secret, so it never prompts for keychain access, and it leaves the host's key state as it was. An item that exists cannot be told apart from a key that way, so status also consults the host's last read of the item, which costs no I/O. A malformed item reads `Present` until an erase prepare or a `reset-key` prepare reads it. From then on status reports `Unavailable` until the item is removed, and `reset-key` prepare is what names the remedy. The same holds for an item the host could not read. A probe that finds no item at all reports `Absent`, whatever the host read before. With rows, status reads the key again, as every operator call reads a key the host does not already hold, and publishes what it finds, so a transient failure an automatic writer latched clears. A key the host already holds is not read again, but status asks the credential store whether its item still exists, which reads no secret: while the item stands status reports `Present`, so a second test home that overwrites the shared account cannot change what this host holds, and once the item is deleted while the host runs status reports `Lost`, or `Absent` when only receipts remain, and an erase prepare is refused with **409** `MemoryErasure.KeyLost`, so no fingerprint is recorded under a key the operating system no longer holds. A probe that cannot answer reports `Unavailable` and leaves the host's key as it was, and a credential store with no such probe cannot be asked, so status keeps reporting `Present` until the host restarts and finds it lost.

**Scrub.** The scrub first reads which receipts are still pending on the write-ahead log. Only then does it retry the checkpoint once, on a dedicated connection with a quarter-second wait. Only a checkpoint that truncated clears `WalCheckpointPending`, and only on the receipts read before it ran; a receipt whose only reason was the log becomes `Verified`. `FullTextSecureDeleteUnverified` and `VectorIndexScrubUnverified` never clear. A busy or unavailable checkpoint changes nothing; run the scrub again once readers have finished. The result carries `walCheckpointAttempt` (`NotAttempted` when nothing was pending on the log, otherwise `Truncated`, `Busy` or `Unavailable`), `verified` (the receipts this call moved to `Verified`) and `stillPending` (the receipts still pending for any reason).

**Key reset, prepare.** Prepare reads the key again and measures each store's unverifiable fingerprints and receipts. The response carries `keyStatus` (`Present`, `Lost` or `Absent`), `stores` as status reports them, `issuedAtUtc`, `expiresAtUtc`, and a five-minute `preflightToken`. The token binds the key state and all six per-store counts. A key that cannot be read, or an item that is not a valid key, refuses prepare with **503** `MemoryErasure.KeyUnavailable`.

**Key reset, apply.** Apply runs three steps, then one checkpoint:
1. **Read the key**, outside any transaction. A key the store cannot read, or a malformed item, is **503** `MemoryErasure.KeyUnavailable`: nothing is discarded and no keychain item is written. A malformed item is never overwritten. If the store is locked or did not answer, unlock it and prepare and apply again. Only an item confirmed malformed is removed with the OS credential tool, and removing a key makes every erasure fingerprint unverifiable, so the reset that follows discards them and erased content could be learned again.
2. **Settle the key.** A present key is kept, whatever state the token was prepared in. A proven absence creates a new key, which is read back before use. A key is created only for a token prepared without one (`Lost` or `Absent`). A token prepared while a key was present is **409** `MemoryErasure.StalePlan`, and nothing is created. `keyCreated` is `true` only when this apply wrote the key: a key another caller wrote after the apply read the account is kept and reported as not created.
3. **Discard**, in one `BEGIN IMMEDIATE`. The evidence the current key cannot verify is measured again. If there is none, the reset succeeds with zero counts, so applying the same token twice is harmless. If any store's counts differ from the token's, the reset is **409** `MemoryErasure.StalePlan`, even when the totals still match. Otherwise every fingerprint and receipt the current key did not record is deleted, and the receipts' subjects go with them.

**The checkpoint.** A receipt still pending on the write-ahead log is the only record that its scrub is owed, so discarding one would leave the erased frames in the log with nothing left to retry them. When step 3 discarded such a receipt, apply runs one checked checkpoint after its commit, the same one the scrub runs, and logs the attempt (`Truncated`, `Busy` or `Unavailable`) without any content. The result does not carry it, a checkpoint that is busy or unavailable changes nothing and the log is truncated by the next one that finds no reader, and it never fails a reset that has already committed. A reset that discarded no pending receipt runs no checkpoint.

The token binds per-store counts, not row identities or a key. A `Lost` or `Absent` token applied after a key has appeared is not refused for that alone: step 2 keeps the key, and step 3 measures against it. If that key recorded every row, nothing is unverifiable and the reset succeeds with zero counts. If it recorded none and the counts still match, the reset discards them all; otherwise it is `StalePlan`. A step-3 `StalePlan` can follow a key that step 2 created. That key stays: status then reports `Present` with the rows still unverifiable, the writers stay refused as `MemoryErasure.KeyLost`, and a fresh prepare and apply finishes the reset.

The result is `MemoryErasureKeyResetResultDto`: `keyStatus` (`Present`), `fingerprintsDiscarded`, `receiptsDiscarded` and `keyCreated`. A reset takes no `mutationId` and writes no receipt.

The key is settled before any row is touched, because the keychain is never read or written inside a transaction. A crash between the two steps leaves a present key and rows it cannot verify: status reports them as unverifiable, the writers stay refused, and a fresh prepare and apply finishes. The token does not survive the crash, because the key that signs it lives only in the host process, so applying it afterwards is **400** `MemoryErasure.InvalidPreflight`. The discarded erasures are gone for good: extraction, the scribe and agent proposals may write that content, name or key again. The CLI confirms before it applies.

| Status | Codes |
|---|---|
| **400** | `Validation.InvalidBody` for a reset body without a `preflightToken`; `MemoryErasure.InvalidPreflight` for an undecodable, expired, tampered or borrowed token |
| **409** | `MemoryErasure.StalePlan`: the key is absent at apply although the token was prepared while one was present, or a store's unverifiable counts differ from the token's |
| **503** | `MemoryErasure.KeyUnavailable` when the key cannot be read or the item is malformed; `MemoryErasure.Unavailable` until the schema that records erasures is reached; `Covenant.OperatorAuthorityUnavailable` |

*End of API reference.*
