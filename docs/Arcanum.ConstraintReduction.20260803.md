# Arcanum constraint reduction report — 2026-08-03

This report is the human-readable view of [`Arcanum.ConstraintInventory.json`](Arcanum.ConstraintInventory.json), the canonical machine-reviewable inventory for GitHub issue #55. It covers Arcanum and Compendium only. Forge is deliberately excluded.

## Outcome

Arcanum's default is now coding-harness behavior: keep working while evidence changes, stop only for completion, caller or host cancellation, an explicit operator token/cost/security policy, the provider/model's real request or context boundary, a required safety/integrity boundary, a catastrophic-resource safeguard, or deterministic repeated no-progress.

The change removes or redesigns fixed turn/tool/correction counts, total coding-command and human-prompt deadlines, silent command-output and assistant-Markdown truncation, small research hop/source ceilings, delegated-child turn/depth/file counters, SQLite retry totals, durable-operation recovery scan totals, workspace/Eye/Spell traversal totals, Spell dependency count/depth totals, selector/result/TRX totals, inline attachment file counts, attachment reference/version counts, workspace-patch elapsed/count/aggregate-input/result totals, the managed-vector 50,000-row scan total, temporary-capacity Apprentice and A2A rejection, campaign registry totals and first-page-only projection, Command Center silent list truncation, total session-entry/fork-depth and per-turn pin-materialization count ceilings, batch request-count, full-record buffering, artifact recount, whole-catalog metadata load, queue-pickup load, and age ceilings, workspace-search filter counts, workspace-check restore graph/input/XML totals, Spell one-response catalog materialization, the lore client's 10,000-page total, encryption diagnostics' 512-file scan total, the session-search 2,048-ID intermediate, audit whole-file/offset traversal, and public Compendium controls for incidental retries, timeouts, queues, batches, and checkpoint counts. The pre-existing durable-pin admission setting is unchanged outside issue #55 scope.

## Retained boundaries

Authentication, secret handling, workspace containment, link/device/FIFO defenses, SSRF/DNS/redirect protections, Wards, Sanctum, edition gates, strict protocol framing, cryptographic/database integrity, provider/model request facts, explicit budgets and retention, single-allocation/frame protections, concurrency admission, bounded safe rendering, and post-cancellation cleanup remain mandatory.

Notable retained one-slice boundaries include the batch 64 MiB per-record materialization maximum and 1-100 metadata response page, the Spell 50-item page and 65,536-byte continuation-name frame, the audit 1,000-record snapshot page with 64 KiB reverse-scan blocks, and SQLite backup's cancellable 64-page steps under a renewable durable lease. None is a total history, catalog, database-size, or operation-duration ceiling.

Idempotency executes a side-effecting endpoint only after durable ownership is exact: one local-orphan transition may be recovered and rechecked, then ambiguous ownership fails closed. Workspace-patch staging and recovery likewise try at most 16 fresh contained GUID artifact names and never reuse an occupied or unverifiable path.

A retained-boundary error must identify the owner, measured value and limit when safe, whether state was saved/checkpointed, and the exact retrieval, continuation, configuration, or recovery action. Page and batch sizes may bound one slice only; iteration must continue automatically or return an explicit continuation.
