# Counterfactual Memory Evaluation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver #106's controlled, exact-version memory comparisons and content-free evidence to Arcanum, then qualify and integrate the exact candidate into `memory-enhancement` and complete #106.

**Architecture:** A request-authorized, stateless Proving Grounds runner freezes one memory/workload/provider plan and derives paired zero-tool prompts. **Tech Stack:** C#/.NET 10 target with latest stable SDK (currently installed 10.0.402), Native AOT, source-generated System.Text.Json, parameterized SQLite/SQLCipher, xUnit, existing operation/disclosure/accounting primitives.

**Spec:** [Approved #106 specification](../specs/2026-10-18-counterfactual-memory-evaluation.md). Read it before any task. The operator approved the direction and written specification on 2026-10-18; this implementation plan is approved and execution uses its recommended subagent-driven method.

## Review Focus

- Operator-corrected Saga has null version-authoring Session but a retained canonical owner Session; Session deletion must erase dependent evidence (Tasks 2 and 4).
- A treatment gains checks while regressing another, or merely keeps the same total score; the classifier must expose the regression and refuse a Benefit claim (Task 1).
- Public operation state becomes Cancelling while heartbeat renewal still succeeds; active provider I/O must cancel and no next send may start (Task 6).

- Any source/dependency/report is erased between preparation, an acknowledged send, finalization and recovery; neither replay nor recovery may recreate it (Tasks 3, 4 and 6).
