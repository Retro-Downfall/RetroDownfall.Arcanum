## Exact source partitions and generations

A transformation partition is exactly Global or exactly one canonical Campaign, rather than ordinary recall's union of Global and Campaign. Unclassified, legacy-unresolved, mismatched subject/version scope, missing claims, invalid labels and stale heads fail closed or remain explicitly pending. A Campaign source also binds its owner availability, canonical binding/path policy and root revision/digest.

Clean and Covenant-derived discovery use separate governed partitions. No protected text, token, summary, vector or snippet enters ordinary Saga/shared search indexes. Metadata and label evidence are checked before reading plaintext. Protected rows and derived hierarchy artifacts require a live exact-scope lease matching the authenticated maintenance capability: GlobalOnly request/binding and Global lease for Global debt, or the exact Campaign request/binding and Campaign lease for Campaign debt. Global owner/path fields must remain absent; neither scope grants access to another partition.

Persist a monotonic source insertion sequence and mutation epoch for each Saga subject, alongside the existing dataset and owner generations. Backfill existing source identities in bounded schema-evolution batches. A generation freezes its insertion high-watermark; enumerate its included identities in stable MemoryId order, independent of insertion/storage order. Projection-only suppression writes do not advance this source epoch. One generation freezes an exact source manifest/high-watermark and stores leaf coordinates: MemoryId, ClaimId, VersionId, content format/hash, embedding binding, lifecycle and sensitivity/provenance evidence. New sources above the insertion high-watermark create future debt and do not cancel the current generation. A change/deletion of an included source, including head/content/lifecycle/embedding/label/provenance or canonical ownership changes, invalidates the current generation before another dispatch. The next generation starts enumeration at the beginning under its new high-watermark, so random-ID insertion behind an old cursor cannot be skipped. Reusable committed nodes still require exact membership/recipe/source proof under the new generation.

All corpus enumeration uses stable keyset pages and bounded allocations. The initial source-page bound is 128; a provider input page is at most 32,768 UTF-8 bytes; a generated summary is at most 8,192 UTF-8 bytes; a transformation contains at most the existing 16 exact targets. Oversized or malformed items are explicitly deferred/refused without silently dropping them behind a cursor. These are page bounds, not a cap on total memories, Sessions or productive maintenance lifetime. Capture the host boot identity and monotonic Long Rest configuration epoch as well as the accepted value digest. Increment the epoch on every relevant notification, including Long Rest/Covenant gate and provider/model transitions; require identical boot/epoch/digest before dispatch and publication, so off-to-on and A-to-B-to-A changes cannot revive an old attempt.

## Hybrid discovery

1. Exact hash equality supplies the deterministic, provider-free duplicate lane.
2. Saga-specific FTS5 supplies lexical candidates. Governed clean and protected indexes remain separate and generation-owned, with exact metadata eligibility applied before deterministic BM25/top-K ordering. Escape generated query tokens and use fixed token/result bounds. No generic search port can reach the protected index. Enable FTS5 secure delete and make protection transitions atomically purge affected clean-index entries and invalidate their generation before a protected label becomes visible. Include both indexes and residual-token cleanup in common erasure/reset/restore ownership.
3. Managed cosine over exact source-of-truth embeddings supplies semantic candidates, filtering before top-K. Native accelerator availability cannot widen scope or change eligibility. Reject malformed/nonfinite or mismatched vectors; stable identity resolves ties.
4. A Saga-specific RAPTOR-style hierarchy supplies cross-page candidates. Reuse managed deterministic clustering and provenance conventions, rather than reading unrelated Tapestry summaries. Build leaves in pages, cluster bounded child groups, summarize and embed them, then recursively cluster summaries up to a code-owned depth bound. Lower-level clustering uses stable bounded source-page partitions, rather than claiming whole-corpus K-Means. Upper levels group summaries from different source pages in stable order and perform real recursive clustering/summarization; every frozen leaf appears exactly once. A level may retain a bounded-work forest when the depth bound is reached. Persist exact child edges and leaf provenance, so a summary match expands only to eligible exact Saga versions. The initial recipe uses up to 16 children per fold and six levels. Bound summary-to-leaf traversal and candidate expansion to the same declared candidate budget, with stable exact-leaf tie breaks. Prove a hierarchical-only hit crossing source pages. No whole-corpus in-memory allocation is required.

Commit each completed node, embedding, child manifest and hierarchy cursor together. Publish a generation atomically only when its source epoch/owner/dataset facts are still valid. Reuse committed nodes by exact membership/recipe/model binding after restart. Never publish a partial or stale hierarchy as complete.

The initial code-owned bounds are 16 lexical query tokens of at most 128 UTF-8 bytes each, eight lexical hits, eight vector hits with minimum cosine 0.92, eight hierarchy summary hits, at most 32 expanded exact leaves per selected hierarchy node, a 128-node traversal frontier and 32 merged neighbors per anchor. Provider groups retain the existing 16-target ceiling. Use streaming bounded ranking heaps and stable identity tie breaks, refusing malformed/nonfinite vectors and overflow without a silent cursor skip. Merge lanes in exact-hash, lexical, vector, hierarchy order with duplicate elimination. Similarity is discovery evidence, not canonical mutation authority.

## Semantic adjudication and canonical application

Exact duplicate groups may call the existing deterministic kernel directly. Other candidate groups use a closed structured provider response declaring equivalent observations, an exact supersession survivor, or no change. The response can name only the frozen input versions; it cannot introduce content, target an unrelated row or supply an arbitrary mutation.

Persist accepted adjudication bound to exact input versions, content/embedding hashes, lifecycle/dependency/sensitivity snapshot identity, recipe/model/provider binding and provider/disclosure evidence immutably. Application reloads current exact heads and decision-relevant state in the owning transaction; changed input refuses publication and leaves fresh debt eligible. Subsequent application replays this recorded evidence through deterministic policy, rather than asking the model to make the same canonical decision again. Unchanged committed work produces no further model calls or canonical writes.

Keep pins, retirement, origin, exact Campaign ownership, bitemporal validity, dependencies and immutable source history. Existing #93 conservative checks continue to govern ordinary transformations. Protected application is a separate authority-bearing store path and versioned policy extension: prove one permitted sensitivity partition, retain all original labels/provenance, validate authority and exact inputs in the same transaction, and bind the protected evidence into its receipt identity. Never make a protected snapshot look clean to bypass policy. The first protected policy supports only targets in one exact authorized Global or Campaign scope with identical, nonempty sensitivity provenance/digests; verify unambiguous canonical Saga labels, their artifact/owner/revision bindings and both label-content and Annals-content digests. A historical clean Annals version with a current protected Saga label remains protected. Exact input label digests and the partition digest enter the versioned canonical identity. Mixed/unproved protected groups produce a typed refusal or no-change result. Extend the suppression insertion trigger with an evidence-backed protected arm while preserving the clean arm; receipt verification selects the recorded policy version. Existing version-1 receipts/digest vectors keep their exact representation and replay behavior.

## Request-bound protected maintenance

Create a nonserializable, single-use root maintenance capability from the server-established invocation, executable pending Session turn claim, exact canonical Global or Campaign context, live matching Covenant turn lease and frozen configuration digest/epoch. Consume it once to drive one declared maintenance operation. Within that still-live request, derive a single-use child dispatch capability for each exact bounded source vector, frozen payload/destination and physical ordinal. Consume each child once for one physical dispatch. A retry/correction needs a fresh child and receipt; no child survives the request, claim or root lease. Root/child reuse is stale and neither capability is serializable.

Generalize the existing authenticated claim-preparation seam so Long Rest can run while Campaign Rollups is disabled. Keep rollup maintenance/prompt injection gated by its own feature. Run protected Long Rest before the requesting claim leaves PendingMaintenance. Background services can schedule/reconcile content-free debt and process proven clean inputs; they cannot acquire or recover protected authority.

Use a dedicated immutable Long Rest provider payload and structured schema for hierarchy summaries/adjudication. At the executor boundary construct exact messages/options after the send fence, advertise zero tools, perform no Spell routing or fresh Covenant injection, and use normal model resolution, token admission, pricing, reservation, usage reconciliation and inference auditing.

Allocate a durable physical attempt ordinal. Before each dispatch, revalidate feature/configuration, canonical Campaign/root, dataset/source/owner generations, requesting claim and authority lease; acknowledge the frozen provider disclosure durably; bind its receipt to the attempt; revalidate again; then dispatch exactly once. A refusal or failed journal write sends nothing. Retry/correction is a fresh receipted physical attempt. Disable client/transport implicit retries, including strict-schema fallback, unless their physical send boundary independently performs the complete receipt/fence sequence. The same rules cover paid hierarchy embeddings; one SDK invocation is not proof of one physical send. Link authority revocation/cancellation to provider I/O. Paid successful usage remains accounted even when subsequent publication is refused.

Acquire ordinary Grimoire admission before creating a clean-work scope/connection, and an external-effect group around each resumable billable unit. Admission denial defers without opening a provider attempt, billing, failure record or cursor advancement. Register the new hosted producer/consumer and derived-output policy in the closed inventories. Append a dedicated LongRestDiscovery artifact kind after existing artifact code 15 and a LongRest maintenance step after existing step 6; preserve all previous code meanings and digest corpus entries. Give protected discovery nodes concrete sensitivity-label and erasure ownership; do not claim protection by an unowned label-only inventory entry.

## Sweep checkpoints, recovery and lifecycle

Register exactly one new long-running operation kind, recovery descriptor and idempotent handler. The recovery descriptor admits checkpoint versions 0 through 1. No provider or canonical work is allowed before the first version-1 checkpoint. A version-0 creation-gap row is abandoned with a typed not-started reason; durable source debt remains eligible for a newly scheduled operation. Checkpoint version 1 contains only operation/scope/generation identities, stable phase/cursor and committed work identity; it contains no plaintext, live task, process, token, DI object, invocation or authority lease. SQLCipher-owned work tables retain bounded generation state and immutable evidence.

The source/build/adjudication cursor moves in the owning transaction after its durable work is committed. Commit canonical receipt/input manifest/suppressions and the owning sweep item completion/cursor together in one immediate transaction. The operation checkpoint follows that committed canonical application. A crash between canonical application and operation-checkpoint write safely replays the exact existing #93 receipt, then records progress. Never advance past an unprocessed item on cancellation or failure.

Durable workers heartbeat their bounded operation lease and the authenticated claim through independent renewal paths; renewal refusal stops work. Checkpoint writes are sequential for one owner, and terminal transitions use the latest revision after heartbeat/checkpoint writes. Public operation cancellation links to worker/provider I/O. Startup reconciles operations and committed staging state idempotently. Protected interrupted work parks as the existing ReconciliationRequired terminal recovery disposition with the typed reason long_rest.authorized_request_required, displayed as waiting for an authorized Session request. A fresh eligible request may use the existing ResetForRetry path on that exact operation after all fences are revalidated; background scheduling does not repeatedly retry or report it. Do not return Waiting from recovery: the current reconciler does not accept it or release its owner lease. Recovery cannot reconstruct authority from a checkpoint. Changed owner/dataset/source/configuration/authority facts invalidate pending work before another dispatch and leave source content intact. New valid work can start from current generation facts.

Join common Annals/derived-artifact cleanup and owner inventories. Campaign/Session deletion, selective erasure, retention, reset, restore and factory reset remove/invalidate complete discovery/adjudication/projection companions without partial receipts or orphan labels. Pinning after discovery is rechecked at application. Restore validation includes the new catalog/evidence and invalidates host/request attempt authority rather than importing it as executable.

- FTS, vector and hierarchy recall reach exact eligible Saga candidates across multiple source pages; scope/partition/owner filters precede bounds in each lane; accelerator states preserve eligibility and stable ordering.
- Pins, retired and unresolved/stale targets cannot be consolidated; immutable source history, provenance, dependencies and sensitivity survive an applied transformation.

- Campaign binding/path, deletion/owner cleanup, reset/restore dataset, source, feature/configuration and authority changes between preparation and dispatch stop the next call; the same fences guard publication.
- Cancellation/failure at source, fold, provider, adjudication, canonical commit and checkpoint boundaries leaves unprocessed work retryable. Fresh-process recovery reuses committed staging work and safely handles a canonical-commit/checkpoint gap.
- Repeating an unchanged completed sweep performs zero model calls and zero canonical writes. Invalid/oversized provider output cannot publish or advance a cursor. Provider retries receive distinct disclosure evidence and ordinals.
- Global protected work succeeds only under matching GlobalOnly Session binding and scoped Global authority; Campaign/Global cross-scope capabilities, fake owner/path facts and explicit Campaign/workspace conflicts are refused.

Expired/failed operation or claim heartbeat and public cancellation stop the next send. Concurrent insertion above the frozen high-watermark permits current generation progress and becomes next-generation debt.
- Labelling a previously clean indexed source makes its tokens and dependent summaries unavailable through the clean lane in the mutation transaction and prevents generation reuse.
- Gate-off prompt/retrieval identity, inspection/preview no-dispatch, normal cost attribution, source-generated HTTP errors, fresh/evolved catalog identity, cleanup and restore tests pass.

## Verified implementation contract clarifications

Recursive singleton carry retains the existing node identity and paid evidence. A parent may reference an exact same-generation child at any strictly lower actual layer, `0 <= child.Layer < parent.Layer`; actual child layers remain hashed. This preserves acyclicity and zero-call carry without manufacturing unpaid summary nodes. Terminal cursor state must identify a completed bounded forest honestly.

A shared Core embedding-only payload digest proves that the paid input was the exact accepted summary. SHA256 binds the literal strict UTF8 domain `Arcanum.LongRest.EmbeddingPayload.v1` followed by NUL, signed big-endian int32 version 1, unsigned big-endian uint32 byte-length-prefixed provider and model, signed big-endian int32 positive dimensions, unsigned big-endian uint32 input count 1, and the same length-prefixed exact sole input. Provider/model follow the existing 1024-byte identity limit; input follows the 32768-byte strict UTF8 limit. No trimming, normalization or truncation is permitted. Storage recomputes it from the retained summary and authoritative recipe; the dedicated executor uses the same digest for its actual single-input request and admission. Work, destination, ordinal, vector output and live authority remain separate bindings. Chat framing remains Api-owned, and summary artifact content retains DerivedArtifactContentDigest.ForText.

Current physical effects retain one nullable 4096-byte bounded, source-generated LongRestDispatchCompletion record separately from cumulative usage/cost counters. A genuinely new attempt clears the current completion while retaining aggregates and copied immutable accepted evidence. Completion CAS records exact per-attempt usage/cost and increments aggregates exactly once; unchanged completion replay writes nothing and mismatching replay refuses. Current paid acceptance requires exact stored accepted completion, rather than inferring usage from cumulative totals. Historical accepted stages retain their original evidence after current-attempt replacement and require current semantic revalidation for reuse. No growing per-attempt history is introduced.
