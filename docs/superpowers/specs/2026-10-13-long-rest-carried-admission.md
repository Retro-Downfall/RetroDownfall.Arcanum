# The Long Rest: Carried Admission (#91)

Status: delivered on memory-enhancement; supersedes the internals of 2026-10-09-long-rest-hybrid-sweeps.md

The Carried Admission implementation was delivered to `memory-enhancement` through `c1b74e95`, as recorded in [#91's completion evidence](https://github.com/Retro-Downfall/RetroDownfall.Arcanum/issues/91#issuecomment-6249864553). The workstreams and their original qualification plan remain in [the companion plan](../plans/2026-10-13-long-rest-carried-admission.md). Its conditional WS13 holder-era retirement was not merged; those checker acceptance lanes and fixtures remain in the delivered tree. Delivery does not imply that optional retirement occurred. The earlier [hybrid-sweeps specification](2026-10-09-long-rest-hybrid-sweeps.md) retains its domain and public-surface history; the sections below distinguish its replaced internals. [Arcanum.DESIGN.md](../../Arcanum.DESIGN.md) owns the current behavior.

## Intent

Deliver #91 under #75 as the 2026-10-09 specification defines it: lexical, semantic and hierarchical Saga candidate discovery; bounded resumable consolidation; protected work bound to one authenticated request; durable provider disclosure before every dispatch; and invalidation before further dispatch when scope, ownership, dataset, feature or authority changes. That specification said what a sweep must guarantee. It did not fix how the permit to use the database and spend money travels through the program, how a crashed sweep comes back, or how the repository's static proof of those rules stays tractable. The first implementation answered those questions with machinery the static proof could not follow, and the evidence below shows it. This design keeps every guarantee and replaces the answers.

Operators and clients see the same feature: the default-off gate `Arcanum:Features:LongRest`, `POST /api/memory/saga/long-rest/sweeps`, exact Global and canonical Campaign partitions, source-generation freezing, protected authority bound to one live Session turn, disclosure before dispatch, and the content-free operation reference. Six behaviors differ and are documented where they live:

- Recovery, startup readiness and `arcanum operation reconcile` park a Long Rest sweep and never resume it. The hosted worker readmits a clean park after a bounded cooldown; a fresh eligible Session request readmits a protected one. An operator can briefly see `ReconciliationRequired` with a transient code such as `long_rest.interrupted` (Arcanum.Command.Reference.md, "Long Rest sweep operation notes").
- A clean schedule refused with a `LongRest.*` code no longer fails a Session turn: it is logged, counted and skipped. A Covenant failure, a configuration change during the turn and a protected partition's failure, `LongRest.OperationBusy` included, still end it (Arcanum.DESIGN.md §21.16.3).
- Long Rest chat resolves `FastModel` first and `DefaultModel` otherwise, fails closed when `FastModel` is set but unusable, and reports an enabled-but-unresolved recipe as a validator warning, a doctor row and a health row (§10.8.2, Compendium.README.md).
- New typed codes: `LongRest.SweepParked` (409), `LongRest.OperationBusy`, `LongRest.ModelContextTooSmall`, `LongRest.ProviderUnavailable`, `LongRest.ProviderUnreachable`, `LongRest.ProviderRejected` and `LongRest.TransportUnknown` (Arcanum.API.md §8.36 and the error rows).
- A provider call that ends without a result is settled as unknown usage on its attempt, and a work unit that reaches two such attempts stops sending (§10.8.2).
- The Session turn that carries live authority can retire a stranded protected sweep itself (Fresh-Authority Retire below).

## Why the first design was replaced

The first implementation is the baseline of this work, taken as it stood on 2026-10-13. It delivered the domain and the surface. It carried the work lease through a DI-scoped mutable holder (`LongRestWorkAdmission`: `Bind`, `Acquire`, `HasLease`, `Lease`), registered the recovery handlers by kind with keyed DI behind a validation pass (`ValidateRecoveryHandlerAliases`), proved drained-maintenance continuity with a proof object (`DrainedMaintenanceProof`, `ProveDrainedMaintenance`), had recovery re-run the sweep through the coordinator under a per-unit external-effect admission kind (`OrdinaryPerUnitExternalEffect`), and extended the hosted-producer checker with holder-era acceptance lanes and a scoped-lease discovery hook so the analysis could certify all of it.

The measurements, taken before any design work:

- The full production graph of the hosted-producer analysis on the baseline failed after 12 minutes 57 seconds with 8,538 diagnostics: 7,602 `WORK_FRONTIER_MISSING` (7,594 under `LongRestSweepHostedService.ExecuteAsync`, 8 under the startup recovery root), 889 `UNCLASSIFIED`, 28 `RECOVERY_HANDLER_UNPROVEN`, 7 recovery-owner, 7 disposal-target, 2 call-target and 1 recovery-dispatch diagnostics, and 2 traversal state limits (`ExecuteAsync`, and `InstallationResetService.ApplyFullUnderMaintenanceLockAsync`). The base commit b15d6960 is CI-green with the same analysis, so every diagnostic came from the #91 code or from the checker hardening that arrived with it.
- Three attribution runs separated the two causes. The new checker on the unchanged base source produced 665 primary and 287 additional diagnostics (mostly `UNCLASSIFIED` record operators, `SqliteConnection.CreateCommand`, `System.Index` and `Int128`): the hardening alone regressed code #91 never touched. The old checker on the new source produced 64 primary and 1,661 additional (mostly handle-escape diagnostics under the recovery handler). The new checker on the new source reproduced the full failure exactly (8,538 primary, 534 additional), so the result is deterministic. The new checker also ran about 75 percent slower than the old one (24 minutes 45 seconds against 14 minutes 12 seconds per run of both partitions, primary plus additional).
- The keyed recovery registration alone broke every recovery proof: the composition could not be validated (a refusal at every consumer), and the block-bodied reconciler factory defeated the factory proof. The runtime baseline (22,695 passed, 7 failed, 117 skipped) already showed it as failures in the Covenant erasure and architecture-boundary suites.
- The first run of the hosted-producer fixtures (3,003 passed, 47 failed) exposed 13 false grants in the checker (a widened `DbDataReader` indexer certified as Sqlite database access), which the first implementation's checker hardening had introduced, and a family of fixtures that hardening had left stale. Neither is a Long Rest defect, but closing both was a precondition, not a neighbouring fix: no soundness claim about Long Rest meant anything while the checker certified a database read it had not proved.
- The product itself had gaps the audit confirmed in the code: one clean refusal parked a sweep and then failed every eligible Session turn; a provider failure left an attempt `Sent` and blocked a same-boot retry; the default 8,192-token chat window made oversize units reachable, so a unit could be paid for and then refused; lexical statistics were shared across partitions; identical candidate sets were adjudicated repeatedly; every validation step re-read the whole corpus; protected full-text content outlived its generation; `FastModel` was ignored; and a pooled connection could resend a request, so one SDK call was not provably one physical send.

An architecture panel (nine independent designers, three judges, a synthesis and adversarial reviewers) then examined the structure. Two attack families were fatal to its first draft: a design that let recovery re-run the sweep put the whole paid Long Rest closure under a second analysis root, where it already exceeds the 8,192-state traversal limit by itself, and a unit-level handoff could not split it. The adopted design removes the cause instead of working around it: recovery never runs a sweep.

### Authority: one lease, carried by value

- **Carried Admission.** A Long Rest work lease (admission kind 17) is minted once at a root and passed by value to every use; outside the admission gate's own nested types no object stores a work lease or an external-effect group. Plainly: the permit to use the database and to spend money is handed down the call chain like a ticket and is never kept in a shared drawer, so nothing can use it after its owner has given it back. This is the architecture's name.
- **Lease Spine.** The by-value path itself: acquisition in the worker's `RunOneAsync`, then `ILongRestAdmittedSweep.ResumeAdmittedAsync`, the sweep core, `RunOwnedAsync`, `ILongRestAdmittedMaintenance.ProcessAdmittedAsync`, fold and adjudication, and the external-effect group begun on that same parameter in `ExecutePaidAsync`. The Session `ResumeAsync` shell acquires its own lease and enters the sweep core directly, not through `ResumeAdmittedAsync`. The scoped holder `LongRestWorkAdmission` and its `Bind` no longer exist (§21.16.4).
- **Admitted ports.** `ILongRestAdmittedSweep` is the Infrastructure-internal hosted door: one member, no capability parameter, exposed as a forwarding alias. `ILongRestAdmittedMaintenance` is the internal port the Api maintenance implements, so the lease crosses the Core/Api seam without appearing on the public Core contract, which no longer has a process member.
- **Admission Kind Guard.** Both admitted entries refuse a missing lease and any lease whose kind is not `LongRestSweep`, before any work. Plainly: a ticket for some other kind of work cannot start a sweep.
- **Presented-Lease Attestation.** The gate answers `AttestDrainedMaintenance(lease, previous, current)` under its own lock at every use, with the same predicate the old proof object encoded; the kind check lives in the Long Rest fence reader, not in the generic gate. Plainly: instead of issuing a certificate that could outlive the permit, the gate is asked every time whether the permit is still good (§21.16.5).
- **Authority Carrier Ban.** An architecture test over the production compilations: no field, property, event, primary-constructor capture or closure capture may hold a work lease or an external-effect group, including through object-, disposable- or generic-typed members. The deliberate request, closing and closed-lease carriers are an exact, reviewed census with a self-test.
- **Admitted Entry Census.** Architecture pins, matched on exact interface symbols and their implementations rather than on names, for who may enter the spine: `ResumeAdmittedAsync` only from the worker's `RunOneAsync`; the sweep core only from the Session shell and the hosted port; `ProcessAdmittedAsync`, clean readmission and the completed-checkpoint proof only from the owned run; the Session `ResumeAsync` only from the campaign preparer; a Long Rest lease minted only by the worker's discovery and `RunOneAsync` and by the Session shell; and Atomic Readmission only from the coordinator core.
- **Ambient Holder Refusal.** The checker keeps refusing a read of an ambient holder as a source of Work, and fixtures pin the refusal. Today it is keyed on an unbound holder whose binder is named `Bind`: a holder with any other binder name, or none, would keep the worker's Work at its send, which `AmbientHolderRefusalIsTodayKeyedOnTheUnboundBindNamedHolder` pins, and the Authority Carrier Ban is what keeps any holder out of production. The final convergence (WS13, not yet merged) is to widen the refusal to any holder read and to retire the holder-era acceptance lanes, but only if the Site Digest equality condition under "Removed machinery" holds. The refusal itself is never retired.

### Recovery: park, then readmit under the owner's authority

- **Park-and-Readmit Recovery.** Durable recovery never runs a Long Rest sweep; it only parks one. The authority class that owns the work is the only one that readmits it: the hosted worker readmits a clean sweep under its own kind-17 lease, and a fresh Session capability readmits a protected one. Plainly: when the program restarts, nothing spends money on its own; unfinished sweeps wait with a reason, and whoever is allowed to pay picks them up (§10.8.2, §21.16.3).
- **Pure Park Handler.** `LongRestSweepRecoveryHandler` has no constructor parameters and one `RecoverAsync`. It decodes the checkpoint and returns a verdict: abandoned (version 0 or cancelling), `long_rest.authorized_request_required` (protected), `long_rest.interrupted` (an expired running or waiting row), `long_rest.readmit_requested` (an operator retry) or the codec error. Plainly: recovery can describe the situation but cannot reach a provider, a store or the coordinator. One deviation from the panel: the handler cannot see a `Pending` row, so the generic `LongRunningOperationStore.AcquireLeaseAsync` stamps `long_rest.readmit_requested` itself when it adopts a `Pending` Long Rest row that carries a prior attempt (which only an operator retry produces). That puts a Long Rest rule inside the generic store; it was taken in WS3 and is recorded as a deviation.
- **Atomic Readmission.** `LongRestSweepStore.TryReadmitParkedAsync` re-proves the parked state in one immediate transaction and moves `ReconciliationRequired` straight to `Running` under the readmitting caller's owner and lease, with row-count checks. It serves both authority classes through the same transaction: the hosted worker readmits clean parks, and the Session shell, under a validated capability and its own kind-17 lease, readmits protected parks. Clean readmission is reachable only from the worker's port. The row never passes through `Pending`, so the generic reconciler, which adopts `Pending` rows that carry a prior attempt, can never observe a half-readmitted sweep.
- **Sweep Failure Budget.** `ReadmitCount` and `ParkedAt` on the sweep row. A clean readmission after a failure is allowed while the count is below 4 and `ParkedAt + 30 s * 2^count` has passed; operator retry and committed progress reset it, and a yield to maintenance spends nothing. When the last readmission fails the park becomes `long_rest.readmit_exhausted` and waits for an operator. Plainly: a sweep that keeps failing backs off and then stops asking for money.
- **LongRestFaultPolicy.** The one pure table mapping every `LongRest.*` and `long_rest.*` code to `ResumeLater`, `RestartGeneration` or `NeedsOperator` (an unknown code needs an operator), with the free-park set and the budget arithmetic. The coordinator, worker discovery, Atomic Readmission and request admission all read it; the SQL receives code lists as parameters.
- **Parked Rescan.** The worker also wakes on a timer (60 seconds, or the next cooldown due time, never under one second), because the hint channel is a single bounded slot and nothing signals a cooldown that expires. The wait is one awaited read on a token a `TimeProvider`-backed source cancels, so no task outlives it.
- **Parked-Is-Active.** The request-admission rule: a parked clean sweep with a resumable code and unspent budget, or a protected sweep parked as authorized-request-required, whose configuration value digest is current, is returned unchanged with no writes; a changed value digest retires it and creates a new one, and so does a configuration epoch that changed inside the same boot (a flip from A to B and back bumps it twice); a park that needs an operator answers `LongRest.SweepParked` (409). A request never claims, resets or runs a started sweep.
- **Fresh-Authority Retire.** A protected sweep parked with a restart-generation code can never be readmitted, so it would fail every protected turn of that partition until an operator cancelled it. A request that carries the live turn lease of the Session turn making it (`RequestAsync(scope, partition, authority, ct)`) retires it through the existing owner-guarded retire path and creates a new generation in the same transaction. The six codes are `LongRest.StaleInput`, `LongRest.StaleFence`, `LongRest.CurrentnessLost`, `LongRest.ConfigurationChanged`, `long_rest.stale_configuration` and `long_rest.not_started`; the class is read from the policy table. The lease is proved before the write and again before the commit. Needs-operator codes still need the operator. A clean sweep needs no such retire: one that faults with a restart-generation code is settled `Abandoned` by the coordinator instead of parked, and the next request replaces it with a new generation.
- **Clean-Only Busy Skip.** `LongRest.OperationBusy` is a non-fatal skip for clean partitions only. A busy protected partition still fails the turn, because only exact protected work finishing under the pending claim lets maintenance end.
- **Unkeyed Registry Restoration.** The recovery-handler registrations, the expression-bodied reconciler factory and the per-operation lookup return to their base-commit shapes; the keyed descriptors and `ValidateRecoveryHandlerAliases` are gone, and a pin bans keyed descriptors. Plainly: the ordinary way of registering handlers works again, so the repository's recovery proofs can read it.
- **Finisher Ambient Fix.** Startup settlement acquires its recovery lease inline instead of through an async helper, so an in-flight external-effect recovery handler keeps the gate's ambient admitted lifetime and can still open a connection while the gate is closing. The base helper lost that lifetime.
- **Retry Cursor.** `SqliteBusyRetryCursor` is a closure-free form of the busy-retry policy (an inline attempt loop with the same policy), so the clean readmission and completed-checkpoint reconciliation no longer capture a work lease in a delegate. It removed two lease-carrying closures from the carrier census.
- **Host start ordering.** The Long Rest worker is registered after the startup readiness service and the host starts hosted services sequentially, so the worker cannot send before the readiness pass; a pin holds the order.

### The paid door

- **Unknown-Usage Settlement and Cap.** When an SDK call ends without a result and without cancellation while its attempt is `Sent`, the frame that owns the send settles the attempt in place: failed, no completion evidence, failure count plus one, `LongRest.TransportUnknown`. Usage is never estimated and never written as zero. Only a failure before any request byte could leave (the egress guard's connect failure, a socket or TLS failure while connecting) settles as not sent. A work unit that reaches two unknown-usage attempts stops sending and parks as needs-operator. Plainly: when we cannot know whether a request was billed, we record that we do not know and stop after two such events rather than guess.
- **One Connection Per Send.** The Long Rest and Campaign Rollup owned HTTP handlers set the pooled connection lifetime and idle timeout to zero, so one SDK call is one request on its own connection and a stale connection cannot silently resend it. A source-association pin holds the text.
- **Owned Client Construction.** Hosted-reachable HTTP clients (Campaign Rollup provider, MCP HTTP transport) are built from an explicit handler chain in their owners instead of through named `IHttpClientFactory` clients, so authored handler code is visible to the static proof and the broad `CreateClient` allowance stays removed. This is a production change outside Long Rest and changes the MCP transport's pooling and lifecycle (§11.11, §10.20.3).
- **Admit-then-Prepare.** Every refusal that follows from the request itself (render size, token budget) happens before any provider-effect row or accounting run exists. A prepared attempt that no send followed (a daily-budget or credential refusal, a failure or a cancellation before the send was recorded) is withdrawn by the frame that owns it (`ReleaseUnsentAttemptAsync`) rather than left behind.
- **Window-derived input bound and group packing.** `LongRestPromptLayout` derives the provider input bound from the chat provider's context window, `floor((window - 2064) * 100 / 115)` bytes capped at 32,768; the bound is part of the recipe. A chat window below 6,775 tokens (a bound under the 4,096-byte minimum) or an embedding window below 1,194 tokens (the smallest summary bound, 1,024 bytes; the Embedding Window Floor) leaves the recipe unresolved and refuses with `LongRest.ModelContextTooSmall` before any effect row. `LongRestGroupPacker` packs each anchor's neighbours into at most three paid packs, plus duplicate-only packs that cost no request.
- **Embedding-Bounded Summary.** The recipe carries `SummaryUtf8Bytes` (2,048 to 8,192), derived from the embedding provider's window, stated in the summary prompt and enforced by a counted embedding gate, so a summary that respects the bound always fits the embedding request. A derived output-token cap was tried and removed after review (a bytes-per-token assumption was too low for real tokenizers); the answer reservation stays fixed. The remaining exposure is a model that ignores the stated bound, which is paid and then refused (§21.16.4).
- **Chat model and recipe.** `LongRestRecipeResolver` resolves `FastModel` first, then `DefaultModel`, fails closed, binds the summary destination digest into the recipe, and is the single source of the sentence the validator warning, the doctor row and the health row share.

### Discovery quality

- **Scoped Lexical Ranking.** Lexical candidates are scored with an integer, BM25-like scorer in Core over a generation-scoped full-text match, with distinct tokens, lazy verification in score order and no cross-scope or cross-partition term statistics. The scorer version is part of the recipe, and published summaries are never indexed (§21.16.1).
- **Ancestor-Excluded Cross-Cluster Recall.** A hierarchy query follows the anchor's exact leaf edges to its nearest generated summary and never ranks or expands the anchor's own ancestor chain, so a hierarchy hit is evidence from another cluster rather than the anchor finding itself.
- **Eligible-Source Capture.** Capture excludes retired, pinned and suppressed sources, mirroring the protected-partition source rules, so retired text is never sent to a provider and a consolidated source does not re-enter discovery.
- **Set-Level Decision Reuse.** An identical input set that already has an accepted no-change decision in the same generation is never adjudicated again; groups render in canonical `MemoryId` order, and an adjudication recipe version separates changed prompts.
- **Supersede-on-Completion.** A trigger purges a completing generation's index rows and invalidates older completed generations of the same scope and partition, so protected full-text content does not outlive the generation that needed it (§21.16.1).

### Verification cost

- **Seams-and-Steps.** The whole corpus is re-proved at seams (publish; completion; resume and clean readmission; interrupted-send settlement; the first unit of a protected run, which is the first thing to hold the capability; capability issuance; completed-replay adoption) and only the inputs a step acts on are re-proved at each step, plus one rotating window of 32 leaves. A step performs one set-based metadata statement over every leaf, and attribution is asked in both directions (every flag on a leaf must be explained by a committed work item of its own generation, and every frozen flag must keep the row that sets it). The depth parameter has no default anywhere, so a new gate cannot inherit the cheap depth by omission. The mutation matrix (`LongRestMutationMatrixTests`) records which mechanism refuses each bypassing path: foreign keys off, restore sanitation, factory reset, the erasure kernel, schema rebuild and readmission after any of them (§21.16.3).

### Campaign context and the Sanctum

- **Long Rest-Scoped Enrichment.** The registered Campaign root that Long Rest compares its fences against is added by a `CanonicalCampaignRootEnricher` used only on Long Rest request and fence paths, and only for requests that are Long Rest turns. With the feature off the canonical Campaign context is byte-identical to before and no registry read happens (§10.12).
- **Sanctum Campaign resolution.** A bundled correction found while reviewing the Sanctum's AuditOnly mode: a turn's Sanctum is its bound Campaign's, chosen from the strictest of the canonical binding, the per-source asks and the registered root containing the working directory, rather than from an exact working-directory string. An unreadable policy refuses every tool call; AuditOnly overrides only policy refusals, never an unreadable Sanctum or an unrecorded breach. The defect also existed on `main`, which has since received its own port of the binding correction and its review fixes (the path boundary judged by the directory a path reaches, the Campaign's limits for `run_spell_script`, a malformed Session binding leaving the Sanctum unreadable); this line carries both. Where the two lines differed on one point, the merged line keeps `main`'s fail-closed behaviour: an AuditOnly Sanctum records the breach and lets the initial target of `read_url` go on, but a redirect hop and a research citation outside the allowed domains are refused in both modes (§11.15, §11.27).

### The static proof

The hosted-producer inventory is the repository's proof that every database use and provider send runs under a gate-minted lease, within bounded analysis state. The design changed it only where Carried Admission needed it, or where the first implementation's hardening had regressed the base source. Nothing here raises a limit, removes a storage scan or deletes a refusal rule; the six budgets (256, 256, 8,192, 4,096, 64 and 128) are pinned by `LimitsAreFrozen` and the limit pins. Two classifications were narrowed, each proved by fixtures and justified where it is listed below: a `Task` is no longer a lease carrier merely because it is disposable, and closed pure data derived from a lease contributes no origin. The contract is in §10.20.3, in the paragraphs from "Authored hosted-producer inventory" to "Lease-Handoff Root".

- **Lease Receiver Proof and Must-Alias Lease Demand.** A send's group counts as its Effect only when the receiver is a must-alias of the lease whose Work is live: a parameter, or a never-written local whose only definition is the guarded acquisition or a formal bound to one. Joins, conditionals, coalesces, loop-carried values and fake leases are refused. It applies at every place a group is recognised, including the recovery shell.
- **Single Gate Census and Departed-Lease Group.** The one reviewed gate is the only implementation of the admission contract, or every acquisition is refused. An Effect carries the origin of the lease its group was begun on, and a send whose Effect and Work come from different leases loses the Effect.
- **Lease-Handoff Root.** The Long Rest closure below the admitted maintenance is judged once, as its own root, instead of under every caller's state budget. The root's lease formal is its admission origin (Root Lease Formal); a caller cuts the edge only under strict conditions; Formal Preservation keeps the caller's lease lifetime only when the root provably never disposes, stores or returns it; and the Handoff Caller Census refuses any production caller of a handoff method that is not a proven cut edge. It was adopted on evidence: the state census measured `ExecuteAsync` at 14,536 states against a limit of 8,192.
- **Premise Ledger.** Opt-in, scan-verified facts about what exists in the analysed universe, requested only by the Production Discovery Entry and never by fixtures. It holds three premises, not the panel's one. `SqliteSealedByUse`: no subclass of the Sqlite connection, command or transaction types in any analysed source or resolved reference. `AuthoredEnumerablesAbsentByUse` (WS0G): no authored type implements the framework sequence interfaces or declares an enumerator member, so a value of a framework collection interface has no authored runtime type to dispatch to. `DbProviderTypesClosedByUse` (WS0H): every type that derives from a database provider or Entity Framework type is declared by a trusted provider assembly, matched by exact name, version, culture and public key token, and no authored `DbContext` overrides a member beyond configuration. Each is verified by an enumeration of every type of the analysed assemblies and their resolved references, each is withheld when a reference, a base type or an interface cannot be resolved, a violation reports `HOSTED_PREMISE_VIOLATED`, and none grants work or effect authority. An unverifiable universe grants nothing. A pin per premise checks that the shipped universe satisfies it.
- **Closed-Value Equality, Canonical Equals Traversal and Full-Environment Identity.** A record operator is classified when a recursive field walk proves every field handle-incapable; an authored typed `Equals` is traversed once in an unbound argument environment under the caller's Work and Effect, with root, recovery tuple, frontiers and lifecycle kept in the state identity so an effect inside it is reported in every root. The Structural Operand Rule and Runtime Type Identity Comparison classify exact framework scalar operators and `typeof`/`GetType()` comparisons.
- **Handle-Incapable Value.** Closed pure data derived from a lease contributes no origin, so data computed from a lease call is not mistaken for a handle carrier. This removes refusals, so its soundness rests on the word closed: a value counts only when its type is proved closed pure data (no instance, whatever its runtime type, can hold or reach anything but more closed pure data), an instance event refuses the claim, and static storage stashing is refused at the store. Its known limits (a stash through a closed key in instance storage, a static alias through a local or `ref`, delegates not being carriers) are pinned, and the Authority Carrier Ban covers them at production level. A companion rule, made in WS0H, stops a `Task` or `Task<T>` being a lease carrier merely because it implements `IDisposable`; it still is one through its type argument, so a task that wraps a lease keeps the lease's origin.
- **Implicit Enumeration, Implicit Call Census, and EF/ADO.NET completeness.** The checker models the calls C# makes without writing them (`foreach` and spread enumeration, deconstruction, awaiters, interpolation handlers, operators, static initialisation), every Entity Framework execution site (synchronous `DbSet`/`IQueryable` enumeration, context hooks, interceptors, loggers, connection state handlers) and the by-name ADO.NET grants, failing closed where provenance is incomplete.
- **State containment and the Headroom Tripwire.** Environment canonicalization rules (constant value identity, foreign parameter projection, cancellation tokens never bound to their chain, non-owning parameter creation, inert payloads) cut analysed states without changing a verdict, proved by identical site and diagnostic dumps at one, two and three root workers. Every production root and every additional root has a committed ceiling (the largest count any worker arrangement reports plus five percent, never above 90 percent of the cap), ceilings only move down, and a root that grows past its row fails a test; the Long Rest rows were raised once, by the change that earned the room, with the reason stated beside them.
- **Verification speed.** A formatter index, once-per-resolution formatting steps, shared semantic models per compilation and tree, and program-wide indexes made the analysis fast enough to run in CI without changing any verdict (fixture partition summed time 6,393 s to 1,206 s). CI runs five partitions (primary, additional, fixtures, fixtures-build, serve-host) in separate jobs and an aggregate that reconciles their receipts (§13.1). This is the response the plan chose to CI cost, in place of the panel's Root-Sharded Discovery contingency.

## Removed machinery

Removed from production: `LongRestWorkAdmission` and every borrow-or-acquire branch; `DrainedMaintenanceProof`, `ProveDrainedMaintenance` and the default attestation slot; `LongRestSweepCoordinator.RecoverAsync` and `RecoverAdmittedAsync`, the coordinator dependency of the recovery handler, the per-unit external-effect admission kind and the reconciler's maintenance-deferral rethrow; the keyed recovery registrations, `ValidateRecoveryHandlerAliases`, the block-bodied reconciler factory and the keyed lookup; the conditional holder `Bind` and the per-lease linked dispatch token in settlement; the public Core `ILongRestMaintenance.ProcessAsync`; the named-client paths for Campaign Rollup and MCP; and the derived reuse index on discovery nodes. Why each is safe: every reader now receives the same lease by parameter, recovery can no longer reach a provider, and the base shapes the checker already accepts returned. The tests that covered the workaround (selected-kind scope tests) went with it.

Draft machinery that was designed and never built, retired by the panel: the second recovery door and its thin handler, readmission by deferral, the unit-level root handoff, and three broad closed-world premises (ADO.NET hierarchy closed, collection contracts closed, `IHttpClientFactory` closed), the first of which is false for shipped dependencies and the others of which were allowances. Checker machinery proposed and never adopted: literal-keyed composition and the lease-discovery helpers built around it.

The delivered premises are not those three revived. The retired ADO.NET premise claimed that nothing but provider types derive from the ADO.NET abstractions, which is false for shipped dependencies (Entity Framework's `BufferedDataReader` derives from `DbDataReader`). `DbProviderTypesClosedByUse` makes a narrower claim and verifies it: every derived type is declared by a trusted provider assembly matched by exact identity, which `BufferedDataReader` satisfies, and any unresolved or untrusted reference withholds it. The retired collection premise was an allowance nothing verified; `AuthoredEnumerablesAbsentByUse` states one fact (no authored implementation exists) and scans for it. The `IHttpClientFactory` premise did not return, because Owned Client Construction removed the factory from the hosted paths instead. Growing the ledger from one premise to three departs from the panel's ruling and is listed under the decisions taken on the owner's behalf.

Deliberately retained in the delivered tree: the six traversal budgets, every storage scan, every fail-closed path and the holder-era refusal rules. The holder-era acceptance lanes (per-unit and readiness acceptance, the ordinary-holder witness acceptance, the scoped-lease instance hook and its fixtures) and the Lease Receiver Proof's holder-era exemption also remain. The companion plan's conditional WS13 retirement was not merged. It required equal Site Digests over the sorted capsule manifest and diagnostics before and after retirement; the delivered behavior and the full producer-analysis qualification do not claim that this separate cleanup happened.

## Security argument

Runtime invariants, each at least as strong as before:

1. **Permit.** Every Grimoire connection use, scope creation and provider send reachable from a hosted or recovery root runs under a live gate-minted work lease, and every Long Rest send also runs inside its own external-effect group begun on that same lease.
2. **Single, non-ambient authority.** No object other than the gate stores a lease or a group; the Authority Carrier Ban enforces it, and the Admission Kind Guard rejects any lease that is not kind 17 at the admitted entries.
3. **No capability source on hosted or recovery paths.** The hosted door has no capability parameter and passes a literal null. The only caller of the capability-bearing resume is the campaign preparer, pinned by the Admitted Entry Census. Protected checkpoints park as authorized-request-required and finish only under a fresh Session capability.
4. **Disclosure before dispatch is unchanged.** The before-send chain (current-fact check, durable receipt, single-use child capability, mark sent, current-fact check) is untouched. Unknown-usage settlement records unknown billing truthfully; a retry gets a new attempt, ordinal and receipt.
5. **Drained-maintenance continuity.** The attestation is the former predicate evaluated under the gate lock at each use, with the previous admission taken from the transaction-reloaded row. No proof object exists, so authority cannot outlive its lease.
6. **Recovery is effect-free for Long Rest by construction.** The Pure Park Handler has no dependencies. A parked sweep resumes only through Atomic Readmission, under the in-process ownership claim and a live kind-17 lease, in one immediate transaction that re-verifies the parked state, partition, code class, budget and cooldown. Clean readmission is reachable only from the hosted worker's port; protected readmission needs a validated fresh Session capability and runs under the Session shell's own kind-17 lease. Fresh-Authority Retire needs the live turn lease of the requesting Session turn, proved before the write and before the commit, and never retires a park a capability could readmit.
7. **No paid egress before readiness, and none from an operator HTTP call.** Recovery and `operation reconcile` only park, the sweep endpoint only schedules, and operator retry only resets a row to `Pending`, which recovery then parks. The worker starts after the readiness pass.
8. **Bounded retries.** Readmission is bounded by the Sweep Failure Budget and unknown billing by the Unknown-Usage Cap; both end in a needs-operator park. Cancellation never settles an attempt, so an interrupted send stays `Sent` and the reboot settlement handles it.
9. **Verification never goes cheap by omission.** Every verification gate names its depth, a step still re-proves the inputs it acts on and the whole-corpus metadata statement, a seam re-proves everything once, and the mutation matrix fails if a bypassing path lacks a refusing mechanism.

Static soundness: no budget is raised or relocated, no storage scan is weakened and no refusal rule is deleted. Two classifications were narrowed, and each is argued under "The static proof": a disposable `Task` is no longer a lease carrier by that fact alone, and closed pure data derived from a lease contributes no origin; both are proved by fixtures. Every new proof surface fails closed (the receiver proof only removes authority; the handoff root cuts an edge only under the must-alias demand, a direct await inside the lease lifetime, a null caller Effect and an equal work kind; every premise refuses an unverifiable universe; every table entry is an exact framework identity with a lookalike negative). Results are deterministic and neutral changes are checkable by Site Digest equality. Compared with the first implementation, which the checker could not prove at all (7,594 refused Work losses under the worker root and a composition refusal at every recovery proof), the Long Rest paid path is now proved in one hosted root and a census-chosen handoff root by the same admission-flow analysis already qualified for the other hosted workloads, plus one stricter receiver rule.

Collateral gains: protected full-text content no longer outlives its generation; retired text is never sent to a provider; partitions no longer share term statistics; one SDK call is one physical send; read-only work no longer holds the writer lock; and an in-flight recovery effect group can finish while the gate closes.

## Deferred work

Each becomes a child issue of #75 at delivery (the last steps of the plan). Default-on stays blocked on the debt gate; the Unknown-Usage Cap and the Sweep Failure Budget bound exposure in the meantime.

- **G5b, cross-generation reuse.** Every new generation re-summarizes and re-embeds every multi-child fold and re-asks every adjudication; reuse needs append-stable paging and generation lineage so exact membership can hit (reuse within one generation is delivered).
- **G5c, debt gate.** `LongRestSweepDebtPolicy`: a cooldown or threshold (suggested: 8 new sources or 6 hours) so every eligible turn does not start another O(N) paid sweep.
- **G6 tier 2.** A per-turn `LongRestTurnAllowance` so protected maintenance yields cooperatively and resumes on the next turn; it would amend the written contract.
- **G3-F6, per-source deferral.** An unusable source (one over the 32,768-byte capture bound, or with a non-finite embedding) fails closed today: capture refuses with `LongRest.Unavailable` and never advances past it, so the sweep retries within its Sweep Failure Budget and then waits for an operator as `long_rest.readmit_exhausted`. The follow-up would add a typed needs-operator code (proposed as `long_rest.source_unusable`, which does not exist yet) and a metric, advance capture past the source, count it and retry it in the next generation. It contradicts a pinned fail-closed test (`Unverifiable_sources_never_advance_capture`) and the 2026-10-09 wording, so it needs a decision before it is built.
- **G7c-2, selector/verifier split.** The per-anchor corpus scan re-verifies every leaf although only the anchor and the winners become authority.
- **G7e, throughput options.** Optimistic read-then-commit for the work reader and a blocked neighbour pass to bring the all-pairs scan to O(N^2/B), relevant at roughly 5,000 sources or measured lock holds near 100 ms.

## Residual risks

- CI wall time is measured on a runner and memory is not (Verification Lanes and Verification Memory in DESIGN section 13.1). Run one at a time as CI runs them under the memory proxy on an Apple M5 Max, the five hosted-producer lanes took 556 s (`primary`), 161 s (`additional`), 182 s (`fixtures`), 495 s (`fixtures-build`) and 480 s (`serve-host`). On the standard `macos-26` runner (three cores) a CI run in which the five lanes passed (run 39034206699) took 1,476 s, 437 s, 381 s, 1,395 s and 1,410 s, which is 2.1 to 2.9 times the local wall time. A second CI run of the same analysis code (run 39042677321) did not finish `primary` inside a 1,740 s deadline: the runner stopped it with its production discovery 93 root traversals in, while the other four lanes took 368 s, 558 s, 1,341 s and 1,266 s. The deadline of each lane is therefore 3,540 s (a 60-minute step inside an 80-minute job): the longest lane of the passing run is at 42 percent of it, and the 1,740 s that `primary` did not meet is less than half of it. A fixture lane that exceeds 85 percent on the runner is split by category into a further lane. The memory margin is the thinner risk. The test host of `primary` peaks at 5.81 GB (5.65, 6.12 and 5.81 GB in three runs, so up to about 6.1 GB), the other lanes at 3.9 to 5.5 GB, and the runner's own `dotnet test`, vstest console and python add about 0.28 GB, which puts the largest lane at about 6.4 GB against a runner of about 7 GB that must also hold the operating system and the runner agent. That leaves roughly 0.6 GB for the operating system and the runner agent together on the worst of the three runs, not free headroom, and no measurement of what a runner really has free; a lane that grew by a GB, or a runner that gave less than 7 GB, would take it, and a lane that grew would need another heap probe like the ones that found the cleanup binding pool, the platform references and the semantic models.
- Thresholds that need live data: the Pairing Gate constants (`PairingClosenessPermille` 550, `PairingSpreadTenths` 35 with `PairingSpreadStepTenths` 2, `PairingSpreadMinimumThousandths` 20, `PairingMinimumLeaves` 16, `PairingFallbackPermille` 920, `PairingAbsoluteMinimumPermille` 500), the lexical coverage bar (`LexicalMinimumCoveragePermille`, 200 thousandths), the scorer constants and the 0.92 summary gate (`SummaryMinimumCosinePermille`, hierarchy summaries only). The live embedding model (qwen3-embedding:8b, 8-bit, 40,960-token window) against the 1,194-token minimum, and the default 8,192-token chat window (two memories whose text together is more than about 3,000 bytes are not paired), are checked against the owner's models in the live qualification gate.
- Unknown-usage settlement records truth but leaves billing unknown; exposure persists until the debt gate exists.
- The Campaign containment lookup used by the Sanctum reads every registered Campaign path per lookup (linear in Campaign count, uncached). Windows path spellings are unverified on a Windows host.
- The Retry Cursor is a mutable struct: a copy loses its attempt count, though its deadline still bounds it.
- The seam cost after decisions grows with the number of distinct applied receipts, within pinned statement counts.
- The Sanctum correction changes behavior (a Strict Campaign now sandboxes subdirectory, case-variant, symlinked and Session-bound turns) on `memory-enhancement` when this work merges, and on `main` only when that branch later reaches it, unless the owner asks for a separate fix.
- The companion plan retains the pre-delivery workstream checklist as history. #91's completion evidence establishes the delivered code and qualification; it does not establish the conditional WS13 checker retirement, which remains unmerged.
- Schema 18 has no downgrade; install needs a backup.
