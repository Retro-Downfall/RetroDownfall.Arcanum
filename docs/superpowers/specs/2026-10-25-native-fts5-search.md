# Native FTS5 search

The user explicitly requires full FTS5 support, superseding RV072's optional keyword-only remediation. Archive search and transcript matching in session search must pass native FTS5 expressions unchanged to the bundled SQLCipher engine through bound SQL parameters. SQLite owns parsing, tokenization, Boolean precedence, phrase concatenation, prefixes, initial-token anchors, proximity and column filters. Content is the indexed Entries_fts column; Id, SessionId and Role remain unindexed. Session title substring matching remains additive.

The chosen approach uses the existing native engine. A hand-written partial grammar would diverge from FTS5; stripping operators violates the user's request. No SQL text interpolation or new dependency is required. Native syntax is supported within existing query-length and result allocation limits. Overlong expressions must be refused intact, never truncated into a different expression.

Malformed expressions return actionable Validation.InvalidQuery failures through the Result contract and existing API envelopes. Archive MCP calls identify invalid input as tool errors rather than successful empty search. Empty/no-searchable input, valid no hits, syntax errors and storage/runtime failures must stay distinguishable. Do not echo raw native exception contents or log user queries. Native engine syntax diagnostics are classified narrowly; missing tables, corruption and admission faults retain their real failure semantics. A parser validation probe may use one bounded native MATCH row when necessary for deterministic errors on empty corpora or title-only matches; do not duplicate whole-result scans.

Literal quoting and examples are taught in tools/list, parameter schema and owning docs. Plain words retain FTS5's implicit AND behavior; users can write OR, NOT, parentheses and quoted phrases explicitly. Internal Lexicon-generated literal terms retain their separate sanitizer. The independently discovered underscore-only sanitizer defect remains fixed and tested there.

Acceptance uses the real bundled SQLCipher and native API/MCP/CLI paths: positive AND negative match fixtures for the complete query grammar; malformed expressions, empty corpus, quoted punctuation/escaped quotes, supplementary Unicode, injection-shaped input, query length, cancellation, missing index, existing title and date/ID pagination controls. Native AOT and existing source/admission guards remain mandatory. Numerical retrieval quality is unrelated to this syntax contract and no semantic-search claim is made.

Reference: https://www.sqlite.org/fts5.html#full_text_query_syntax (verified 2026-10-25).
