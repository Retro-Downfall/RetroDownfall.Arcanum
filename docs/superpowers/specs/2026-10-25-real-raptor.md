## Intent and chosen approach

Replace spherical K-Means as the production Tapestry builder with an actual RAPTOR pipeline: UMAP manifold reduction, global then local full-covariance Gaussian mixture selection by BIC, posterior-threshold multiple membership, model summaries, re-embedding, and recursive abstraction. Keep The Tapestry optional, existing corpora/scopes, configured providers/models, billed summary requests, ledger precedence, and both retrieval modes. The user specifically requested the real algorithm, not a renamed approximation.

Recommended approach: first-party pure-managed numeric kernels in Core, immutable generation-scoped DAG persistence in Infrastructure, and one typed retrieval service used by Wizard. A Python sidecar would best reuse the reference but violates single-binary Native AOT deployment and adds process/native dependencies. Random projection plus K-Means would be cheap but does not meet the request. A speculative general numerical framework is unnecessary; bounded sparse graph operations and matrices of at most ten reduced dimensions keep the implementation focused.

The existing DESIGN §21.11 assertion that overlap makes provenance/deletion “intractable” is false. A finite acyclic relation supports exact ancestry and source closure. Erasure can remove the entire affected derived generation transactionally, which is stronger and simpler than trying to edit model prose. Overlap increases edge count and demands explicit deduplication; it does not prevent correct deletion.

## Algorithm contract: `raptor-umap-gmm-v1`

All settings below are code-owned and included in the algorithm manifest/fingerprint. Keep only existing `RetrievalMode` and `SummaryModel` as public operator policy. Do not repurpose `TargetChildrenPerSummary` as K: remove it from the new build path and explicitly classify legacy-only mechanics. Do not introduce a selectable K-Means production fallback.

1. Read the entire eligible scope in stable source-id order. Preserve every eligible nonblank leaf, its original source identity and original-dimensional embedding. Validate finite, nonzero, consistent-width vectors. If a vector is invalid, try the configured embedding provider; if still invalid, refuse the new generation with a typed, content-free outcome rather than publish a partial corpus. Existing embeddings require model/provider provenance, not merely matching width; absent or mismatched provenance means re-embed. Keep the current explicit 50,000-source admission ceiling; exceeding it returns `TooLarge` before paid work, never a prefix advertised as complete. The ceiling is an operational bound, not a RAPTOR property.
2. For more than 11 current nodes, perform global UMAP to `min(10,n−2)` dimensions, then full-covariance GMM. For each global posterior membership, perform local UMAP/GMM on the corresponding original input embeddings, except subsets of at most 11 form one local group. Never run local UMAP on the global reduced coordinates. Retain original integer indices throughout; never join by vector equality.
3. Select all components with posterior `p > 0.1` at each stage. Final membership identifies `(global component, local component)`; store the two posterior values separately, since their product is a hierarchical score, not a calibrated joint probability. If no posterior clears the threshold, add the maximum-posterior component with canonical tie-break and `NoMembershipRepair`; do not silently discard the point. At this threshold each stage has at most nine qualifying memberships, providing a useful bound of 81 raw local memberships per point before repairs. Do not arbitrarily cap this at top-one or top-two.
4. Canonicalize components and clusters by ordered stable membership identities, with mean/covariance lexicographic tie-break when needed. Coalesce identical member sets before summary calls, retaining a reason that duplicate cluster paths merged. A content hash does not replace node identity: byte-identical distinct sources remain distinct leaves.
5. Re-run the same clustering within an oversized cluster until both the retained child-count bound (24 by default) and `ITapestrySummarizer.FitsOneRequest` hold. Track the canonical input member set of every split to detect repetition. If it cannot contract, use explicit stable-id partitions, refining by real request fit, not only count. Record `NonContractingPartition` or `DegeneratePartition`. A single oversized source is carried unsummarized as a reachable root; never truncate or silently rechunk authoritative source text.
6. Summarize bounded member lists in stable order through the existing summarizer, then embed the returned summary through `IWeaveService`; cluster those summary embeddings next. Do not use a centroid or reduced vector as a summary embedding. Singletons can remain carries without a paid restatement, explicitly recorded as an Arcanum adaptation. For layers of at most 11 nodes, stop with roots (reference stopping rule), except oversized-request subdivision is still required for work already planned. Do not force a single root merely because the whole layer happens to fit.
7. Require strict contraction of the deduplicated next working frontier before spending on its summaries. If an overlapping layer would not shrink, stop at the existing frontier with `NonContracting` and preserve all reachable sources. Maximum summary depth remains five by default. `SmallLayer`, `NonContracting`, `MaxDepth`, and `LeafOnly` are distinct terminal reasons; never disguise nonprogress as `MaxDepth`.

Safe adaptations are explicit: deterministic seeds/order; repaired empty membership; duplicate-safe source indexing; singular-fit handling; bounded recursive split; carries; noncontraction stopping; source admission ceiling; current source chunks and configured models instead of the paper's chunk/model choices. None substitutes a different clustering family.

## Actual UMAP, efficient enough to ship

Implement four independently testable operations: nearest-neighbor graph; smooth local distance calibration; fuzzy simplicial set; low-dimensional cross-entropy optimization. A random projection can initialize a neighbor search but is not the embedding algorithm.

Use normalized original vectors for cosine distances with stable double accumulation. For small sets (up to 2,048 rows) compute exact blockwise kNN with bounded heaps and no dense n-by-n matrix. For larger sets implement deterministic NN-descent with seeded random-projection-tree initialization, bounded neighbor/reverse-neighbor candidate lists, stable candidate deduplication, and fixed convergence/iteration rules. Store CSR arrays: O(nk) graph storage plus the original embedding buffer. Global k remains floor(sqrt(n−1)), clamped to valid 2..n−1; local k is min(10,n−1). A small-set scalar exact-kNN oracle is retained only for tests and numerical validation.

Build directed weights `exp(-max(0,d-rho)/sigma)` with sigma found by the UMAP smooth-kNN target; fuzzy union uses `a+b−ab`, not a binary adjacency matrix. Preserve duplicate samples as separate indices. Zero-distance duplicates participate in rho/sigma calculation; enforce documented finite sigma floors and handle disconnected components explicitly. Follow umap-learn 0.5.5's smooth-kNN and local-connectivity semantics and test them against exported arrays.

Optimize the fuzzy graph in Euclidean output space using attraction/negative-sampling repulsion, fitted distance curve for `min_dist=0.1`, `spread=1.0`, repulsion 1, negative-sample rate 5, initial learning rate 1, and the reference 500/200 epoch small/large schedule. Port the pinned numerical equations and epoch scheduling, with license attribution, rather than inventing an unverified simplification. Use deterministic seeded random initialization as the first production implementation: UMAP officially supports it; this is an explicit difference from the Python default spectral initialization, avoids an unrelated sparse eigensolver, and does not replace UMAP optimization. If spectral initialization later materially improves accepted quality, it requires a new algorithm version.

Use fixed order, single-threaded arithmetic and SplitMix64 streams derived from `(algorithm manifest, scope kind, exact scope id, layer, global/local/split stage, sorted input identity)`. Same persisted vectors, manifest and runtime numeric contract must yield identical graph/layout/membership/node identities. Cross-runtime/architecture bit equality and Python coordinate equality are not acceptance criteria. Cancellation checks must be inside neighbor candidate loops, graph calibration iterations, and optimizer edge/negative-sample loops.

The [UMAP API](https://umap-learn.readthedocs.io/en/latest/api.html) documents random and spectral initializations, cross-entropy-related parameters and epoch defaults; the production manifest must pin 0.5.5 equations rather than follow `latest` implicitly.

## Full-covariance GMM and BIC

Implement EM in double precision for d<=10, with Cholesky solves and log-determinants, log-sum-exp E steps, and stable-order weighted sufficient statistics. Never invert covariance matrices directly. Full covariance means all d(d+1)/2 covariance parameters per component, not diagonal or isotropic covariance.

For each `K` from 1 through `min(50,n)-1`, fit deterministically and score `BIC = -2 * total_log_likelihood + ((K-1) + K*d + K*d*(d+1)/2)*log(n)`. Default regularization 1e-6 on each covariance diagonal, average-log-likelihood convergence tolerance 1e-3, maximum 100 EM iterations, one initialized fit per candidate; these match established GaussianMixture defaults, verified against pinned fixture environment. Use deterministic Euclidean K-Means initialization in reduced space ONLY as an EM initializer; its labels never become Tapestry memberships. Reuse the best converged fit instead of a differently seeded refit, an explicit determinism/quality adaptation.

An empty/vanishing component or failed Cholesky invalidates that candidate; it does not manufacture probabilities. Nonconverged fits are diagnosed and excluded. If no candidate converges, return a typed fit failure; keep the old valid generation, back off paid work, and never switch to spherical clustering. Exact identical reduced rows are a recognized degenerate one-component model with regularized covariance and posterior one, preserving multiplicity. BIC ties favor smaller K, then canonical parameter order. Reject NaN, infinity, negative weights, unnormalized responsibilities, and overflow. Block E/M computations to avoid holding n*K*d tensors; O(n*d + K*d*d + batch*K) is sufficient, with final memberships streamed. Performance claims remain measurements, not assumptions.

The [GaussianMixture API](https://scikit-learn.org/stable/modules/generated/sklearn.mixture.GaussianMixture.html) specifies full covariance, regularization and EM controls. Fixture generation pins a specific sklearn version because upstream RAPTOR did not.

## DAG persistence and immutable publication

Keep `tapestry_generations`, nodes and BLOB embeddings. Add `tapestry_edges` with `(GenerationId,ParentNodeId,ChildNodeId)` primary key; indexed reverse lookup `(GenerationId,ChildNodeId,ParentNodeId)`; parent and child composite foreign keys to unique `(GenerationId,NodeId)` nodes; cascade deletion; posterior columns nullable for legacy/repair edges; membership-reason code. Enforce parent summary kind and strictly greater parent layer in SQL insert/update guards. This proves acyclicity, same-generation membership and scope isolation without trusting callers. Building-only node/edge writes and no content/edge mutations after publication are schema-enforced.

Retain legacy `ParentNodeId`/`ParentScopeKey` columns during compatibility, but new DAG nodes leave them null/root-placeholder and readers never use them as authoritative topology. `SetParentAsync` is replaced by `AppendEdgesAsync`; insertion of a summary, its embedding and all its edges is one checkpoint transaction. Root means no incoming parent edge, at any layer, including carried leaves. `DescendantLeafCount` is DISTINCT source-leaf reachability, not the sum of child counts. Use recursive UNION deduplication and indexed edge scans for requested roots/candidates; avoid an O(n²) persisted all-pairs closure. Source IDs and scope labels stay inside admitted storage and model-safe rendering boundaries.

New `tapestry_scope_revisions(ScopeKind,ScopeId,CorpusRevision,InvalidationRevision)` and generation `SourceRevision`/`ValidatedInvalidationRevision` fields distinguish build freshness from content safety. Every membership/content mutation increments CorpusRevision; edits, deletion, replacement or lost eligibility of an existing source also increment InvalidationRevision. Pure append of a genuinely new source increments only CorpusRevision: existing summaries are still true of their captured source set and must remain usable while the new scope is built. Invalidating on every new Entry would effectively starve Session Tapestry on active conversations. Writer-independent triggers cover old and new scopes, INSERT OR REPLACE (including detecting replacement), attachment version activation/deactivation, workspace reassignment, Entry SessionId changes and blank transitions. Avoid unrelated metadata bumps. Leaf-hash invalidation remains separate and correct.

Build captures fingerprint and both revisions, stages all leaves before paid summary effects, and checks invalidation revision before each provider effect and both revisions before publication. Publication compares corpus revision plus frozen build identity, validates source coverage, edge shape, embeddings and root reachability, then supersedes old/marks new Complete in one transaction. If sources moved, no publish. Retrieval requires Complete, supported algorithm, current invalidation revision, matching embedding identity and valid scope authority; hydration checks the same generation/revision snapshot. Source edits make prior summaries unavailable immediately, rather than merely dropping edited leaves. Erasure removes ALL affected generations and caches in the erasing transaction. Revocation/admission barriers must cover final provider send, not just a check before it.

For immutable data or append-only corpus growth under rebuild, an old valid generation stays visible until the new atomic switch. For changed or erased data, safety intentionally permits an empty Tapestry until rebuilt. The current unique Complete-scope index remains the publication invariant. Reconciliation continues dropping abandoned/superseded generations; no durable operation kind is added. This preserves the existing recovery contract and spend/backoff behavior; it does not pretend paid-prefix resume exists.

## Upgrade and legacy compatibility

Add one next Core schema transition, reserving its number only after integration with ongoing controller work. Author one schema object per file and transition resources under `Data/Schema/Transitions/V<next>/`; no EF migration or ad hoc runtime initializer. Freeze old catalog/source fingerprints before editing. Old frozen transitions and fixtures must not be rewritten to make the new head pass.

Upgrade backfills edges from each valid legacy ParentNodeId relation, preserving existing generation algorithm strings and node ids. A corrupt cross-generation/missing/cyclic legacy relation makes that derived generation unusable and eligible for cleanup; never “repair” it by attaching arbitrary parents. Add revision fields with legacy `ValidatedInvalidationRevision = NULL`. Before first legacy retrieval, compare its corpus fingerprint to the complete live eligible corpus under a revision-stable transaction; if equal set its validated invalidation revision, otherwise refuse it. The first new build always rebuilds legacy shape into `raptor-umap-gmm-v1`; legacy summaries may be reused only when exact canonical input/recipe/provider/model identity is demonstrably equal. A model or recipe identity not recorded by an old generation is not guessed. No synchronous model calls in schema upgrade.

The transition is atomic with schema metadata: inject failure/cancellation after each DDL/backfill stage and prove old or fully upgraded schema, never partially admitted tables. If a bounded managed backfill is required by size, use the repository schema coordinator with its existing resumable tier contract and publish head version only after validation. Older binaries encountering the new schema fail through existing newer-version refusal. Restore handles both pre-DAG and DAG archives and applies erasure before activation.

## Retrieval, overlap and authority

Introduce typed `ITapestryRetriever` rather than string-configuring arbitrary SQL identifiers for a graph join. Infrastructure scans admitted original-dimensional BLOB embeddings in bounded pages with a stable top-K heap; Core owns traversal/selection policy. Reuse shared cosine codec and ranking behavior, but do not send reduced UMAP coordinates to Divination. Existing `IDivinationService` remains unchanged for other sources.

Collapsed mode considers every eligible node of the captured generation across all layers. Traversal ranks all roots, selects K, expands the DISTINCT union of their children, reranks the union once, and records each node once even when several parents reach it. Mixed-layer roots/carries are valid. Visited sets plus decreasing layers guarantee termination. Rank-based backfill after stale/over-budget/overlap rejection must not turn the first K rejected candidates into an empty result while eligible lower candidates exist; use a deterministic rank cursor or increasing bounded candidate windows with an explicit cap and diagnostics, never arbitrary source truncation.

Retain ancestor/descendant suppression and ledger precedence, but compute ancestry through all DAG paths. For sibling overlap, count unique covered leaves and suppress a candidate only when its whole leaf set is already covered; partial overlap is allowed, because the prose cannot safely be subtracted. Never remove one sentence from a summary on the assumption that membership proves sentence attribution. Identical node ids and exact duplicate content remain deduplicated. This is a documented Arcanum retrieval adaptation; the numeric ranking stays cosine. Candidate budgets use the actual configured token estimator and rendered overhead, not `Content.Length/4`, and count each accepted node once.

Wizard must pass invocation authority into Tapestry retrieval. A request's SessionId/working directory alone is not delegated memory authority. Existing delegation grants contain Covenant/Saga/Lexicon snapshots; do not extend their closed source inventory silently. Delegated execution gets no ambient Tapestry lookup unless a separately authorized future capsule schema includes it. Test no capsule, stale/revoked capsule, cross-Campaign SessionId and workspace alias cases. Keep document attachment exclusion, latest retrieval scope only, session spelling rules, workspace path resolution, promotion prohibition, untrusted fences, provider admission, and source precedence.

## Evidence and release acceptance

A reproducible dev-only fixture generator pins Python, numpy 1.26.3, umap-learn 0.5.5, sklearn (proposed 1.4.2), scipy, numba and pynndescent, hashes lock/package artifacts, records RAPTOR commit and seed, and uses synthetic/no private corpora. Python is not a shipping or normal .NET-test dependency. Generate checked-in JSON numeric fixtures with source-generated test readers. Do not claim exact Python end-to-end membership where layouts/initialization differ.

Golden tests: cosine kNN identities with ties/duplicates; rho/sigma and directed/symmetric fuzzy weights (1e-6 absolute); fixed-initialization optimizer one-epoch coordinates/gradient (1e-6); Gaussian logpdf/Cholesky/logdet and responsibilities (1e-8 double); EM final likelihood/BIC against supplied initial parameters (1e-6 relative); normalized posteriors and known overlapping membership; permutation-invariant component matching. End-to-end tests use separable and overlapping synthetic manifolds, shuffled stable ids, identical/near-identical vectors, disconnected components, tiny sets 0..12, and adversarial near-threshold probabilities. Quality acceptance compares neighborhood recall/trustworthiness and retrieval source coverage, not coordinate plots. Proposed NN-descent acceptance: recall@k >=0.95 against exact oracle on fixed representative synthetic sets; below that is a failed implementation, not a license to lower the gate. Threshold is a design choice to validate before production enablement.

Graph tests: diamond overlap with exact union counts and ancestors; malformed edges rejected in SQL; all leaves reachable from some root; multiple duplicate clusters coalesce; source deletion invalidates both parents and shared ancestors; old/new readers race publication and erasure; cancellation at every numeric/provider/checkpoint stage; crash/restart reconciliation; disabled feature makes zero calls.

Retrieval fixture: two topics plus a shared bridge leaf and a cross-topic summary; fixed embeddings prove collapsed cross-layer ranking, traversal child-union ranking, no repeated diamond leaf, partial sibling overlap retention, full coverage suppression, actual token/byte bounds, raw/explicit precedence, and no scope/capsule leakage. Do not use a live model's subjective prose as a deterministic golden.

Qualify the final integrated exact SHA with focused and full required .NET suites, schema evolution/retention/restore/authority catalogs, AOT warning closure, shipping Native AOT smoke and native SQLCipher gate. Capture corpus size/dimension, graph edges, peak working set, BIC candidate counts, paid summary calls/reuse, cancellation latency and wall time on synthetic 1k/10k/50k corpora. Benchmark 50k global k≈223 honestly; do not promise linear worst-case runtime. Run requested local-model proof only through already configured models and normal admission, with no installation mutations; an unavailable fixture/provider is reported unverified, never green.

## Material decisions and implementation entry conditions

This design recommends deterministic random UMAP initialization, 0.1 posterior threshold, full covariance, 10 dimensions, reference exclusive K upper bound, same-runtime determinism, existing 50k explicit ceiling, legacy-reader compatibility, and whole-generation invalidation. No user-specific new model or config choice is required.

Two engineering gates remain measurable rather than speculative: pinned reference fixture environment must resolve and reproduce numeric arrays; sparse neighbor quality/performance must meet measured acceptance before enabling the new builder. Current sklearn docs are not a substitute for that pin. Integration must reserve the next Core schema number after concurrent remediation lands. The implementation must audit the exact delegated call path before deciding where invocation/capsule denial belongs; the plan names its behavioral contract rather than assuming a request parameter already grants authority. Any requirement to exceed 50k leaves is a separate out-of-core scaling decision, not silent truncation in this feature.
