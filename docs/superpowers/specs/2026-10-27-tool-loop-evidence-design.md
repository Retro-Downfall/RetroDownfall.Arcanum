# Tool-loop diagnostics and trimmed-evidence design

Approved direction: RV116/RV117/RV135 choiceC in /private/tmp/arcanum-tool-loop-diagnostics-trim-preflight.md; isolated branch from sealed7ffcd9b8. Actual shared buffered/streamed real-estimator RED was established before production edits (red-r4:4failures/7controls; expanded:8/7, all runtime bytes equal7ff).

The shared loop keeps its8 completed-round comparison window and ordered name/argument/result equality. A host-only weak association binds the actual assistant/tool messages produced by each current round to an evidence witness. It stores no payload, call-id identity, delegate, capability or wire metadata. Trimming reports only actual removed messages to that invocation; historical/unassociated removals cannot forgive current-turn fingerprints.

Each retained fingerprint has EvidenceEvicted and ReacquisitionUsed flags plus its payload-free witness. First observation is productive. A repeat whose prior evidence was never evicted stops as today. A repeat with demonstrably evicted evidence and no consumed allowance is accepted once; all retained equal fingerprints and the new observation inherit ReacquisitionUsed=true. Later eviction never clears that flag. Another equivalent repeat stops, whether or not the replacement evidence was trimmed again. Different calls/arguments/results remain productive. Overlapping equal fingerprints share the consumed flag; no separate unbounded history is added. Expiry remains exactly8 completed observations, including a permitted reacquisition. This detects the recurring loss/reread cycle without a new total model-call/round/retry ceiling.

The trim helper preserves system messages and complete assistant/tool groups. It provides actual removed-message identity to the loop; no comparison reset or whole-context fingerprint occurs. A single coalesced fixed notice explains that earlier tool evidence was removed and suggests a narrower reread only when necessary. No removed arguments/results appear in the notice. Notice placement must remain provider-protocol-safe, measured by the actual context estimator with all output/reasoning reserves. If irreducible context+notice cannot fit, existing ContextBudgetExceeded refuses before send. No free marker tokens, protocol orphan or unbounded notices.

Ordinary terminal errors/warnings identify bounded ordinal-distinct actual advertised tool names, call count and a fixed next step. Unknown model-selected names map to a fixed label; configured names are length/control/U+2028/U+2029 sanitized with honest omission counts. Keep existing optional safe correlation. Never add raw arguments/results, paths, prompts, arbitrary tool names or stable per-argument hashes. Protected/delegated turns retain no-name/no-signature logging, with fixed guidance only; turn-local HMAC equality stays intact.

Alternatives considered: notice-only leaves the legitimate reread stop; clearing/removing comparison history on every trim allows an infinite identical reread cycle. The approved bounded eviction/reacquisition state preserves both legitimate recovery and the structural stop.

No schema, database, public/wire, provider retry/fallback, paid accounting, authority, numerical harness, model/TSV or catalog change. Runtime owners are existing ToolLoopProgressDetector, TurnContextGuards and shared Wizard loop; use the existing append boundary only if needed for exact message association. DESIGN and CHAT-LOOP own final behavior documentation.

Implemented seam: capture the shared round's first appended-message index and associate its actual new assistant/result message objects after completion. The trim helper receives this data-only detector observer; no ToolExecutionPipeline change or arbitrary callback is added. A fixed host-owned TextContent is appended to the final User message, identified by reference rather than text; plain Assistant fallback is used only when no User exists. Slice estimation subtracts the already-counted fixed per-call overhead; the final full real estimate remains authoritative.
